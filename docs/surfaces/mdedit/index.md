# 마크다운 공동 편집기 (`mdedit`)

- **Status**: Implemented
- **kind**: `mdedit` — 번들 plugin `com.tasty.mdedit` (`bundle = false`: dev 번들 sync 로만 붙고 배포 패키지에는 없다)
- **렌더 경로**: webview
- **주체**: 로컬 사용자 (GUI surface) · AI Agent (`tasty mdedit` CLI / `mdedit.*` IPC)
- **기여**: surface_kind(webview) · 파일 핸들러(markdown detector 의 보조 handler) · cli · ipc · commands · settings_page — [plugins 개념](../../concepts/plugins.md)
- **설계**: 아래 [설계 결정](#설계-결정)
- **코드**: `crates/tasty-plugin-mdedit/`
- **화면**: [screens/mdedit.md](screens/mdedit.md)

## 목적·지원 범위

사용자 1 명과 에이전트(옆 터미널에서 같은 파일에 직접 쓰는 AI)가 **같은 로컬 `.md` 를 함께 고친다.**
보기 전용인 [markdown 뷰어](../markdown/index.md)는 그대로 두고, 편집이 필요한 문서만 이 편집기로 연다.
실시간 동시 편집(CRDT)이 아니라 **기준점(base) + 3-way 병합 + 스냅샷** 모델이다 — 사람 1 명 · 에이전트
1 개 · 로컬 파일 1 개 규모에서 원문을 바이트 그대로 지키는 쪽을 골랐다.

지원하지 않는 것(비-목표):

- 실시간 CRDT · 여러 사람 동시 편집 · 원격 mirror 편집 · 렌더 결과를 markdown 으로 되돌리는 WYSIWYG 편집(미리보기 편집은 블록의 원문 조각을 고친다).
- markdown 뷰어(`com.tasty.markdown`)의 동작 변경 — 그 plugin 은 보기 전용 그대로다.
- 파일 도구로 직접 쓰는 에이전트를 막는 것 — 사후 검토·스냅샷·경고로 다룬다([방어선은 쓰기 이후에 둔다](#방어선은-쓰기-이후에-둔다)).

## 상태 소유자

- **구조 트리 leaf**: host 의 `SurfaceDescriptor`(kind `mdedit`). 공통 규칙은 [작업 영역](../../features/work-area/index.md#surface-종류).
- **실행 자원**: plugin 프로세스가 surface 마다 `Session` 을 든다(`crates/tasty-plugin-mdedit/src/session.rs`). 세션은 아래 세 텍스트와 모드(미리보기/원문)·검토 목록·conflict 상태를 가진다. 파일 감시는 plugin 의 `mdedit-watch` 스레드가 SDK `file_watch` 로 한다. 스냅샷은 plugin data 디렉터리의 파일이다.
- **View 상태**: 원문 편집기의 커서·선택·스크롤, 미리보기 스크롤, 접은 자리, 쓰던 초안은 웹뷰 안 스크립트가 든다(탭의 `sessionStorage`). plugin 에는 보내지 않는다.

### 문서 상태

surface 마다 세 텍스트를 든다.

- **base** — 마지막으로 맞춘 디스크 내용.
- **편집 버퍼** — 사용자가 고치는 중인 내용. base 와 같고 미리보기에 적용 전 고침이 없으면 깨끗하다(저장할 것이 없다). 미리보기에서 열린 블록의 고침은 적용할 때 버퍼로 들어가므로, 그 전에는 웹뷰가 알린 "적용 전 고침" 표시가 dirty 를 켠다 — 저장 단추 · 상태줄 · `mdedit status` 가 같은 값을 본다([적용 전 고침도 dirty 로 센다](#적용-전-고침도-dirty-로-센다)). 병합·저장 판단은 버퍼만 본다.
- **검토 기준/대상** — 외부 쓰기 직전 내용과 그 이후 내용. 둘의 줄 diff 가 검토 목록이다.

원문은 줄바꿈(LF/CRLF)과 BOM 을 떼어 다루고 저장 때 되붙인다. CRLF 와 LF 가 섞인 파일은 LF 로 통일된다(열 때 배너로 알린다).

## 생성·갱신·종료

- **생성**: `mdedit` surface 생성에 `file` 이 필수다(없으면 경고만 남기고 빈 surface). `mode = "source"` 면 원문 모드로 연다. 사용자는 마크다운 파일의 "다른 앱으로 열기" 목록의 **마크다운 편집기**로 연다 — 매니페스트의 `[[contributes.handler]]` 가 markdown detector 에 우선순위 40 으로 붙어, 기본 열기(뷰어, 50)는 그대로다. 경로는 `canonicalize` 해 같은 파일을 여는 편집기와 IPC 대상을 맞춘다.
- **갱신**: 파일 감시가 변경을 보면 자기 `mdedit.reload` 를 self_invoke 하고, 읽기·병합은 그 메서드 하나로 모인다(아래 [외부 쓰기 감지 · 병합](#외부-쓰기-감지--병합)). `theme.changed` 를 구독해 테마가 바뀌면 열린 문서를 다시 싣는다(webview kind 는 Theme 을 자동으로 받지 않는다).
- **종료**: surface 를 닫으면 세션을 버리고 파일 감시에서 뺀다. 저장하지 않은 버퍼는 남지 않는다.
- **plugin 정지**: `mdedit.lifecycle_busy` 는 저장하지 않은 편집(dirty)이 있는 세션이 하나라도 있으면 `busy: true` 와 파일 이름을 답한다. host 는 `plugin.disable`·`plugin.remove`·`plugin.upgrade_builtins`(`restart_running`) 전에 이 관례 메서드를 묻는다 — 규약은 [plugin 개발 › CLI + IPC namespace](../../dev-guide/plugin-development.md#cli--ipc-namespace).

### 저장

1. 마지막으로 맞춘 뒤 디스크가 바뀌었으면 **쓰지 않는다** — 그 변경을 먼저 병합하고 멈춘다.
2. 섹션 가드와 비밀값 검사를 지난다(아래).
3. 직전 디스크 내용을 스냅샷으로 남긴다.
4. 같은 폴더의 임시 파일에 쓰고 rename 한다(도중에 죽어도 반쯤 쓰인 파일이 없다). 원래 파일 권한을 유지한다.

편집기가 바꾸는 것은 사용자가 고친 바이트뿐이다 — 한 줄을 고쳐 저장하면 `diff` 는 그 줄만 보인다.

### 외부 쓰기 감지 · 병합

SDK `file_watch`(내용 지문, 공용 주기)가 열린 파일을 본다. 디스크가 base 와 다르면:

- 직전 내용을 스냅샷으로 남기고 검토 목록에 올린다.
- 편집 버퍼가 깨끗하면 새 내용으로 바꾼다.
- 더러우면 줄 단위 3-way 병합(base / 버퍼 / 디스크)을 한다. 서로 다른 줄을 고쳤으면 둘 다 남고("병합했다" 배너, 저장은 사용자가 한다), 같은 base 범위를 다르게 고쳤으면 **conflict** 로 멈춘다. conflict 동안 원문 편집기는 읽기 전용이고 저장은 거부된다. 조용히 한쪽을 고르지 않는다.
- 같은 자리에 양쪽이 끼워 넣은 것도 conflict 다. 한쪽이 변경 범위의 바로 앞·뒤에 붙인 것은 conflict 가 아니다.

에이전트가 `mdedit` 연산으로 쓴 경우 plugin 이 바로 반영한다(감시 주기를 기다리지 않는다). 이때 원문 편집기의 커서·선택·스크롤은 유지되고 포커스는 옮겨지지 않는다.

### 검토 (외부 변경 hunk 별 유지·되돌리기)

검토 목록의 hunk 마다 출처를 표시한다.

- **에이전트** — `mdedit` 쓰기 연산이 넣거나 뺀 줄이거나, 추가된 줄이 `> [!agent]` 블록이다.
- **외부** — 그 밖(파일 도구·다른 편집기).

**유지**는 그 hunk 를 검토 기준에 적용하고, **되돌리기**는 그 hunk 를 원래대로 돌린 내용을 버퍼에 3-way 로 얹어 바로 저장한다(저장하지 않은 편집과 겹치면 거부). 사용자가 저장하면 저장한 편집이 검토 기준에도 옮겨져, 목록에는 외부 변경만 남는다.

### 섹션 가드 · 비밀값 검사

문서 `<dir>/<name>` 옆의 사이드카 `<dir>/.<name>.tasty.toml` 이 설정이다([섹션 가드는 사이드카 파일에 둔다](#섹션-가드는-사이드카-파일에-둔다)).

```toml
[[guard]]
heading = '^# 참조$'          # 헤딩 줄 전체(`#` 포함)에 거는 정규식
allow = ["checkbox"]           # 체크박스 토글만 허용. 생략하면 전부 읽기 전용
allow_suffixes = [" → todo"]   # 줄 끝에 이 꼬리를 붙이는 변경만 허용

[[guard]]                      # 날짜 섹션: 오늘·어제는 자유, 그 이전은 체크박스·꼬리만
heading = '^# \d{4}\.\d{2}\.\d{2}'
date_format = '%Y.%m.%d'       # 헤딩 제목 앞머리에서 날짜를 읽는 형식(strftime)
older_than_days = 1            # 기준일(오늘 - 이 일수)보다 앞선 날짜만 가드
allow = ["checkbox"]
allow_suffixes = [" → todo"]

[secrets]
mode = "block"                 # block(기본) | warn | off
allow = ['\[pw:[A-Z]\d+\]']    # 이 패턴에 걸리는 부분은 검사에서 뺀다
extra = []                     # 더할 정규식
```

- **날짜 조건**(`date_format` + `older_than_days`): 헤딩 정규식이 맞고, 제목 앞머리에서 읽은 날짜가 **로컬 날짜 기준** 오늘에서 `older_than_days` 일을 뺀 날보다 앞설 때만 가드한다. `1` 이면 오늘·어제는 자유롭게 고치고 그제부터 가드된다. 날짜를 못 읽는 헤딩은 가드 대상이 아니다. 둘 중 하나만 적은 규칙(또는 음수 일수)은 통째로 빠지고 사이드카 경고로 보인다. 규칙은 위에서부터 처음 맞는 것 하나만 쓴다.
- 가드 섹션은 그 헤딩부터 같거나 높은 레벨의 다음 헤딩 전까지다. 그 안의 변경(헤딩 삭제·이름 변경 포함)은 사람의 저장과 에이전트 쓰기 모두 거부된다. 검토 되돌리기·스냅샷 복원처럼 **이전 내용으로 되돌리는** 저장은 허용된다.
- 비밀값 검사는 **새로 생기거나 바뀐 줄만** 본다. `[pw:P1]` 같은 라벨은 먼저 지운 뒤 검사한다. 내장 패턴: `password:`·`token=` 같은 대입(한·일·중 낱말 포함), `root/…` 같은 계정/비밀번호(값에 숫자와 문자가 섞일 때), AWS·GitHub·GitLab·Slack·`sk-` 키, 개인키 머리말, JWT. 보고에는 값을 싣지 않는다(줄 번호와 종류만).
- 사이드카가 없거나 깨졌으면 가드는 없고 비밀값 검사는 기본값(`block`)이다. 깨진 사이드카는 저장을 막지 않는다 — `mdedit status` 의 `sidecar_warnings` 로 보인다.
- 에이전트가 파일 도구로 직접 쓴 변경은 막을 수 없다 — 감지 뒤 경고 배너를 띄우고 검토 목록에서 되돌리게 한다.

### 스냅샷

외부 쓰기 감지 직전 · 에이전트 연산 직전 · 저장 직전 · 복원 직전에 원문 바이트를 `<plugin data dir>/snapshots/<경로 지문>/<unix ms>-<사유>.md` 로 남긴다. 직전 스냅샷과 내용이 같으면 새로 만들지 않는다. 보존은 파일당 개수·기간(설정 창, 기본 50 개 · 7 일) 중 하나라도 넘는 오래된 것부터 지우되 가장 최근 하나는 남긴다.

### 미리보기

본문은 markdown 뷰어의 렌더러 소스를 이 크레이트에서 함께 컴파일해 만든다(사본 없음, [렌더러 제자리 컴파일](#렌더러-제자리-컴파일)) — 뷰어와 같은 모양(TOC · 콜아웃 · 코드 하이라이트 · 찾기)이다. 렌더러의 문구는 markdown plugin 설치본의 번역을 읽는다. 편집기 스크립트가 돌아야 하므로 매니페스트의 `[surface_kinds.webview_defaults] sandbox_scripts = false` 로 JS 를 기본으로 켠다([WebView 설정 출처](../../design/systems/webview.md#설정-출처--kind-를-등록한-plugin)). 사용자가 저장한 `sandbox_scripts` 가 있으면 그 값이 우선한다.

- `> [!agent] HH:MM 제목` 블록은 에이전트 배지로 그린다. 원문은 그대로라 markdown 뷰어에서는 일반 인용으로 보인다.
- 체크박스를 누르면 그 줄의 `[ ]`↔`[x]` 한 바이트만 **버퍼에서** 바꾼다 — 다른 미리보기 편집과 같이 파일에는 저장할 때 쓴다([미리보기 조작은 저장할 때만 파일에 쓴다](#미리보기-조작은-저장할-때만-파일에-쓴다)). 에이전트의 `mdedit task` 는 바로 쓴다. 미리보기의 체크박스 수가 원문에서 센 수와 다르면 어느 줄인지 확정할 수 없어 거부한다.
- **접기**: 본문 바로 아래 제목은 다음 같은·상위 수준 제목 전까지를, 하위 목록을 가진 항목은 그 하위 목록을 접는다. 왼쪽 여백의 화살표(펼친 것은 가리킬 때만, 접힌 것은 늘 보인다)로 접고 편다. 보기 상태일 뿐이다 — 원문·버퍼에 닿지 않고 plugin 에 아무것도 보내지 않는다. 접은 자리는 그 탭의 `sessionStorage` 에 남아 편집 적용·외부 쓰기로 다시 그려도 유지되고, 탭을 닫으면 사라진다. 접혀 가려진 블록을 편집기로 열거나 목차·문서 안 링크로 찾아가면 그 접기를 푼다([접기는 보기 상태](#접기는-보기-상태)).

#### 미리보기에서 바로 고치기

미리보기의 블록을 누르면 **렌더된 그 블록이 그대로 입력 가능해지고** 커서가 누른 자리에 놓인다(`contenteditable="plaintext-only"`). 따로 뜨는 입력칸은 없다. 적용하면 그 블록의 원문 범위만 바뀐다([미리보기 편집 단위는 블록 원문 조각](#미리보기-편집-단위는-블록-원문-조각) · [정렬되는 블록은 렌더된 자리에서 고친다](#정렬되는-블록은-렌더된-자리에서-고친다)).

- **무손실의 근거 — 정렬**: 블록을 열 때 DOM 을 서식 표기와 함께 직렬화한 글을 원문 조각과 글자 단위로 맞춘다. 굵게 `**` · 기울임 `*` · 취소선 `~~` · 코드(백틱) · 링크 `[글](주소)` 로 직렬화하고, 연 순간 맨 주소였던 링크는 맨 주소로 고정한다. 같은 글자이거나 렌더러의 스마트 구두점(`“”‘’` · `…` · `—` · `–`) 치환만 허용한다. 적용할 때는 편집 전후 글의 바뀐 구간만 정렬표로 원문 위치에 옮겨 바꾼다 — 서식 표기 · 스마트 따옴표 · 링크 표기 등 손대지 않은 원문 바이트는 그대로다.
- **맞추지 못한 블록**(이스케이프 `\_` · 엔티티 `&amp;` · `_강조_` · 이미지 · 수식 등)은 그 자리에 **원문 조각 입력칸**이 열린다. 표기를 그대로 보이고 그 값으로 범위를 바꾼다.
- 그 자리 편집은 글만 받는다 — 붙여넣기는 글만 들어가고, 서식 단축키는 없다. 표기를 직접 치면(`**글**`) 다시 그릴 때 서식이 된다.
- 편집 중인 블록은 `white-space: pre-wrap` 이다 — WebKit(macOS 앱의 웹뷰)은 `normal` 에서 편집하면 옆의 줄바꿈 문자를 공백으로 바꾸고, 낱말을 지우면 보이는 공백을 지키려고 NBSP 를 넣는다(실측, 원문 손상). 그래서 여러 줄 문단의 줄바꿈은 편집하는 동안 줄로 보인다. 직렬화는 NBSP 를 공백으로 되돌린다 — pre-wrap 이 깨졌을 때를 위한 보조 장치이고, 원문에 진짜 NBSP 가 든 블록은 정렬이 안 맞아 원문 조각 입력칸으로 열린다.

| 블록 | 열리는 범위 | Enter | 그 밖 |
|---|---|---|---|
| 최상위 문단 | 문단 전체(여러 줄) | 커서 자리에서 나눠 뒤쪽을 새 문단으로(끝이면 새 줄 입력칸, 머리면 적용 + 새 줄 입력칸) | 줄 머리 `/` 메뉴(그 자리 편집에서는 블록 아래에 뜨고 고르면 곧바로 적용) · `Shift+Enter` 줄바꿈 |
| ATX 제목 | `#` 뒤 글 | 커서 자리에서 나눠 뒤쪽을 새 문단으로(끝이면 새 줄 입력칸) | — |
| 목록 항목 | 표지(·체크박스) 뒤 첫 줄 | 커서 자리에서 나눠 뒤쪽을 같은 수준의 새 항목으로(하위 목록 뒤, 번호 +1, 체크 항목이면 `[ ]`) | 빈 항목에서 Enter 는 목록을 빠져나간다 — 하위 항목은 한 단계 내어쓰고, 최상위 항목은 그 줄을 지우고 앞 항목 아래에 새 줄 입력칸(쓴 문단이 목록을 나눈다) |
| 최상위 표의 셀 | 셀 글(글 안의 세로선 문자는 저장할 때 앞에 역슬래시를 붙인다) | 적용 | 셀 아래에 뜨는 `위에 행 추가` · `아래에 행 추가`(머리 행은 아래만 · 고친 글이 있으면 먼저 적용) |

- **열리지 않는 것**: 인용(`> [!agent]` 포함) · 각주 · 정의 목록 · 코드 블록 · 목록 안의 제목·표 · setext 제목 · 여러 줄 항목, 그리고 렌더 결과의 글자가 원문에서 기대한 글자와 다른 블록(위키링크·각주 번호·수식 등). 이런 블록은 원문 모드에서 고친다.
- **짝짓기**: plugin 이 원문을 렌더러와 같은 파서 옵션으로 다시 파싱해 편집 단위마다 원문 범위와 렌더될 글자를 넘기고, 스크립트가 같은 맥락의 요소를 순서대로 짝지어 글자가 같을 때만 연다. 파서 옵션은 시험 `parser_options_match_the_renderer` 가 렌더러 소스와 대조한다.
- **Enter 로 나누기**([Enter 는 커서 자리에서 나눈다](#enter-는-커서-자리에서-나눈다)): 커서 자리에 표지 글자를 잠깐 끼워 블록을 원문으로 직렬화한다 — 정렬 접합을 그대로 타므로 앞쪽+뒤쪽 = 원문이다. 커서가 서식(굵게·기울임·취소선·코드·링크) 안이면 그 서식이 끝나는 자리에서 나눈다. plugin 이 블록을 앞쪽으로 바꾸고 뒤쪽을 새 항목·새 문단으로 넣어(`split`, 한 단계라도 거부되면 버퍼 그대로) 다시 그린 문서에서 새 블록을 커서 머리로 연다. 바뀌는 것은 버퍼뿐이다. 표지 글자가 원문에 이미 있으면 적용 + 다음 자리 열기로 간다. `Shift+Enter` 는 문단 안 줄바꿈만 넣는다(항목·제목의 둘째 줄은 원문 표기가 렌더 글자와 갈린다). 첫 줄에서 위 · 마지막 줄에서 아래 방향키는 이웃 편집 단위(표 칸·접혀 숨은 것 제외)를 같은 가로 위치로 연다 — 고친 것이 있으면 적용하고 다시 그린 뒤 연다.
- **새 줄 입력칸**: 문단·제목 끝에서 Enter 또는 본문 끝의 `줄 추가` 로 연다. 내용이 있을 때만 빈 줄로 띄운 새 블록으로 들어간다(다음 줄이 붙어 있으면 뒤에도 빈 줄). 줄 머리 `/` 는 블록 삽입 메뉴(본문 · 제목 1–3 · 글머리 · 번호 · 체크박스 · 인용 · 코드 블록 · 표 · 구분선)를 띄우고 입력으로 거른다. 코드 블록·표 틀을 넣으면 Enter 가 줄바꿈이 되고 `Cmd/Ctrl+Enter` 로 적용한다. 기존 문단 입력칸의 `/` 메뉴는 머리 표지(제목·목록·체크박스·인용)만 보인다.
- **적용 규칙**: plugin 은 그 블록의 현재 원문이 화면을 그릴 때의 조각과 같을 때만 바꾸고, 다르면 거부 배너와 함께 다시 그린다. 미리보기 편집은 **버퍼만** 바꾼다(원문 편집기와 같다) — 저장은 `저장`·저장 단축키이고, 그 사이의 외부·에이전트 쓰기는 위 병합 경로를 탄다. 저장 단축키와 툴바 동작은 열린 입력칸을 먼저 적용한다. `Esc` 는 취소, 다른 곳을 누르면 적용이다. 한글 조합 중의 Enter 는 적용으로 치지 않는다.
- conflict · 읽기 실패 · 원문 모드에서는 편집 단위를 싣지 않는다(입력칸·`줄 추가` 없음).
- 다시 그린 뒤 이어서 열 자리(새 항목·새 행·새 줄)는 plugin 이 바이트로 넘기고 스크립트가 그 줄의 첫 편집 단위를 연다. 외부 쓰기로 다시 그려지면 쓰던 글은 같은 블록(원문 조각이 그대로일 때)에 되살린다.

#### 블록 손잡이

블록에 마우스를 올리면 왼쪽 여백(접기 화살표 바깥)에 `+`(삽입)와 `⠿`(끌어 옮기기 · 클릭하면 블록 메뉴)가 뜬다([블록 손잡이는 원문 줄을 통째로 옮긴다](#블록-손잡이는-원문-줄을-통째로-옮긴다)).

- **단위**: 최상위 블록과 목록 항목(하위 목록째). 인용 · 표 · 각주 안의 블록은 단위가 아니다. plugin 이 원문을 다시 파싱해 단위마다 종류 · 그릇(최상위 / 목록 번호) · 원문 해시를 넘기고(`core::units`), 스크립트가 문단 · 제목 · 항목은 편집 단위의 요소로, 목록은 첫 항목의 부모로, 그 밖의 최상위 블록은 태그 순서로 짝짓는다. 짝이 없는 단위에는 손잡이가 없다.
- **`+`**: 항목이면 같은 수준의 빈 새 항목, 그 밖이면 그 블록 뒤 새 줄 입력칸을 `/` 메뉴와 함께 연다.
- **`⠿` 끌기**: 같은 그릇의 보이는 이웃 사이에 끼울 자리를 강조색 선으로 보이고, 놓으면 그 앞(또는 그릇 끝)으로 옮긴다. 제목은 제목 줄만 옮긴다.
- **`⠿` 클릭**: 그 블록을 옅은 배경으로 고르고 블록 메뉴를 연다 — 형식 변경(문단 · 제목: 본문 · 제목 1~3 · 글머리 · 번호 · 체크박스 · 인용, 항목: 글머리 · 번호 · 체크박스, 현재 형식은 끔 · 여러 줄 문단은 제목 끔) · 위로 이동(맨 위면 끔) · 아래로 이동(맨 아래면 끔) · 복제 · 삭제. `Esc` 나 바깥 클릭으로 닫는다.
- **원문 규칙**: 단위의 원문 줄을 통째로 잘라 붙이고 앞뒤 구분(빈 줄 · 줄바꿈)만 함께 다룬다. 이웃 줄의 글자 · 들여쓰기 · 줄 끝 공백과 이벤트가 없는 줄(링크 정의 · 머리말)은 그대로다. 번호 목록의 번호는 다시 매기지 않는다. 단위 원문의 해시가 화면을 그릴 때와 다르면 거부하고 다시 그린다. 버퍼만 바뀐다(저장할 때 쓴다). `> [!agent]` · 코드 블록도 통째로 옮기고 지울 수 있다 — 그 안의 글은 그 자리 편집으로 열리지 않는다.
- 편집 중에 고친 것이 있으면 손잡이는 먼저 그 블록을 적용하고 멈춘다(다시 그린 뒤 다시 누른다).
- **현재 블록**: 편집 중인 블록과 고른 블록은 옅은 배경이고, 도구 막대 상태 옆에 그 형식 이름이 붙는다.

### 웹뷰 ↔ plugin

편집기 스크립트는 `location.hash` 에 `tasty-nav:mdedit:<seq>:<op>:<JSON>` 을 넣어 plugin 에 말한다(host 가 navigation 시도로 넘긴다, [웹뷰 입력은 nav fragment 로 보낸다](#웹뷰-입력은-nav-fragment-로-보낸다)). 원문 편집은 300 ms 쉬면 마지막 동기 이후의 **차이(splice)만** 보낸다. 인코딩 뒤 16 KiB 를 넘으면 조각으로 나누고, 조각마다 plugin 의 응답을 기다린다. 번호가 어긋나거나 적용 결과 길이가 다르면 plugin 이 전체 재전송을 요청한다.

## 저장·복원

- **저장하는 값**: 레이아웃 스냅샷에 정규화한 파일 경로(`{"file": …}`)만 넣는다.
- **저장하지 않는 값**: 모드(미리보기/원문), 편집 버퍼, 검토 목록, conflict 상태, 접은 자리, 스크롤. 저장하지 않은 편집은 복원되지 않는다 — 파일에 남은 것만 다시 연다. 스냅샷 파일은 레이아웃과 별개로 plugin data 디렉터리에 남는다.
- **복원 순서**: host 가 `restore_surface` 로 `file` 을 넘기면 생성과 같은 경로로 세션을 열고(모드는 미리보기), 파일 감시에 다시 등록한 뒤 문서를 싣는다.
- **실패 시**: `file` 이 없으면 빈 surface 로 남는다. 파일을 읽지 못하면 상태가 `파일을 읽지 못했습니다` 이고 본문 자리에 실패 문구가 뜬다([화면 › 상태별 시각](screens/mdedit.md#상태별-시각)).

## IPC·CLI

대상은 항상 `--file`(CLI 가 호출자 cwd 기준 절대경로로 바꾼다)이다. 편집기가 열려 있지 않아도 되고, 포커스나 활성 surface 를 보지 않는다([IPC namespace 는 mdedit](#ipc-namespace-는-mdedit)).

| CLI | IPC | 하는 일 |
|---|---|---|
| `tasty mdedit read --file F [--outline]` | `mdedit.read` | 본문(또는 헤딩 목차) + `hash` |
| `tasty mdedit section <get\|append\|prepend\|insert-before\|replace> --file F --heading H [--text T] [--if-match X]` | `mdedit.section` | 헤딩 경로로 고른 섹션 하나 |
| `tasty mdedit task toggle --file F --heading H --match M [--to checked\|unchecked]` | `mdedit.task` | 섹션 안 체크박스 한 줄 |
| `tasty mdedit agent-note --file F --heading H --title T [--text B] [--time HH:MM \| --no-time]` | `mdedit.agent_note` | 섹션 끝에 `> [!agent]` 블록(시각 기본 = 지금) |
| `tasty mdedit snapshot <list\|restore> --file F [--id I]` | `mdedit.snapshot` | 스냅샷 목록·복원 |
| `tasty mdedit status --file F` | `mdedit.status` | `hash` · 열린 편집기의 수정·conflict·검토 수 · 가드 수 · 사이드카 경고 |

- **헤딩 경로**: `# 2026.10.22` 처럼 레벨까지 적으면 레벨도 맞아야 하고, `#` 없이 적으면 제목만 견준다. ` > ` 로 조상을 잇는다(`# 할 일 > ## Project A`). 맞는 헤딩이 0 개거나 2 개 이상이면 오류(줄 번호를 추측하지 않는다). 펜스 코드 안의 `#` 줄은 헤딩이 아니다.
- **연산 위치**: append 는 섹션의 마지막 내용 줄 뒤(섹션 끝 빈 줄 유지), prepend 는 헤딩 줄 바로 뒤, insert-before 는 헤딩 줄 앞(뒤에 빈 줄 하나 보장), replace 는 헤딩 줄을 뺀 본문(끝 빈 줄 유지). agent-note 는 직전 줄이 인용이면 빈 줄을 끼워 별개 블록으로 만든다.
- **`--if-match`**: `read`·`status`·쓰기 응답의 `hash` 를 넘기면 그 사이 파일이 바뀐 경우 쓰지 않는다.
- 오류 코드: `-32040` 오래된 hash · `-32041` 가드 섹션 · `-32042` 비밀값 차단 · `-32043` 헤딩/체크박스 지정 실패.
- `mdedit.reload` — 파일 감시가 self_invoke 하는 내부 메서드다. 디스크를 다시 읽고 위 병합 경로를 탄다.
- `mdedit.lifecycle_busy` — 저장 안 한 편집이 있으면 `busy: true`. host 가 plugin 을 내리기 전에 묻는다([생성·갱신·종료](#생성갱신종료)).
- **사용자 명령**: 저장 단축키는 설정 › 단축키의 **마크다운 편집기 저장**(기본 `ctrl+s`, 편집기 surface 에 포커스가 있을 때만, 매니페스트 `[[contributes.commands]]` `save`).
- **설정**: 설정 › 일반 › 마크다운 편집기 — 파일당 스냅샷 수(1–1000) · 보관 기간(1–365 일).

## headless·원격 제약

- **헤드리스**: plugin kind 는 헤드리스에서도 GUI 와 같이 등록된다([작업 영역](../../features/work-area/index.md#surface-종류)). 에이전트 연산(`mdedit.*`)은 편집기 surface 없이 파일 경로만으로 동작하므로 헤드리스에서도 쓸 수 있다.
- **원격**: 원격 mirror 편집은 비-목표다. plugin 은 로컬 파일 경로만 열고 mirror 용 경로를 구현하지 않는다.

## 검증 기준

- Given 1,764 줄 문서를 편집기로 열었다 When 한 줄을 고쳐 저장한다 Then 저장 전후 `diff` 는 그 줄뿐이고 파일 권한은 그대로다.
- Given 버퍼가 깨끗하다 When 에이전트가 파일을 고친다 Then 편집기가 새 내용을 싣고 검토 목록에 그 hunk 가 출처와 함께 오른다.
- Given 사용자가 날짜 섹션을, 에이전트가 할 일 섹션을 고쳤다 When 디스크 변경이 감지된다 Then 둘 다 버퍼에 남고 conflict 가 없다.
- Given 같은 줄을 양쪽이 다르게 고쳤다 When 디스크 변경이 감지된다 Then conflict 패널이 뜨고 저장이 거부되며, 곳마다 내 것/디스크 것/둘 다를 고르고 적용하면 그 결과가 버퍼가 된다.
- Given 에이전트 쓰기 직후 When 스냅샷 목록의 가장 최근 항목을 복원한다 Then 파일이 쓰기 직전 내용으로 돌아간다.
- Given 미리보기 When 체크박스를 누르고 저장한다 Then 그 줄의 체크 문자 한 바이트만 바뀌어 저장된다. 저장 전에는 파일이 그대로다.
- Given 미리보기 When 목록 항목의 글 가운데를 눌러 그 자리에서 Enter 를 누르고 이어 친 뒤 저장한다 Then 커서 앞 글은 그 항목에 남고 커서 뒤 글은 바로 아래 같은 들여쓰기·표지의 새 항목으로 가며 그 새 항목이 커서 머리로 열려 이어 친 글이 거기 들어간다. Enter 는 파일에 쓰지 않고, 저장 전후 `diff` 는 그 항목 줄과 새 항목 줄뿐이다.
- Given 미리보기 When `줄 추가` 에서 `/h2` 를 쳐 제목 2 를 고르고 글을 적어 Enter 를 누른다 Then 빈 줄로 띄운 `## 글` 블록이 문서 끝에 들어간다.
- Given 미리보기 When 표 셀의 `아래에 행 추가` 를 누른다 Then 그 행 아래에 열 수만큼 빈 셀을 가진 행 하나가 생긴다. 머리 행에는 `위에 행 추가` 가 없다.
- Given `> [!agent]` 인용 · 코드 블록 · 위키링크가 든 항목 When 미리보기에서 누른다 Then 입력칸이 열리지 않는다.
- Given 미리보기에서 한 줄을 고쳐 두었다(저장 전) When 에이전트가 다른 줄을 고친다 Then 두 변경이 병합되고 저장하면 두 줄만 바뀐다. 같은 줄이면 conflict 로 멈추고 그동안 미리보기 편집은 열리지 않는다.
- Given 섹션이 둘 이상 같은 제목이다 When `tasty mdedit section append --heading` 을 그 제목으로 부른다 Then `-32043` 과 함께 그 헤딩들의 줄 번호가 나오고 파일은 그대로다.
- Given `--if-match` 에 이전 hash 를 넘겼다 When 그 사이 파일이 바뀌었다 Then `-32040` 으로 거부되고 파일은 그대로다.
- Given 사이드카가 `# 참조` 를 가드한다 When 사용자 저장이나 에이전트 쓰기가 그 섹션의 체크박스가 아닌 줄을 바꾼다 Then 거부된다.
- Given 사이드카 날짜 가드(`older_than_days = 1`)가 있고 오늘이 D 다 When D·D-1 섹션을 고친다 Then 저장된다. When D-2 섹션의 체크박스가 아닌 줄을 고친다 Then 사람 저장과 에이전트 쓰기 모두 거부된다. 날짜를 못 읽는 헤딩은 영향이 없다.
- Given `root/Passw0rd!` 를 새 줄에 적었다 When 저장한다 Then 차단 배너가 뜨고 파일은 그대로다. `[pw:P1]` 라벨은 통과한다.
- Given `tasty mdedit agent-note --heading "# 2026.10.22" --title T` When 실행한다 Then 그 섹션 끝에 `> [!agent] HH:MM T` 블록이 붙고 편집기 미리보기에서 에이전트 배지로 보인다.
- Given 저장하지 않은 편집이 있는 편집기 When `tasty plugin disable com.tasty.mdedit` 를 부른다 Then host 가 `mdedit.lifecycle_busy` 의 `busy: true` 를 받아 `-32023` 으로 거절하고 plugin 은 그대로 떠 있다.

## 설계 결정

일반 구현의 선택과 이유다. 코드 주석은 이 절의 제목을 앵커로 인용한다.

### 웹뷰 입력은 nav fragment 로 보낸다

웹뷰→plugin 입력은 새 메시지 채널 없이 기존 navigation 채널을 쓴다. 형식은 `#tasty-nav:mdedit:<seq>:<op>:<payload>`(`seq` 는 문서마다 단조 증가, `payload` 는 `encodeURIComponent` 한 JSON)다.

- 본문은 통째로 보내지 않고 편집 차이 `{start, end, text}`(UTF-16 단위)만 보낸다. 바이트 오프셋 변환은 `bridge.rs` 한 곳이다.
- 메시지는 한 번에 하나씩 보낸다. 스크립트는 plugin 이 `webview.post_message` 로 그 번호의 ack 를 돌려줄 때까지 다음 메시지를 큐에 둔다(1.5 초 안에 안 오면 넘어가고, 그 틈은 plugin 이 번호로 알아챈다). 한 태스크 안의 연속 fragment 대입이 엔진마다 몇 번의 navigation 으로 잡히는지에 기대지 않기 위해서다.
- 인코딩 뒤 16 KiB 를 넘으면 `chunk` 연산으로 나눈다. 16 KiB 는 측정값이 아니라 URL 상한보다 충분히 작게 잡은 보수적 가정이다.
- `seq` 가 어긋나면 plugin 은 동기 상태를 버리고 전체 재동기(`resync`)를 요청한다 — 어긋난 splice 로 본문을 망가뜨리지 않는다.

이유: 전용 메시지 채널은 protocol · SDK · 세 OS backend 를 모두 바꿔야 한다. navigation 시도는 세 backend 가 이미 큐로 순서대로 넘기는 경로라 플랫폼별 코드가 없다. 값은 메시지마다 왕복 하나(`webview.post_message`)와 웹뷰 history 항목이다.

### IPC namespace 는 mdedit

id `com.tasty.mdedit`, 크레이트 `tasty-plugin-mdedit`, surface kind `mdedit`, CLI `tasty mdedit …`, IPC prefix `mdedit`, i18n 루트 `mdedit.` 로 이름 규약("id 마지막 마디 = prefix")을 따른다. 연산은 모두 파일 경로가 대상이고 포커스를 보지 않는다([포커스 정책](../../design/policies/focus.md)). host 는 `mdedit` 아래 메서드를 구현하지 않는다.

이유: `markdown` prefix 는 뷰어 plugin 의 것이고 host 메서드를 되돌려 주는 공유 prefix 다. 그 아래에 더하면 뷰어 plugin 의 코드를 고쳐야 하고 trampoline 의무가 따라온다. 에이전트는 이름만 보고 보기(`markdown`)와 편집(`mdedit`)을 가른다.

### 섹션 가드는 사이드카 파일에 둔다

문서 `<dir>/<name>` 의 가드는 `<dir>/.<name>.tasty.toml`(확장자 포함 전체 파일명)에 둔다. 가드는 사람의 저장과 에이전트 쓰기에 같은 판정기로 걸리고, 파일은 판정 때마다 다시 읽는다(캐시 없음). 날짜 조건의 기준일은 판정기의 인자라 시험이 시계를 주입한다.

이유: 문서 안 frontmatter 는 맨 첫 줄을 차지해 첫 줄이 고정된 문서와 충돌하고, 전역 plugin 설정은 문서마다 다른 정규식을 표로 넣을 UI 가 없으며 문서를 옮기면 규칙이 끊긴다. 확장자를 뺀 이름(`.<stem>.tasty.toml`)은 `a.md` 와 `a.markdown` 이 같은 파일을 가리킨다. 잘못된 TOML·정규식은 저장을 막지 않고 경고로 알린다 — 설정 오류 때문에 문서를 못 고치는 상태를 만들지 않는다. 가드는 사고 방지 장치이지 접근 통제가 아니다.

### 방어선은 쓰기 이후에 둔다

에이전트는 `mdedit` 연산(plugin 을 지난다)과 자기 파일 도구(디스크에 직접 쓴다) 두 길로 고친다. 두 번째 길은 막을 수 없으므로 방어선을 쓰기 이후에 둔다.

| 방어 | 어느 경로에 |
|---|---|
| 섹션 단위 연산 + `--if-match` | `mdedit` 연산만 |
| 외부 쓰기 감지·저장 직전 스냅샷 | 둘 다(편집기가 연 파일) |
| base 대비 외부 변경을 hunk 로 보이고 hunk 별 유지·되돌리기 | 둘 다 |
| 섹션 가드 · 비밀값 검사 | `mdedit` 연산과 사람 저장은 쓰기 전에 거부, 직접 쓰기는 감지 뒤 경고 배너 |

외부 쓰기는 조용히 병합하지 않는다 — 깨끗하면 다시 읽고, 더러우면 3-way 병합하고, 겹치면 conflict 로 멈추며, 어느 경우든 검토 목록에 남는다. 에이전트 연산은 열린 편집기의 커서·선택·스크롤과 포커스를 건드리지 않는다.

이유: plugin 은 OS 권한이 없고, 파일 잠금은 OS 마다 의미가 다르며(Windows 만 강제 잠금) 사용자의 다른 편집기까지 막는다. 쓰기를 즉시 되돌리는 감시는 에이전트의 정상 작업을 사용자 확인 없이 지운다. 한계: 편집기가 그 파일을 열고 있지 않으면 직접 쓰기에 대한 스냅샷도 검토 목록도 없다.

### 렌더러 제자리 컴파일

미리보기는 markdown 뷰어의 렌더러 소스를 사본 없이 이 크레이트에서 함께 컴파일한다. `render.rs` 는 `render/` 아래 하위 모듈을 두므로 파일 하나를 `#[path]` 로 실으면 하위 모듈을 mdedit 크레이트 안에서 찾게 된다. 그래서 markdown 의 `src` 폴더를 가리키는 인라인 모듈 안에 선언한다(`crates/tasty-plugin-mdedit/src/preview.rs`).

```rust
#[path = "../../tasty-plugin-markdown/src"]
mod shared {
    pub(crate) mod render;
}
```

- 렌더러가 쓰는 크레이트(`pulldown-cmark` · `ammonia` 등)는 mdedit `Cargo.toml` 에 markdown 과 같은 버전으로 선언한다.
- 렌더러의 UI 문자열(`markdown.*`)은 markdown plugin 설치본의 번역 카탈로그를 읽는다. 없으면 키가 그대로 보인다(기능은 동작한다).
- 편집기 전용 요소(툴바·편집기·배너·`[!agent]` 배지)는 렌더 결과에 덧붙인다 — 렌더러 소스를 고치지 않는다. markdown 쪽에서만 쓰는 항목의 경고는 모듈 단위로 끈다.
- **고정값(pin)**: plugin 버전 게이트는 cargo 의존 폐포로 "어느 plugin 산출물이 바뀌었나"를 판정하므로 `#[path]` 결합을 보지 못한다. 그래서 `crates/tasty-plugin-mdedit/src/shared_renderer.pin.txt` 에 렌더러 소스와 자산의 내용 해시를 적고, 시험 `shared_renderer_pin` 이 현재 내용과 견준다. 다르면 실패문이 pin 갱신 + mdedit patch bump(+ 매니페스트 version · `Cargo.lock`)를 같은 커밋에 하라고 지시한다. pin 파일이 mdedit 크레이트의 `src` 안에 있어 그 갱신이 곧 게이트가 보는 내용 변화가 된다.
- **pin 범위**: `pin::current_pin` 은 `render.rs`, `render/` 아래 하위 모듈 전부, markdown `assets/` 전부를 상대 경로 순으로 해시한다. 하위 모듈만 바뀐 변경도 이 시험이 잡는다.

이유: 공용 lib 로 떼면 markdown plugin 코드를 옮겨야 하고, 복제는 sanitize 허용 목록이 갈라져 한쪽만 보안 수정을 받을 수 있다. 제자리 컴파일은 미리보기 = 뷰어이고 보안 수정이 두 plugin 에 동시에 들어간다. markdown 크레이트에 `[lib]` 가 생기면 크레이트 의존으로 옮기고 pin 은 필요 없어진다.

### 미리보기 편집 단위는 블록 원문 조각

미리보기 편집은 렌더 결과를 markdown 으로 되돌리지 않고 **블록 하나의 원문 조각**을 바꾼다. plugin 이 원문을 렌더러와 같은 파서 옵션으로 다시 파싱해 편집 단위(최상위 문단 · ATX 제목 · 목록 항목 첫 줄 · 최상위 표 셀)마다 원문 범위와 렌더될 글자를 넘긴다. 스크립트는 같은 맥락의 요소를 순서대로 짝짓되 **글자가 같을 때만** 연다. 적용은 그 블록의 현재 원문이 화면을 그릴 때와 같을 때만 범위를 바꾸고, 버퍼만 바꾼다(저장·병합은 기존 경로).

이유: 렌더러는 이벤트를 HTML 로 바꾼 뒤 sanitize 하므로 요소에 원문 위치를 실을 자리가 없고, 그 파일은 고치지 않는다. HTML→markdown 직렬화는 원문 표기(`*`/`_`, 들여쓰기, 이스케이프)를 다시 정해 손대지 않은 바이트 보존이 깨진다. 순서만으로 짝지으면 렌더러가 요소 하나를 더하거나 빼는 순간 다른 줄이 바뀐다 — 글자 검사는 그 실패를 "안 열림"으로 바꾼다. 파서 옵션은 시험 `parser_options_match_the_renderer` 가 렌더러 소스와 대조한다. 웹뷰 스크립트를 도는 자동 시험 채널은 없다 — 짝짓기·키 처리는 헤드리스 브라우저 하네스로 확인했다.

### 정렬되는 블록은 렌더된 자리에서 고친다

블록을 열 때 DOM 을 서식 표기(`**` · `*` · `~~` · 백틱 · `[글](주소)`)와 함께 직렬화한 글을 원문 조각과 글자 단위로 맞춘다(같은 글자 또는 스마트 구두점 치환만 허용). 맞으면 그 블록을 `contenteditable="plaintext-only"` 로 만들어 누른 자리에 커서를 두고, 적용할 때 바뀐 구간만 정렬표로 원문 위치에 옮긴다. 맞지 않으면 원문 조각 입력칸으로 연다. 연 순간 맨 주소였던 링크는 끝까지 맨 주소로 쓴다 — 맨 주소 안쪽을 고치면 `[글](주소)` 로 바뀌어 사용자가 친 글자 밖이 바뀌기 때문이다.

이유: 렌더된 모양 그대로 고치면서도 바꾸는 바이트는 사용자가 고친 구간뿐이다. 렌더러 출력 모양에 기대므로 렌더러가 바뀌면 맞추지 못하는 블록이 늘지만, 손상이 아니라 원문 조각 입력칸으로 실패한다. 서식 붙이기(굵게 만들기 등)는 그 자리에서 되지 않는다.

### 미리보기 조작은 저장할 때만 파일에 쓴다

미리보기의 체크박스 토글을 포함해 사람이 미리보기에서 하는 모든 조작은 버퍼만 바꾸고, 파일에는 저장 단추·저장 단축키에서만 쓴다(가드·비밀값 검사·스냅샷도 그때 돈다). 에이전트의 `mdedit task` 는 IPC 연산이라 바로 쓴다.

이유: 저장하지 않은 체크박스 변경이 파일에 들어가 자동 커밋으로 새는 일을 막고, 사람의 미리보기 조작 규칙을 하나로 둔다. 체크박스 하나 고치고 끝내던 흐름에 저장 한 번이 더 든다.

### 접기는 보기 상태

제목·하위 목록 접기는 웹뷰의 보기 상태다. 원문·버퍼·plugin 에 아무것도 보내지 않는다. 접은 자리는 탭의 `sessionStorage` 에 둔다(키는 제목 수준·글·같은 글 중 몇 번째). 화살표는 CSS `::before` 가 그리고 토글 요소에는 글자가 없어 짝짓기와 정렬이 그대로다.

이유: 접은 상태를 원문(주석 표지)이나 스냅샷에 두면 파일 내용이나 파일 이력이 바뀐다. plugin surface 상태에 두면 블록이 바뀔 때 어느 제목인지 다시 찾는 규칙이 plugin 과 스크립트 양쪽에 생긴다. 제목 접기는 렌더러가 본문을 평평하게(제목과 블록이 `#tasty-md-body` 바로 아래 형제로) 그린다는 데 기댄다 — 렌더러가 절로 감싸면 접기가 아무것도 숨기지 못하는 쪽으로 실패한다.

### 적용 전 고침도 dirty 로 센다

미리보기에서 열린 블록(그 자리 편집 · 원문 조각 입력칸 · 새 줄 입력칸)에 적용 전 고침이 있는지가 바뀔 때마다 스크립트가 `pend {p}` 를 보낸다. `Session::dirty()` 는 버퍼 ≠ base **또는** 적용 전 고침이고, 저장 단추 · 상태줄 · `mdedit status` · `mdedit.lifecycle_busy` 가 이 값을 본다. 병합·저장 판단은 버퍼만 본다(`Session::edited()`). 적용 전 고침은 블록 적용 · 모드 전환 · 문서 다시 싣기로 지워진다.

이유: 그 자리 편집은 적용할 때만 버퍼를 바꾸므로, 이 신호가 없으면 고치는 동안 저장 단추가 꺼져 있고 status 도 깨끗하다고 답한다. 입력마다 버퍼에 적용하면 블록 번호·낡음 검사를 매번 다시 거치고 정렬의 기준점이 바뀐다. 웹뷰에서만 단추를 켜면 단추와 status 가 다른 값을 본다.

### Enter 는 커서 자리에서 나눈다

그 자리 편집 중 Enter 는 커서 자리에 표지 글자(U+E000)를 잠깐 끼워 블록을 원문으로 직렬화하고, 표지 앞뒤를 앞쪽·뒤쪽 원문으로 삼는다. plugin 이 `split` 으로 블록을 앞쪽으로 바꾸고 뒤쪽을 새 항목·새 문단으로 넣은 뒤 다시 그린 문서에서 새 블록을 커서 머리로 연다. 커서가 서식 안이면 그 서식 끝에서 나눈다. `Shift+Enter` 는 문단에서만 받는다.

이유: 정렬 접합을 그대로 타므로 앞쪽+뒤쪽 = 원문이 보장된다. 서식 안에서 그대로 나누면 `**가운**` · `**데 글**` 처럼 사용자가 친 글자 밖의 표기를 바꿔야 한다. 웹뷰에서 DOM 만 나누고 plugin 에 나중에 알리면 블록 번호·원문 조각이 양쪽에서 갈려 이후 편집이 모두 낡음 검사에 걸린다. 항목·제목의 둘째 줄은 원문 표기(줄 끝 공백·역슬래시·들여쓰기)가 렌더 글자와 갈려 다음에 열 때 정렬이 맞지 않는다. 표지 글자가 원문에 이미 있으면 적용 + 다음 자리 열기로 간다.

### 블록 손잡이는 원문 줄을 통째로 옮긴다

손잡이 단위는 최상위 블록과 목록 항목(하위 목록째)이다. 이동 · 복제 · 삭제는 단위의 원문 줄을 통째로 잘라 붙이고 앞뒤 구분(빈 줄 · 줄바꿈)만 다룬다. 형식 변경은 첫 줄 머리의 표지만 바꾼다 — 항목은 목록 형식 사이만, 하위 블록을 가진 항목은 표지 폭이 같을 때만. 제목은 제목 줄만 옮긴다. 자동 저장은 하지 않는다.

이유: 렌더 결과에서 블록을 직렬화해 옮기면 원문 표기가 바뀐다. 번호 목록을 다시 매기면 옮긴 줄 밖의 번호 줄이 모두 바뀐다(화면 번호는 렌더러가 차례로 그린다). 항목을 목록 밖 형식으로 바꾸면 목록이 갈라지며 앞뒤 빈 줄이 새로 필요해 그 줄 밖이 바뀐다. 제목을 섹션째 옮기면 섹션 끝이 탭마다 다른 접기 상태와 엮인다. 빈 최상위 항목에서 Enter 는 빈 문단을 남길 수 없으므로 항목을 지우고 앞 항목 아래에 새 줄 입력칸을 연다. 렌더러가 블록을 다른 요소로 감싸면 태그 순서 짝짓기가 그 블록을 놓치지만, 손잡이가 없어질 뿐 손상은 없다.
