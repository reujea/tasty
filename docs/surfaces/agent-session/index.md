# 에이전트 세션 (`agent_session`)

- **Status**: Implemented
- **kind**: `agent_session` — 번들 plugin `com.tasty.agent-session` (`bundle = false`)
- **렌더 경로**: webview
- **주체**: 로컬 사용자 / AI Agent
- **코드**: `crates/tasty-plugin-agent-session/`
- **화면**: 아래 [화면](#화면) 절

## 목적·지원 범위

Claude Code(stream-json 모드)나 pi(rpc 모드)를 터미널 TUI 가 아니라 줄 단위 JSON 으로 띄우고, 그 대화를 턴 기록으로 보여 주는 대화 탭이다. 쉘 탭처럼 입력하고 답을 받지만 자식에 TTY 가 없어 화면 격자·커서·키 입력은 없다.

- 지원: 새 세션 시작 · 기존 세션 잇기 · 턴 입력과 답 · 도는 턴 취소 · 권한 확인과 질문(`AskUserQuestion`)에 탭에서 답하기 · 추가 작업 폴더 · `/clear` · 현행화 후 compact · 상태줄(모델 · 컨텍스트 · 사용량).
- 현행화 후 compact 는 세 자리에서 자동으로 연다 — 턴 끝 컨텍스트가 기준을 넘을 때(`auto`) · 쉬는 탭의 캐시가 식기 전(`idle`) · 5시간·7일 사용 한도 중 큰 쪽의 사용률이 설정 문턱(기본 90%)을 넘을 때(`limit`, 그 한도 창마다 한 번). 한도 사용률은 claude.ai 로그인 프로필만 받으므로 API 키 프로필에서는 `limit` 이 열리지 않는다.
- API 한도(429)는 agent 프로필이 쓰는 계정 단위로 걸린다. 그래서 차단도 프로필 단위다. 한 탭의 턴(현행화 턴 포함)이 429 로 끝나면 그 프로필의 자동 전송을 1분 동안 멈춘다. 자동 전송은 429 재전송과 `auto` · `idle` · `limit` 현행화다. 기다림이 끝나면 자동 전송 하나만 탐침으로 보낸다. 성공하면 풀리고, 또 429 면 기다림이 두 배가 된다(1·2·4·8·15분, 상한 15분). 탐침 결과가 15분 안에 오지 않으면 다시 탐침을 허락한다. 차단이 첫 429 부터 15분을 넘으면 분당 한도가 아니라 지출 상한·일 한도·조직 공유 소진 같은 긴 차단으로 본다. 이때 재전송 예약을 버리고 Console 확인을 안내한다. 사용자가 직접 보내는 말은 막지 않고, 그 결과도 차단기에 반영한다. 차단 중에는 실패한 `idle` 현행화 뒤 회수를 하지 않는다. 내린 세션은 다음 입력에 컨텍스트 전체를 다시 써서, 풀리자마자 큰 요청을 내기 때문이다.
- 프로필 단위 분당 계측: 열린 탭이 쓰는 agent 프로필마다 별도 스레드가 15초마다 그 설정 폴더(`CLAUDE_CONFIG_DIR`)의 대화 기록을 잰다. 다른 탭 · 터미널의 claude · 하위 에이전트 기록까지 센다. 최근 5분 안에 바뀐 파일의 끝 4 MB 만 읽는다. 최근 1분의 요청 수(`requestId` 로 중복 제거) · 분당 입력 한도에 세는 입력+캐시 쓰기 토큰 · 출력 토큰, 최근 5분의 429 수, 마지막 성공 · 429 시각을 낸다. 상태줄 넷째 줄에 `1m:21req ↑406k/↓38k` · `429:4` · `차단:12m` 으로 보인다. 기록으로 센 추정이다. 서버의 버킷 잔량 헤더는 Claude Code 가 넘기지 않는다.
- 같은 계측으로 다른 세션의 결과를 차단기에 싣는다. 그 프로필의 마지막 결과가 2분 안의 429 이고 마지막 해제 뒤의 것이면 차단을 연다. 차단 중 차단 시작 뒤의 성공이 마지막 결과면 푼다. 탭이 자기 턴만 보면, 같은 프로필의 터미널 세션이 이미 막힌 것을 모른 채 자동 전송을 연다.
- `idle` · `limit` 은 사용자가 시키지 않은 현행화라 프로필마다 하나씩만 연다. 같은 프로필의 다른 탭이 `idle` · `limit` 현행화 중이거나 429 재전송을 기다리면 미룬다. 미룬 탭은 이번 쉼을 쓴 것으로 적지 않아 다음 판정에서 다시 연다. 캐시가 식은 큰 세션의 현행화는 컨텍스트 전체를 입력으로 다시 보내므로, 여러 탭이 한꺼번에 열면 서로를 429 로 막는다. 사용자가 연 현행화는 줄을 서지 않는다.
- API 오류로 끝난 턴은 실패 사유로 그 턴의 본문을 싣는다(`API Error: Request rejected (429) …`). Claude Code 는 이런 턴의 `result` 를 `subtype` `success` 로 보내고 오류 문면은 본문에만 싣는다 — `success` 는 사유에서 뺀다. 다른 `subtype`·`errors[]` 가 있으면 `<사유> (출력: <본문>)` 이다.
- 현행화가 실패하면(현행화 턴의 오류 · 중지 · 턴 유실) compact 를 보내지 않고, 안내 줄에 사유를 · 상태줄에 "현행화 멈춤" 을 보인다. 둘 다 다음 현행화가 시작되거나 오류 없이 끝난 턴이 오면 거둔다.
- 유휴 회수: 휴식 시계가 유휴 기한(캐시 수명 − 1분: 5분 캐시 240초 · 1시간 캐시 3,540초)을 넘기면 세션의 claude 를 내린다. 컨텍스트가 유휴 기준 이상이면 `idle` 현행화 → compact 가 끝난 뒤(실패해도), 미만이거나 유휴 현행화가 꺼졌으면 바로 내린다. 현행화가 끝났을 때 휴식 시계가 아직이면 그때까지 기다린다. 탭에는 `sleep` 과 같은 표시가 켜지고 다음 입력이 `--resume` 으로 다시 띄운다. 설정 `idle_reclaim`(기본 켬)으로 끈다.
- 유휴 시계 두 개: 캐시 시계는 API 를 부른 턴의 끝(현행화 턴 포함)에서만 다시 재고 `idle` 현행화를 연다 — 서버 캐시는 API 호출만 늘리므로, 로컬 명령으로 이 기한을 밀면 현행화가 식은 캐시에 컨텍스트 전체를 다시 쓴다. 휴식 시계는 사람이 연 턴의 시작과 끝, 탭 조작(`#` 꼬리표가 붙은 이동: 보내기 · 중지 · 비우기 · 폴더 · 응답 등), 세션을 겨눈 IPC 명령(`tell` · `clear` · `sync_compact` · `add_dir` · `remove_dir` · `abort`)에서 다시 재고 회수를 정한다. 자동 현행화 · compact 턴은 휴식 시계를 밀지 않는다. 휴식 시계가 비었으면(plugin 재기동 뒤) 캐시 시계를 쓴다.
- 캐시 수명은 그 탭이 턴에서 관측한 캐시 쓰기(1시간 · 5분)가 먼저고, 관측이 없을 때(비우기 직후 · plugin 재기동 직후) 프로필 `cache_ttl`, 그것도 없으면 5분이다. 관측이 먼저인 것은 인증 변수가 빠진 재기동처럼 1시간 캐시가 5분으로 내려간 세션을 프로필 값이 덮지 않게 하려는 것이다.
- pi 세션: 실행기가 pi 의 rpc 줄을 claude stream-json 모양으로 바꿔 넣는다 — 대화 화면 · 출력 기록 · 현행화가 같은 길을 탄다. 권한 확인 · 질문 · `command_lifecycle` · 턴 밖 작업 · 상태줄의 사용 한도와 claude hook(`claude-idle` 등)은 pi 에 없다. `/clear` 는 `new_session`, `/compact` 는 `compact` 명령으로 간다.
- 지원하지 않음: `claude` · `pi` 외 종류(그 프로필은 거절한다) · 모델 목록 조회(별칭과 프로필의 `model` 을 보인다) · 동시 실행 수 상한.

### agent 프로필

세션은 agent 프로필로 띄운다. 프로필은 `$TASTY_PLUGIN_DATA_DIR/profiles/<이름>.json` 파일 하나이고 파일 이름이 프로필 이름이다. 폴더가 비면 기본 프로필 `claude` 하나를 쓴다.

| 칸 | 뜻 | claude 인자 |
|---|---|---|
| `agent_type` | `claude` 또는 `pi`(옛 파일의 `kind` 도 읽는다) | — |
| `command` | 실행 파일과 앞붙이 인자(공백 분리, 비우면 종류 이름) | — |
| `cwd` | 기본 작업 폴더 | 자식의 cwd |
| `env` | 자식 환경에 더할 값(예: `CLAUDE_CONFIG_DIR`) | — |
| `model` | 기본 모델 | `--model` |
| `permission_mode` | 기본 권한 모드 | `--permission-mode` |
| `settings` | JSON 객체 | `--settings` |
| `add_dirs` | 늘 붙일 추가 폴더 | `--add-dir` 반복 |
| `args` | 맨 뒤에 붙일 인자 | 그대로 |
| `cache_ttl` | 프롬프트 캐시 수명 `5m` · `1h` — 탭이 캐시 종류를 아직 관측하지 못했을 때 유휴 기한에 쓴다. 다른 값은 거절한다 | — |

자식 환경에서는 `TASTY_*` · `CLAUDE_CODE_*` · `CLAUDE_PID` · `CLAUDECODE` 를 뺀다 — 자식의 hook 이 tasty 를 부모로 오인하지 않게 한다.

pi 프로필은 `model` · `env` · `cwd` · `args` 와 `add_dirs` 만 쓴다(`permission_mode` · `settings` 는 claude 칸이다). pi 설정 폴더는 보통 `env` 의 `PI_CODING_AGENT_DIR` 로 고른다. pi 의 명령줄은 `pi --mode rpc --session-id <좌표>` 에 `--name` · `--model` · `--append-system-prompt` 를 붙인다. pi 는 그 id 의 세션이 없으면 만들고 있으면 이으므로 새 세션과 재개가 같은 인자다. 추가 폴더는 pi 에 없어 그 목록을 지침 끝에 한 줄로 알린다.

세션 하나에 프로필은 하나만 고른다(시작 화면 연결 탭의 select · CLI `--agent`). 시작 화면은 프로필을 **에이전트**라고 부른다.

### 역할 폴더

역할 폴더는 `CLAUDE.md`(지침)를 가진 폴더다. 명부는 `$TASTY_PLUGIN_DATA_DIR/roles.json` 이고 이름 → 경로를 적는다. 세션을 띄울 때 여럿을 고른다(시작 화면 연결 탭의 역할 표 · CLI `start --roles a,b` · 탭 복제는 원본의 역할을 옮긴다). 모르는 이름이 있으면 띄우기 전에 거절하고, 띄운 뒤 명부에서 빠진 역할은 로그를 남기고 빼고 다시 띄운다.

| 종류 | 역할 폴더 하나당 |
|---|---|
| claude | `--add-dir <폴더>` 를 붙이고, 자식 환경에 `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` 을 넣어 그 폴더의 `CLAUDE.md` 를 읽게 한다 |
| pi | `--append-system-prompt <폴더>/CLAUDE.md` (`CLAUDE.md` 가 없는 폴더는 건너뛴다) |

세션 기록과 세션 행은 고른 역할 이름(`roles`)을 싣는다.

### 관리

에이전트는 시작 화면의 **에이전트 관리** 탭, 역할은 **역할 관리** 탭에서 고친다. 고친 뒤 화면을 다시 그리고 그 탭을 연 채로 맨 위에 결과 한 줄을 둔다(실패는 빨간 상자). 연결 탭의 select 와 역할 표에도 바로 보인다.

- 에이전트 폼: 이름 · 에이전트 종류 · 실행 명령 · 작업 폴더(옆의 **선택…** 이 폴더 피커를 연다) · 모델 · 환경(줄마다 `KEY=VALUE`). 모드가 둘이다.
  - 새로 만들기: 제목 "새 에이전트", 단추 "만들기". 목록에 있는 이름(폴더가 비었을 때의 기본 `claude` 포함)이면 거절하고 아무것도 쓰지 않는다. 거절 판정은 plugin 이 한다(폼 값 `pmode=new`).
  - 편집: 표의 **편집** 으로 들어간다. 제목 "에이전트 편집", 단추 "저장", 이름은 잠기고 **취소** 단추가 생긴다. Esc 도 편집을 끝낸다. 적은 칸만 바꾸고 폼에 없는 칸(`settings` · `add_dirs` · `args` · `permission_mode`)은 둔다. 없는 이름의 편집은 거절한다(`pmode=edit`).
  - Enter 는 제출이다(환경 칸 안에서는 줄바꿈). 실패한 제출과 폴더 선택은 화면을 다시 그리므로 친 값을 webview 의 `sessionStorage` 에 두었다가 되살린다.
- 에이전트 표: 이름 · 에이전트 종류(실행 명령이 종류와 다를 때만 `종류 · 명령`) · 작업 폴더 · 모델 · 환경(`KEY=값`, 값의 홈 폴더는 `~`) · 조작(편집 · 삭제).
- 역할 관리 탭: 새 역할(이름 · 폴더 + **선택…**, 추가) · 가져오기(상위 폴더 + **선택…**: `CLAUDE.md` 가 있는 하위 폴더를 폴더 이름으로 모두 더한다) · 역할 표(이름 · 폴더 · 지침: `CLAUDE.md 있음`/`없음` · 삭제). 역할 삭제는 폴더를 건드리지 않는다.
- 삭제(세션 · 에이전트 · 역할)는 두 단계다. 첫 클릭에 그 칸이 "삭제할까요? 삭제 · 취소" 로 바뀌고, 확인을 눌러야 지운다.

## 상태 소유자

- 구조 트리의 leaf: `SurfaceDescriptor`(kind `agent_session`). surface meta `agent-session-id` 가 이 탭에 이어진 세션 id(supervisor 기록 id)다. claude 대화 id 는 `agent-session-conversation-id` 에 따로 남기며(바뀔 때만 쓴다) 읽는 곳은 없다. 두 id 는 이어받기 · `/clear` 에서 갈린다. 잇기 값이 기록 id 가 아니고 그 대화를 가진 기록이 하나면 활동 폴링이 탭마다 한 번 그 기록 id 로 되돌린다. 그런 기록이 없거나 둘 이상이면 그대로 두고 경고를 남긴다.
- 실행 자원: claude 자식 프로세스는 plugin 프로세스가 띄우고 쥔다. plugin 이 내려가면 자식도 내린다.
- 코드 소유: crate `src/` 는 층을 디렉터리로 나눈다 — `domain/` · `ports/` · `application/` · `adapters/driving/` · `adapters/driven/`, 조립은 `main.rs`. 탭 하나의 대화 상태(`Convo` — 턴 · 대기 · 표시 상태)와 턴 전이 · 스냅샷 모양은 `domain/convo.rs` 가, surface 별 대화 표와 대기열 · 활동 · 워커 결과는 `application/plugin.rs` 의 `SupervisorPlugin` 이 쥔다. 로직은 호스트와 데몬을 포트(`ports/host.rs` 의 `HostCall` · `ports/supervisor.rs` 의 `Supervisor`)로만 부르고, 실물(`SdkHost` · `adapters/driven/local.rs` 의 `LocalSupervisor`)은 `main.rs` 가 만들어 넣는다. 문서 싣기 · 증분 메시지는 `application/session_surface.rs`, 화면 HTML 은 `adapters/driving/view.rs`, navigation 주소 판독은 `adapters/driving/url.rs`, IPC 오류 변환은 `adapters/driving/ipc.rs` 가 맡는다. 파일 명부 · 보관(`adapters/driven/store/`)과 스킬 · 계측 · 프록시 모듈은 포트 없이 응용이 직접 부른다. 이 응용 → driven 참조는 crate 의 `.code-topology-known.json` 에 사유와 함께 고정돼 있다. `HostHandle` · `SdkHost` · `LocalSupervisor::new` · `IpcMethodError` 가 `main.rs` · `ipc.rs` 밖에 새로 생기면 `tasty-doc-guards` 의 `agent_session_port_bypasses_do_not_grow` 가 실패한다.
- 세션 기록: `$TASTY_PLUGIN_DATA_DIR/sessions.json` — 세션 id · 프로필 이름 · claude 세션 id(재개 좌표) · cwd · 모델 · 권한 모드 · 추가 폴더.
- View 상태: 대화 로그(턴 · 이전 대화 · 시스템 줄 · 에이전트 내역 줄)와 상태줄 · 질문 카드 · 에이전트 내역 패널은 페이지 앱이 그린다. 상태줄은 plugin 이 줄과 토큰(값 · 라벨 · 색 · 툴팁 · 복사 링크 · 한도 초기화 시각)을 계산해 싣고 앱은 그대로 그린다. 질문 카드는 묻는 내용(권한 도구와 입력 미리보기, 또는 질문과 선택지)을 싣고, 선택은 일반 입력칸에 남아 다시 그려도 유지된다. 에이전트 내역 줄 · 패널은 카드 순서와 글 · 단계를 plugin 이 싣고, 카드 · 단계마다 바뀌지 않는 key 로 그려 다시 그려도 펼친 카드와 목록 · 단계 스크롤이 그대로다. plugin 은 문서에 상태 JSON 과 내장 Preact · htm(출처 · 라이선스는 `crates/tasty-plugin-agent-session/assets/NOTICE.md`)을 싣고, 앱이 그 상태로 컴포넌트를 그린다. 이후 변화는 `webview.post_message` 메시지로 오고, 로그 · 상태줄 메시지(턴 답 · 늦어짐 · 이어 간 턴 · 자르기 · 시스템 줄 · 보낸 턴 · 상태줄 · 복사 표시 · 질문 카드 · 답하기 실패 · 에이전트 내역)는 앱의 store 를 바꿔 다시 그리며 나머지(진행 표시 · 대기열 칸 · 안내 줄)는 문서의 처리기가 그 자리를 고친다. 답 글은 텍스트로만 넣고 마크다운 표는 그 요소 안에서 짓는다. 사용자가 로그 맨 아래를 보고 있었으면 답이 채워지거나 질문 카드가 떠서 내용이 길어져도 끝을 따라가고, 위를 읽고 있었으면 위치를 그대로 둔다. 시각(`[HH:MM:ss]` · 날짜 줄)은 앱이 webview 의 지역 시간대로 그린다. 문서 전체 교체는 `webview.set_url` 로 하며, 그때는 그 시점 상태가 문서에 다 들어간다. kind 는 `lazy_webview` 라 탭이 처음 보일 때 WebView 가 생긴다 — 복원된 탭이 많아도 보지 않은 탭의 렌더링 프로세스는 뜨지 않는다. 그 전 메시지는 버려지므로 `surface.webview_created` 를 받으면 지금 대화로 문서 전체를 다시 싣는다. 같은 탭의 WebView 가 다시 만들어지면 입력칸에 쓰던 글과 로그 스크롤은 처음 모양으로 돌아간다([WebView 생성 시점](../../design/systems/webview.md#생성-시점--미리-만들기와-처음-보일-때-만들기)).

## 생성·갱신·종료

- 생성: 탭 만들기(preset 칸 `session_id` · `agent` · `cwd` · `model` · `name` · `prompt`) 또는 `tasty agent-session start`. 세션이 없으면 시작 화면을 그린다.
- 실행 파일: 프로필의 실행 명령이 이름뿐이면(`claude` · `pi`) 사용자의 대화형 로그인 셸(`$SHELL -ilc`)이 쓰는 PATH 에서 찾아 절대 경로로 띄우고, 그 PATH 를 자식 환경에도 넣는다. 앱 아이콘·런처로 띄운 tasty 의 PATH 에는 `~/.local/bin` 같은 설치 위치가 없을 수 있어서다. 셸 PATH 는 plugin 이 뜰 때 한 번 받는다(상한 5초). 못 받으면 plugin 의 PATH 를 쓴다. 프로필 `env` 에 `PATH` 가 있으면 그 값이 이긴다.
- 시작: `claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --session-id <id>` 에 프로필과 폼 값을 붙인다. 대화 탭에서 띄운 세션은 `--permission-prompt-tool stdio` 로 권한 확인을 탭이 받는다.
- 턴: stdin 에 `uuid` 꼬리표를 실은 `user` 메시지를 쓰고 `result` 줄에서 턴을 닫는다. 취소는 `control_request{subtype: interrupt}` 다.
- 자가 턴: 백그라운드 작업이 끝나면 claude 가 입력 없이 턴을 연다(`system/task_notification` → `system/init` → … → `result`). 탭은 이 턴도 도는 턴으로 보이고 답을 기록에 남긴다. 턴 끝의 답은 `command_lifecycle` 에서 `started` 로 보고된 입력에만 간다. 그래서 자가 턴 도중 보낸 입력은 자가 턴이 아니라 제 턴의 답을 받고, 한 턴에 합쳐진 입력들은 모두 같은 답을 받는다. `command_lifecycle` 을 내지 않는 claude 에서는 도착 순서로 짝짓는다.
- 재개: 멈춘 세션에 턴을 보내면 `--resume <claude 세션 id>` 로 다시 띄운다. `/clear` 뒤 claude 가 새 세션 id 를 내면 그것을 좌표로 바꿔 적는다.
- 추가 폴더: 바뀌면 자식을 내리고 `--resume` 으로 다시 띄운다(대화는 그대로). 턴 중이나 턴 밖 작업이 남은 동안에는 거절한다.
- 턴 밖 작업: 백그라운드 Bash · Monitor · 백그라운드 하위 에이전트는 턴이 끝나도 남는다. 실행기는 `system/background_tasks_changed`(살아 있는 작업 전체)를 정본으로, 그 줄이 없는 claude 에서는 `task_started` · `task_updated` · `task_notification` 으로 목록을 맞춘다. 세션 행은 `background_tasks` 와 `busy`(턴 · 기다리는 물음 · 턴 밖 작업 중 하나라도 있음)를 싣는다.
- 바쁨 판정: 넓은 판정(`busy`)은 탭 점 · 상태줄 · 정지 전 질의(`agent_session.lifecycle_busy`) · 유휴 현행화 · 유휴 회수 · 추가 폴더 변경이 쓴다 — 자식을 내리면 잃는 것이 있는가와 같은 질문이다. 입력 전송 · 대기열 · 재시도 · 비우기 · 문턱 현행화는 턴 판정(`turn_active`)만 본다. 끝나지 않는 작업(개발 서버 등)이 대화를 막지 않게 하기 위해서다.
- 종료: 탭을 닫으면 그 세션의 자식을 내린다. 기록은 남아 다시 이을 수 있다.

## 저장·복원

- 저장: 탭 스냅샷에 세션 id 와 턴 기록 일부(턴 시각 포함)를 싣는다. 세션 기록은 plugin 데이터 폴더에 따로 남는다.
- 대기열 파일: 턴이 도는 동안 쌓인 말은 바뀔 때마다 plugin 데이터 폴더의 `send-queue/<세션 id>.json`(문자열 배열)에 임시 파일을 거쳐 바꿔 쓰고, 한 메시지로 꺼내 보내면 지운다. 탭을 되살릴 때는 이 파일이 스냅샷의 대기열보다 앞선다 — 스냅샷은 호스트가 레이아웃을 저장할 때만 기록되므로, 그 사이 plugin 이나 앱이 죽어도 쌓인 말이 남는다. 탭을 닫으면 파일을 지우고, 다시 열면 스냅샷이 되살린다. 세션 id 가 정해지기 전에는 메모리에만 둔다.
- 메모리 절약(`release_hidden_webview`, 세션 관리 묶음, 기본 끔): 켜면 호스트가 가려진 대화 탭의 WebView 를 없앤다([가려지면 없애기](../../design/systems/webview.md#가려지면-없애기--메모리-절약)). 다시 보이면 `surface.webview_created` 로 문서 전체를 다시 싣는다. 대화 · 대기열 · 상태는 plugin 이 쥐고 있어 잃지 않는다. 페이지에만 있던 입력칸의 쓰던 글은 페이지가 300ms 묶어 `agent-view=<n>&d=<글>` 로 보내고(로그에 남기지 않는다) plugin 이 `view-state/<세션 id>.json` 에 둔다. 다시 실은 문서와 재시작으로 되살린 탭은 그 글로 입력칸을 채운다. 보내면 비우고, 탭을 닫으면 지운다. 스크롤은 다시 실으면 바닥에서 시작한다. 설정을 바꾸면 열린 문서에 `view.save` 메시지로 알려 다시 싣지 않고 보내기만 켜고 끈다. 끄면 WebView 를 한 번 만든 뒤 숨겨도 유지한다. 다시 싣는 시간은 대화 길이를 따르므로 긴 대화는 `memory_turns` 로 줄인다.
- 복원: 탭이 복원되면 같은 세션 id 로 다시 잇는다. 자식은 첫 턴에 `--resume` 으로 뜬다.
- 실패: 세션 기록이 없으면 시작 화면을 그린다.

## 설정

설정 화면의 agent_session 페이지다. 묶음은 대화 기록 보관 → 컨텍스트 비용 자동 관리 → 세션 관리 → API 트래픽 조절 순서다. 컨텍스트 · 세션 묶음은 스위치 없는 머리 아래에 기능마다 스위치(토글)를 두고, 그 뒤에 기준 칸과 왜 · 언제를 적은 읽기 전용 글을 둔다. 머리 스위치는 묶음 전체의 칸을 숨기므로([플러그인 개발](../../dev-guide/plugin-development.md#설정-페이지)) 기능 여럿을 한 묶음에 모으면 머리 스위치를 쓸 수 없다. 그래서 기능 스위치를 꺼도 그 기준 칸은 보이고, 묶음 맨 위의 설명 글이 그렇게 알린다. 스위치의 저장 키는 예전 묶음 머리 스위치와 같아 저장값이 이어진다. API 트래픽 조절은 머리 스위치 묶음이다. 아래 값은 모두 코드의 기본값과 같고 시험(`manifest_defaults_match_the_code` · `limit_sync_manifest_defaults_match_the_code` · `manifest_default_matches_the_code` · `the_settings_page_keeps_its_groups_in_order`)이 매니페스트와 대조한다.

| 묶음 | 머리 스위치(기본) | 칸(기본) |
|---|---|---|
| 대화 기록 보관 | 없음 | `memory_turns`(0) · `disk_swap`(끔) |
| 컨텍스트 비용 자동 관리 | 없음 | 설명 글 · `sync_threshold_on`(켬) · `sync_threshold_tokens`(400,000, 1 이상) · 글 · `idle_sync_on`(켬) · `idle_sync_tokens`(150,000, 1 이상) · 글 · `limit_sync_on`(켬) · `limit_sync_percent`(90, 1–100, %) · 글 · `sync_prompt`(읽기 전용) · `compact_prompt`(읽기 전용) |
| 세션 관리 | 없음 | `idle_reclaim`(켬) · 글 · `cache_watch`(켬) · 글 · `release_hidden_webview`(끔) · 글 |
| API 트래픽 조절 | `traffic_on`(끔) | `traffic_up_kbps`(0) · `traffic_down_kbps`(0), KB/s, 0–1,250,000 |

- `memory_turns`: 탭 메모리에 남길 턴 수. 0 이면 전부라 끄는 스위치가 따로 없다.
- `disk_swap`: 넘친 턴을 버리지 않고 디스크로 옮긴다.
- 컨텍스트 비용 자동 관리의 목적: 컨텍스트가 커지면 턴마다 비용이 늘고 응답이 느려진다. 에이전트마다 기준을 따로 두면 관리가 어렵고, Claude Code 의 auto-compact 는 창 한계에서 메모리 안에서만 요약해 재개 지점이 문서로 남지 않는다. 그래서 하나의 기준 묶음으로 먼저 현행화(상태 · 재개 지점 문서 갱신)하고 그 문서와 진행 중인 작업을 중심으로 compact 한다.
- `sync_threshold_on` · `sync_threshold_tokens`(작업 중 현행화): 턴 끝 컨텍스트가 기준을 넘으면 그 탭이 60초(`AUTO_QUIET`) 조용해진 뒤 현행화 → compact 를 연다. 조용함은 마지막 턴 끝부터 재고, 탭이 연 턴 · 대기열 · 물음 · 비우기가 없어야 한다. 기준보다 200,000 토큰(`AUTO_URGENT_OVER`) 이상 많으면 기다리지 않고 다음 판정에서 연다. 기준은 창의 90% 를 넘지 않게 끌어내린다(200k 창이면 180,000) — 창보다 큰 기준은 영영 안 넘고, 창에 붙이면 Claude Code 의 자체 compact 가 먼저 돈다. 같은 세션의 자동 실행 사이는 10분이다. compact 뒤 첫 턴 끝에도 기준을 넘으면 바닥값(시스템 프롬프트 · 도구 정의)으로 보고 멈추며, 컨텍스트가 기준 아래로 내려가면 다시 장전한다. 끄는 것은 스위치뿐이고, 기준 칸의 1 미만 값은 기본값으로 읽는다.
- `idle_sync_on` · `idle_sync_tokens`(유휴 현행화): 프롬프트 캐시는 5분(또는 1시간) 뒤 식고, 식은 뒤 첫 요청은 컨텍스트 전체를 캐시에 다시 쓴다(5분 캐시 쓰기 ×1.25 · 1시간 캐시 쓰기 ×2 대 읽기 ×0.1). 그래서 캐시 시계의 유휴 기한(캐시 수명 − 1분: 240초 · 3,540초)에 컨텍스트가 기준 이상이면 현행화 → compact 를 연다. 쉼 한 번에 한 번이고 사람(또는 `tell`)이 다음 말을 보내야 다시 열린다. 같은 프로필에서는 한 번에 하나만 연다(위 `idle` · `limit` 줄서기). 기준(150,000)이 작업 중 기준(400,000)보다 낮은 것은 의도다. 끄는 것은 스위치뿐이고, 기준 칸의 1 미만 값은 기본값으로 읽는다.
- `limit_sync_on` · `limit_sync_percent`(사용 한도 현행화): 5시간 · 7일 사용 한도 중 큰 쪽의 사용률이 이 % 이상이면 현행화 → compact 를 연다. 한도에 막혀 세션이 끊기기 전에 재개 지점을 남기려는 것이다. 그 한도 창(풀리는 시각)마다 한 번이다. 사용률은 claude.ai 로그인 프로필만 받으므로 API 키 프로필에서는 돌지 않는다. 끄는 것은 스위치뿐이고, 문턱 칸의 1 미만 값은 기본값, 100 초과는 100 으로 읽는다.
- 문구 칸 `sync_prompt` · `compact_prompt`(현행화 · compact 문구)는 읽기 전용 글이라 설정 창에서 고칠 수 없다. 저장값이 없으면(공백뿐인 값 포함) 코드 기본값을 쓰고 화면도 그 기본 문구(활성 언어)를 보인다. 세 현행화가 함께 쓴다.
- `idle_reclaim`(유휴 세션 프로세스 회수): 쉬는 탭마다 claude 프로세스가 메모리를 잡는다. 휴식 시계가 유휴 기한을 넘기면 세션의 claude 를 내린다. 유휴 현행화가 돌 탭은 그것이 끝난 뒤(실패해도), 기준 미만이거나 유휴 현행화가 꺼졌으면 바로 내린다. 턴 밖 작업(백그라운드)이 남은 세션은 바쁨이라 내리지 않는다. 다음 입력이 `--resume` 으로 다시 띄운다. 세션 관리 묶음은 머리 스위치가 없어 유휴 현행화를 꺼도 이 스위치는 숨지 않는다.
- `cache_watch`(프롬프트 캐시 재작성 알림): 쉬지 않았는데(쉰 시간 ≤ 직전 캐시 수명) 턴의 첫 호출이 대화 전체를 캐시에 다시 쓰면 상태줄 토큰과 알림 줄로 알리고, 1시간 캐시가 5분으로 내려가면 세션마다 한 번 알린다. 쉰 뒤의 재작성은 지표만 남긴다. 끄면 알림 · 상태줄 토큰만 끄고 지표는 남긴다.
- `release_hidden_webview`(메모리 절약): 가려진 대화 탭의 WebView 를 내리고 쓰던 글은 디스크에 둔다(위 "메모리 절약"). 대화 탭을 많이 열어 둘 때 권한다.
- `traffic_on` · `traffic_up_kbps` · `traffic_down_kbps`: 켜져 있으면 claude 프로필 세션의 API 연결을 loopback 프록시로 흘려 올림 · 내림을 각 한도(KB/s, 1 KB = 1,000 바이트) 아래로 맞춘다. 한도 칸의 0 은 그 방향 무제한이다. 아래 "API 트래픽 조절" 을 본다.
- 왜 · 언제 글(`sup.about.*`)은 위 수치를 그대로 적는다. `the_setting_descriptions_state_the_numbers_the_code_uses` 가 세 언어의 글에 코드 상수(60초 · 200,000 · 90% · 10분 · 240초 · 3,540초)가 있는지 본다.
- 바꾼 값은 최대 10초 뒤에 현행화 판정 · 트래픽 한도에 반영된다(설정 변경을 plugin 에 알리는 길이 없어 짧은 캐시로 다시 읽는다).

### API 트래픽 조절

턴마다 대화 전체가 요청 본문으로 올라간다(프롬프트 캐시는 계산만 줄이고 바이트는 줄이지 않는다). 단말기 링크가 상단 네트워크 장비의 policing · shaping 한도보다 빠르면 그 순간의 버스트가 버려지고, 연결이 끊기면 claude 가 요청을 처음부터 다시 보낸다. 보내는 쪽에서 한도 아래로 흘리면 버려질 것이 없다.

- 길: `traffic_on` 이 켜져 있으면 claude 프로필 세션을 띄울 때 자식 환경의 `HTTPS_PROXY` · `https_proxy` 를 plugin 프로세스의 loopback 프록시(`http://127.0.0.1:<동적 포트>`)로 바꾼다. 프록시는 `CONNECT` 만 받고(그 밖은 `405`) TLS 를 풀지 않고 바이트를 중계한다.
- 한도: 올림(자식 → 서버)과 내림이 각자 토큰 버킷 하나를 plugin 프로세스 전체가 나눠 쓴다 — 상단 장비의 한도는 단말기(포트) 단위라서다. 버스트는 한도의 1/8초 분량이고, 한 번에 읽는 양도 한도가 낮을수록 줄인다. 한도는 이미 열린 터널에도 바로 걸리고, 끄면 프록시를 쓰던 세션은 한도 없이 통과한다.
- 적용 시점: 환경 변수는 띄울 때만 넣을 수 있어 켜는 것은 새로 뜨거나 재개되는(회수 뒤 다음 입력 포함) 세션부터다.
- 기존 프록시: 자식이 원래 받을 `HTTPS_PROXY`(프로필 `env` → plugin 환경 순)가 `http://[user:pass@]host[:port]` 이면 그 뒤로 이어 보낸다 — upstream 에 `CONNECT` 를 한 번 더 보내고 자격이 있으면 `Proxy-Authorization: Basic` 을 싣는다. upstream 의 거절 상태 줄(예: `407`)은 자식에게 그대로 돌려준다. upstream 마다 리스너가 따로지만 버킷은 같다. `NO_PROXY` 에 든 호스트는 claude 가 프록시를 안 거쳐 조절 밖이다.
- 이어 보낼 수 없는 upstream(`https://` · `socks5://` 등)이면 연결을 깨지 않으려고 그 세션은 조절 없이 띄우고 경고를 남긴다.
- pi 프로필에는 걸지 않는다 — pi 가 `HTTPS_PROXY` 를 따르는지 확인되지 않았다.
- 관측: `tasty agent-session traffic`(IPC `agent_session.traffic`)이 켜짐 · 한도 · 중계한 올림 · 내림 바이트 · 열린 · 누적 · 실패 터널 수 · 리스너 포트와 upstream 을 낸다.

## IPC·CLI

네임스페이스는 `agent_session.*`, CLI 는 `tasty agent-session <명령>` 이다. 탭을 고르는 명령은 `--surface` 를 생략하면 호출자의 `TASTY_SURFACE_ID` 를 쓴다.

- 세션: `start` · `tell` · `abort` · `sleep` · `status` · `output` · `watch` · `broadcast` · `delete` · `list` · `clear` · `add-dir` · `remove-dir`
- 탭 연결: `link-add` · `link-of` · `link-remove` · `link-siblings` · `link-list` · `sync`
- 대화 탭: `sync-compact`
- 트래픽 조절: `traffic`
- 프로필: `profile-list` · `profile-show --name` · `profile-set --name --json` · `profile-remove --name`
- 역할: `role-list` · `role-add --name --path` · `role-scan --path` · `role-remove --name`

`tell` 은 답을 응답에 싣고 최대 2분 기다린다. 더 긴 턴은 완료 전략 `agent-session-tell-wait` 가 `status` 의 `turn` 칸으로 끝을 잡는다.
본문은 위치 인자나 `--text` 중 하나로 준다. 둘 다 없거나 둘 다 있으면 사용법을 담아 거절한다.
탭이 가리키는 세션이 지워졌으면 연결이 낡았다고 알리고 `link-remove` 로 끊는 법을 준다.
탭이 권한 확인이나 질문에 답을 기다리는 중이면 말을 대기열에 넣고 곧바로 `queued: true` 와 경고를 돌려준다 — 그 말은 물음을 풀지 않는다.

## 검증 기준

- Given 프로필 폴더가 비어 있다 When `tasty agent-session profile-list` Then 기본 프로필 `claude` 하나가 `builtin: true` 로 온다.
- Given 프로필 `work` 에 `model` 과 `env` 가 있다 When 그 프로필로 세션을 시작한다 Then claude 인자에 `--model` 이 붙고 자식 환경에 그 `env` 가 들어간다.
- Given 세션이 멈춰 있다 When 대화 탭에서 말을 보낸다 Then `--resume` 으로 다시 떠 이전 대화를 이어 답한다.
- Given 어제와 오늘 보낸 턴이 있다 When 대화 화면을 연다 Then 두 날짜 줄이 각 날의 첫 턴 위에 있고, 턴마다 `[HH:MM:ss]` 가 보낸 말 앞에 붙는다.
- Given 턴이 도는 중이다 When 중지 단추를 누른다 Then 자식에 interrupt 가 가고 세션은 살아 다음 말을 받는다.
- Given 권한 확인이 필요한 도구를 claude 가 쓰려 한다 When 탭의 허용 단추를 누른다 Then 그 도구가 실행되고 턴이 이어진다.
- Given `agent_type` 이 `pi` 인 프로필 When 그 프로필로 세션을 시작해 말을 보낸다 Then `pi --mode rpc --session-id <좌표>` 로 떠 답이 대화 탭에 온다. `/clear` 뒤에는 새 좌표로 다시 뜬다.
- Given 역할 `builder` 를 골랐다 When claude 세션을 시작한다 Then 인자에 `--add-dir <builder 폴더>` 가 붙고 자식 환경에 `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` 이 들어간다. pi 세션이면 `--append-system-prompt <builder>/CLAUDE.md` 가 붙는다.
- Given 앱으로 띄워 plugin PATH 에 `~/.local/bin` 이 없고 `claude` 가 거기에만 있다 When 기본 프로필로 세션을 시작한다 Then 로그인 셸 PATH 에서 찾은 절대 경로로 떠서 답한다(`No such file or directory` 가 나지 않는다).
- Given 탭 스트립 빈 곳 우클릭 When **새 에이전트 세션** 을 고른다 Then 그 pane 에 agent_session 탭이 생기고 시작 화면의 연결 탭이 열린다.
- Given 시작 화면에 세션이 여럿 있다 When 옆에 surface 를 열어 폭이 607px 로 준다 Then 문서의 가로 스크롤 폭이 창 폭과 같고, 세션 표는 자기 상자 안에서 가로로 스크롤한다.
- Given 에이전트 관리 탭 When 표의 삭제를 한 번 누른다 Then 아무것도 지워지지 않고 그 칸이 "삭제할까요?" 확인으로 바뀐다. 확인의 삭제를 누르면 그 에이전트가 지워지고 에이전트 관리 탭이 열린 채로 다시 그려진다.
- Given 에이전트 `cc` 가 있다 When 새 에이전트 폼에 이름 `cc` 로 만들기를 누른다 Then 프로필 파일은 그대로이고 에이전트 관리 탭 맨 위에 이미 있다는 실패 줄이 보이며 친 값이 폼에 남는다.
- Given 역할이 하나도 없다 When 연결 탭을 연다 Then 역할 칸에 "등록된 역할이 없습니다." 와 **역할 관리** 단추가 보이고, 단추를 누르면 역할 관리 탭으로 바뀐다.
- Given 턴이 끝난 뒤 백그라운드 작업이 남았다 When 정지 전 질의 · 유휴 회수가 세션을 본다 Then 바쁨으로 보고 내리지 않는다. 대화 입력은 그대로 보낸다.
- Given 프로필 `cache_ttl` 이 `1h` 인 탭 When `/clear` 뒤 4분을 쉰다 Then 회수하지 않고, 59분을 쉬면 내린다.
- Given 기준 미만의 5분 캐시 탭이 턴을 끝냈다 When 200초에 `add-dir` 을 한다 Then 240초에는 내리지 않고 440초에 내린다.
- Given 기준 이상의 5분 캐시 탭이 턴을 끝냈다 When 200초에 `add-dir` 을 한다 Then 240초에 `idle` 현행화를 열고, 회수는 440초가 지난 뒤에 한다.
- Given `traffic_on` 이 켜졌고 올림 한도가 200 KB/s 다 When 프록시를 거쳐 400 KB 를 올린다 Then 1.7초 이상 걸리고, 한도 0 이면 바로 끝난다. 내림 한도도 같은 방식으로 따로 걸린다.
- Given 프로필 `env` 에 `HTTPS_PROXY=http://user:pass@corp:3128` 이 있고 `traffic_on` 이 켜졌다 When claude 세션이 뜬다 Then 자식의 `HTTPS_PROXY` 는 loopback 프록시이고, 프록시는 `corp:3128` 에 `Proxy-Authorization` 을 실은 `CONNECT` 로 잇는다.
- Given `traffic_on` 이 꺼졌다 When 세션이 뜬다 Then 자식 환경의 `HTTPS_PROXY` 는 그대로다.

### UI 요소 인벤토리

- 시작 화면: 맨 위 세그먼트 컨트롤 셋 — **연결** · **에이전트 관리** · **역할 관리**. 평소에는 연결 탭이 열리고, 관리 조작의 결과가 있으면 그 결과의 탭이 열린다. 탭 전환은 문서를 다시 받지 않는다. 고른 탭은 webview 의 `sessionStorage` 에 남아, 열기 · 삭제로 문서가 다시 그려져도 유지된다.
- 글꼴 · 간격: 라벨 · 단추 · 제목은 시스템 글꼴(13px, 보조 글 12px), id · 경로 · 명령 · 환경 값만 고정폭이다. 간격은 4px 격자, 선은 1px 이다. 색 · 글꼴 · 간격은 문서 CSS 맨 위의 사용자 정의 속성에 모여 있다(Theme 연동은 아직 없다).
- 폼: 최대 폭 640px, 오른쪽 정렬 라벨과 입력칸의 두 열, 컨트롤 높이 28px. 긴 설명은 칸 아래 작은 회색 글이고 주 단추는 오른쪽 아래다. 폭 520px 이하에서는 라벨이 칸 위로 간다.
- 연결 탭: 에이전트(select · 종류로 묶음 · 하나만) · 작업 폴더와 **선택…** · 에이전트 옵션(접힌 묶음: 모델 별칭 · 직접 입력, 세션 이름, 이어받을 세션 ID, 권한 모드) · 시작 단추 · 세션 목록(검색 · 새로고침 · 표 · 선택 삭제). 폼 옆(폭 900px 미만이면 폼 아래)에 역할 표: 검색(이름 · 경로) · `{n}개 · 선택 {k}` · 표(고르기 · 이름 · 경로, 행 클릭도 고른다) · 쪽 넘김(한 쪽 8행). 여럿을 고르고, 쪽을 넘기거나 검색해도 고른 것은 남는다. 없으면 회색 안내와 역할 관리 단추.
- 표(세션 · 에이전트 · 역할 공용): 머리글 줄, 칸은 한 줄(넘치면 말줄임), 행 사이 옅은 선. 경로는 홈 폴더를 `~` 로 줄이고 칸 폭에 맞춰 가운데를 줄이며 전체 값은 툴팁이다. id 는 전체 값을 싣고 같은 방식으로 가운데를 줄인다. 빈 값은 회색 `—` 다. 행이 많으면 표 상자 안에서 세로로 스크롤한다(쪽 나눔 없음). 조작 칸은 맨 오른쪽 고정 폭이고 행에 마우스를 올리거나 행 안에 키보드 포커스가 있을 때 보인다(터치 화면은 늘 보인다).
- 세션 표: 전체 선택(머리글 체크 칸, 검색에 보이는 행만) · 상태(색 점 + 글: 실행 중 초록 · 재워짐 주황 · 중지됨 등 회색, 데몬의 `starting` · `finished` · `failed` · `blocked_precondition` 도 번역하고 모르는 값은 그대로) · 에이전트 · 폴더 · 변경(그 폴더 `spec/resume.md` 의 열린 질문 수 · 물음 응답 대기 · 미커밋 파일 수 · 마지막 활동, 폴더 값은 30초 캐시) · 세션 ID · 에이전트 세션(ID와 이름) · 탭(다른 탭이 쓰면 그 탭 번호, 이 탭이면 "이 탭") · 조작(이 탭에서 열기 · 삭제). 행을 누르면 고르기가 바뀐다. 실행 중인 세션은 고를 수 없고 삭제 단추가 흐리다. 다른 탭이 쓰는 세션에는 열기 단추가 없다.
- 폭: 옆에 surface 를 열어 폭이 줄어도 문서는 가로로 넘치지 않는다. 표는 자기 상자 안에서 가로로 스크롤한다.
- 대화 화면: 턴 기록 · 입력칸(Enter 보내기 · Shift+Enter 줄바꿈) · 중지 단추 · 물음 카드(허용 · 거절 · 선택지) · 에이전트 내역 패널 · 상태줄.
- 입력칸 이동 키: Home · End 는 커서가 있는 줄의 처음 · 끝, ⌘↑ · ⌘↓ 와 ⌘·Ctrl+Home · End 는 글 전체의 처음 · 끝이다. Shift 를 함께 누르면 선택을 늘린다. PageUp · PageDown 은 대화를 한 화면씩 넘긴다.
- 답 글의 링크: 답 · 실패 글의 URL(`https://` · `http://` · `ftp://` · `file://`)과 경로(`/a/b` · `~/a` · `./a` · `../a` · 확장자가 있는 상대 경로 `src/main.rs`, 뒤의 `:줄[:칸]` 포함)에 밑줄을 긋는다. 누르면 URL 은 호스트 `webview.open_external` 로 기본 브라우저에서, 경로는 작업 폴더 기준으로 풀어(`~` 는 홈) **있을 때만** 호스트 `file_handler.dispatch` 로 연다 — 폴더는 탐색기, 파일은 그 형식의 handler 다(터미널 링크와 같은 길). 없는 경로는 아무것도 하지 않는다. 글을 드래그해 고른 채 놓으면 열지 않는다. 링크는 글 노드를 나눠 짓고 원문 글자는 그대로라 복사한 글이 바뀌지 않는다.
- 입력칸 높이: 글에 맞춰 늘고 줄지만(CSS 최대 높이까지) 대화 로그가 보던 자리는 그대로다 — 높이를 바꾸기 전 로그 바닥까지의 거리를 재고 바꾼 뒤 같은 거리로 되돌린다. 바닥을 보던 사람은 입력하는 동안에도 마지막 줄을 본다.
- 에이전트 내역: 대화 로그 맨 위의 "에이전트 내역 (N)" 줄을 누르면 탭 오른쪽에 패널이 열린다(pane 을 나누지 않는다 · 읽기 전용). N 은 하위 에이전트와 백그라운드 작업 카드 수다. 범위는 마지막 `/clear` · `/compact` 이후다. 맨 위 **현재 에이전트** 카드는 메인 대화의 도구 호출 단계를, 그 아래 **하위 에이전트** 카드(지시 · 답 · 단계)와 **백그라운드 작업** 카드(종류 · 설명 · 상태: 도는 중 · 끝남 · 실패 · 멈춤)는 도는 것 먼저 · 최근 시작 먼저 놓인다. 단계 한 줄은 시각 · 성패 표지(✔ 성공 · ✖ 실패 · `·` 결과 없음) · 도구 이름 · 입력 요약(Bash 명령 · Read/Edit/Write 파일 경로 · Grep/Glob 패턴 · WebFetch 주소 · Agent 설명 등, 공백을 접은 한 줄 120자)이다. 성패는 `tool_result` 의 `is_error` 로 정한다. 카드마다 단계는 200개까지 두고 넘치면 오래된 것을 버리며 "앞 단계 N개 생략" 을 보인다 — 도구 결과 본문은 담지 않고, 대화 턴 한도(`memory_turns`)와 따로 센다.
  - 출처: 정본은 claude 의 대화 기록이다. 탭이 처음 읽을 때 메인 기록을 한 줄씩 끝까지 읽어(64KB 를 넘는 줄은 풀지 않는다 — 그 결과의 성패는 `·` 로 남는다) 마지막 `compact_boundary` 이후 단계만 남기고, 그 뒤로는 덧붙은 줄만 읽는다. 하위 에이전트는 기록 옆 `<대화 id>/subagents/agent-*.jsonl` · `.meta.json` 이고 마지막 경계보다 먼저 시작한 것은 뺀다. 백그라운드 작업은 기록에 없어 원문 `system/task_started` · `task_updated` · `task_notification` · `background_tasks_changed` 줄과, 처음 읽을 때 세션 행의 `background_tasks` 로 안다. 끝난 작업은 다음 경계까지 남는다. 하위 에이전트로 도는 작업(`local_agent`)은 하위 에이전트 카드로 보이므로 작업 카드로 겹쳐 싣지 않는다. `tell` 로 맡긴 다른 탭의 일은 그 탭의 내역이다.
  - 읽는 때: 원문 줄이 메인 도구 호출 · 결과, 하위 에이전트 줄, 경계, 작업 끝 알림, 턴 끝(`result`)일 때 표시만 해 두고 2초에 한 번으로 묶어 읽는다. 도는 하위 에이전트가 있으면 4초마다 읽는다. 패널의 ↻ 는 바로 읽는다. 읽은 결과가 같으면 화면을 바꾸지 않는다.
  - 범위 갱신: 기록에 새 `compact_boundary` 가 붙으면 그 앞의 단계 · 하위 에이전트 · 끝난 작업이 빠진다. `/clear`(탭의 비우기 · CLI `clear`)는 내역을 비우고 새 대화 id 의 기록으로 다시 시작한다. 도는 작업은 남는다.
  - 열림: 처음 보는 하위 에이전트가 생기면 패널이 열린다. 사람이 닫으면 다음 새 하위 에이전트까지 닫혀 있다.
  - IPC `agent_session.agent_log {surface_id}`: 그 탭의 내역을 다시 읽고 패널과 같은 값(`row` · `panel` 의 제목 · 수 · 카드 · 단계)을 돌려준다. 패널이 닫혀 있어도 답한다. claude 기록을 못 찾는 세션(pi 등)은 안내 글과 작업 카드만 싣는다.
- `/` 목록: 입력칸이 `/` 로 시작하면 뜬다(↑ · ↓ 고르기 · Tab 채우기 · Enter 채우거나 보내기 · Esc 닫기). 고정 커맨드 8개(`/add-dir` · `/clear` · `/compact` · `/context` · `/cost` · `/model` · `/reload-plugins` · `/reload-skills`) 뒤에 그 세션의 스킬이 회색 "스킬" 꼬리표와 설명(한 줄 · 120자)으로 붙는다. 스킬은 claude 가 읽는 자리를 파일로 훑어 찾는다 — 사용자(`<설정 폴더>/skills`) · 켜진 플러그인(`installed_plugins.json` 의 설치 폴더 중 `settings.json` `enabledPlugins` 가 켠 것, 이름 `<플러그인>:<스킬>`) · 프로젝트(작업 폴더와 그 모든 상위 · 추가 폴더 각각의 Claude Code 프로젝트 스킬 폴더). 이름은 앞머리 `name`, 없으면 폴더 이름이다. 앞머리 `user-invocable: false` 는 claude 처럼 뺀다. 내장 커맨드(`/init` 등)와 디스크에 없는 내장 번들 스킬은 싣지 않는다. 같은 이름은 고정 커맨드 → 사용자 → 프로젝트 → 플러그인 순으로 하나만 둔다. 훑기는 탭이 세션에 붙은 뒤 첫 문서를 지을 때 그 자리에서 한 번 한다(세션 연결 · 탭 복원마다, 실측 2.3~11ms · 스킬 11개). 작업 스레드에 맡기면 결과가 막 갈아 끼우는 문서보다 먼저 닿아 사라진다. `/reload-skills` · `/reload-plugins` · `/add-dir` 가 끝나면 작업 스레드가 다시 훑어 문서를 다시 싣지 않고 `{type:"commands", items}` 메시지로 목록을 바꾼다(입력 중 글 유지). 작업 폴더는 자식을 띄울 때와 같이 세션 → 프로필 → 홈 순서로, 추가 폴더는 세션 것과 프로필 것을 함께 본다. claude 의 `system/init` 은 첫 입력 뒤에 와서 연결 시점 목록에 쓸 수 없다. pi 세션은 `/add-dir` · `/clear` · `/compact` 만 보인다.
- 우클릭 메뉴: 시작 화면과 대화 화면의 우클릭은 WebKit 기본 메뉴 대신 host 네이티브 메뉴 "터미널 ID 복사" 를 연다 — 고르면 이 탭의 surface id 가 클립보드에 들어가고, 우클릭한 자리에 "복사함" 이 1.5초 뜬다(host 토스트는 페이지를 가려 쓰지 않는다). 고른 글이 있거나 입력칸 안이면 복사 · 붙여넣기를 위해 기본 메뉴를 둔다. 페이지가 우클릭 위치를 fragment 로 plugin 에 넘기고 plugin 이 `webview.context_menu` 를 부른다([컨텍스트 메뉴 구현](../../dev-guide/context-menu.md)).
- 상태줄 복사: 작업 폴더 · 대화 id(`sess:`, 접은 줄은 `종류(id)` 의 id) · surface id 를 누르면 호스트 클립보드(`clipboard.set_text`)에 전체 값이 들어간다. 작업 폴더는 줄여 보여도 전체 경로를, 대화 id 는 claude 의 대화 id(없으면 이 탭의 supervisor id)를 복사한다. 누른 칸 옆에 1.5초 동안 "복사함" 이 보인다. webview 의 `navigator.clipboard` 는 쓰지 않는다.
- 상태줄 유휴 시계: 두 시계가 **만료 예정 시각**(`HH:MM:ss`, webview 의 지역 시간대)을 보인다 — 편 줄은 셋째 줄 끝, 접은 줄은 `작업 폴더 · 프로필(계정) · 종류(대화 id)` 뒤. `cache:` 는 API 를 부른 마지막 턴 끝에서 프롬프트 캐시 수명(관측값 > 프로필 `cache_ttl` > 5분)이 지나는 시각, `rest:` 는 마지막으로 손댄 때(말 · 탭 조작 · 세션을 겨눈 명령)에서 유휴 회수에 이르는 시각이다. `rest:` 는 유휴 회수가 켜졌고 세션이 회수되지 않았을 때만 있다. plugin 은 기한(유닉스 초)만 싣고 페이지가 시각으로 그린다. 60초 안이면 노란색이고, 지나면 `cache:` 는 빨간 `(만료)`, `rest:` 는 노란 `(회수 대기)` 가 시각 뒤에 붙는다 — 색이 시간에 따라 바뀌므로 페이지가 1초마다 다시 그린다. 턴이 도는 동안에는 두 시계를 싣지 않는다. 휴식 시계를 미는 탭 조작 · 명령은 상태줄을 다시 그리지 않으므로 판정 고리(`flush_queues`)가 기한을 견주어 바뀐 탭만 다시 그린다.
- 턴 시각: 날짜가 바뀌는 자리에 `───[YYYY-MM-DD]───` 구분선(양쪽 선이 폭을 채운다)이 들어가고, 그 아래 턴마다 보낸 말 앞에 `[HH:MM:ss]` 가 붙는다. 시각은 턴이 열린 때이고 webview 의 지역 시간대로 그린다. 이어받은 대화는 기록의 사람 글 시각을 쓰며, 시각을 모르는 턴(시각이 없던 스냅샷)에는 붙이지 않는다.
