# 첫 화면 둘러보기

사이드바에서 워크스페이스를 고르고, 작업 영역에서 터미널을 사용합니다. 페인마다 탭 바가 있고, 각 탭 안에는 터미널이나 문서를 표시하는 서피스가 있습니다.

## 화면 위에서 직접 익히기

사이드바의 **도구** <!-- en: Tools --> > **튜토리얼…** <!-- en: Tutorial… --> 에서 화면 구조와 분할을 직접 익힐 수 있습니다.

분할 실습은 새 연습 워크스페이스에서 진행합니다. 작업 영역을 클릭한 뒤 표시된 단축키나 메뉴를 사용하세요. 동작이 확인되면 **다음**을 누릅니다. 연습 공간은 완료 후에도 남으므로 계속 쓰거나 직접 닫을 수 있습니다.

**목록** 또는 `Esc`로 중단하고 나중에 **이어하기**를 선택할 수 있습니다. 완료와 진행 위치는 앱을 다시 열어도 기억합니다. 분할 실습은 이어할 때 새 연습 공간을 만듭니다. 단축키 안내는 현재 설정을 따릅니다.

## 네 가지 용어 — 워크스페이스 · 페인 · 탭 · 서피스

Tasty 의 화면은 이 순서로 포함 관계를 이룹니다. 각 부분을 화면에서 확인하려면 사이드바의 **도구** <!-- en: Tools --> > **튜토리얼…** <!-- en: Tutorial… --> 을 열어 화면 위에 직접 표시되는 안내를 따라가면 됩니다.

| 용어 | 뜻 | 비슷한 개념 |
|------|----|------------|
| **워크스페이스** <!-- en: Workspace --> | 탭 · 페인 · 서피스를 전부 담는 가장 큰 단위. 사이드바에서 전환합니다 | tmux 의 session, iTerm2 의 window |
| **페인** <!-- en: Pane --> | 워크스페이스를 물리적으로 나눈 칸. 칸마다 **자기 탭 스트립**을 가집니다 | tmux · iTerm2 에는 없는 Tasty 고유 개념 |
| **탭** <!-- en: Tab --> | 페인 안의 탭 하나 | tmux 의 window, iTerm2 의 tab |
| **서피스** <!-- en: Surface --> | 실제로 터미널 · 마크다운 · 탐색기가 그려지는 면. 탭 하나 안에서 여러 개로 분할할 수 있습니다 | tmux · iTerm2 의 pane |

**분할이 두 단계**라는 점이 Tasty 의 특징입니다.

- **페인 분할** — 워크스페이스를 좌우 · 상하로 나눕니다. 어느 페인에서 탭을 바꿔도 다른 페인은 그대로입니다. 예: 왼쪽 페인은 Claude Code 전용, 오른쪽 페인은 로그 · 빌드 탭 여러 개.
- **서피스 분할** — 탭 하나 안을 나눕니다. 탭을 바꾸면 그 분할 전체가 함께 바뀝니다.

자세한 조작은 [페인 · 탭 · 분할](../using/panes-tabs-splits.md).

## 윈도우의 구성

<!-- tasty-diagram: window-anatomy -->
```
┌─────────────────────────────────────────────────┐
│ 타이틀바                                        │
├──────────┬──────────────────────────────────────┤
│          │ 탭 스트립                            │
│ 사이드바 ├──────────────────────────────────────┤
│          │ 작업 영역 (페인 · 탭 · 서피스)       │
│          ├──────────────────────────────────────┤
│          │ 상태바                               │
└──────────┴──────────────────────────────────────┘
```

- **타이틀바** — 윈도우를 끌어 옮기고, 더블클릭으로 최대화합니다. Linux · Windows 는 Tasty 가 최소화 · 최대화 · 닫기 버튼을 직접 그리고, macOS 는 왼쪽 신호등 버튼을 그대로 씁니다.
- **사이드바** — 워크스페이스 목록과 도구 · 플러그인 · 설정 진입점.
- **작업 영역** — 터미널과 문서를 배치하는 곳. 아래 네 가지 구성 요소로 나뉩니다.
- **상태바** — 현재 터미널의 상태와 빠른 버튼.

## 사이드바

위에서부터 세 영역입니다.

- **헤더** — `tasty.` 워드마크와 **접기** <!-- en: Collapse --> 버튼. 접으면 아이콘만 남는 좁은 레일이 됩니다.
- **워크스페이스** <!-- en: WORKSPACES --> 목록 — 카드를 클릭하면 전환, 드래그하면 순서 변경. 맨 아래 **새 워크스페이스** <!-- en: New workspace --> 버튼으로 추가합니다. 이 버튼을 우클릭하면 **프리셋으로 새 워크스페이스 생성...** <!-- en: Create workspace from preset... --> 과 **원격 워크스페이스 추가** <!-- en: Add remote workspace --> 가 나옵니다. 카드 우측의 숫자 배지는 두 종류입니다. 노란 배지는 입력을 기다리는 서피스 수, 파란 배지는 작업이 끝났거나 알림이 온 서피스 수입니다. 둘 다 있으면 노란 배지가 왼쪽에 옵니다.
- **하단 버튼** — **도구** <!-- en: Tools --> (**명령 팔레트…** <!-- en: Command palette… --> · **연결 대기 중인 포트…** <!-- en: Listening ports… --> · **원격 접속…** <!-- en: Remote connections… --> · **프리셋** <!-- en: Presets --> · **튜토리얼…** <!-- en: Tutorial… --> · **작업 DAG** <!-- en: Task DAGs --> · **파일 열기…** <!-- en: Open File… --> 순서이고, 그 아래 구분선 뒤에 플러그인이 추가한 항목), **플러그인** <!-- en: Plugins --> (설치 · 활성화 관리 윈도우), **설정** <!-- en: Settings --> (설정 윈도우).

워크스페이스가 많아지면 **설정** > **일반** <!-- en: General --> > **워크스페이스 카테고리(폴더)** <!-- en: Workspace categories (folders) --> 를 켜서 폴더처럼 묶을 수 있습니다. 자세한 내용은 [워크스페이스](../using/workspaces.md).

## 탭 스트립

각 페인의 맨 위에 있습니다.

- 탭마다 종류 아이콘(터미널 · 마크다운 등)과 이름이 보입니다. 이름은 직접 지정한 이름 → 프로그램이 정한 터미널 제목 → 셸의 현재 디렉터리 이름 → 기본 이름 순으로 정해집니다. 우클릭 > **탭 이름 변경** <!-- en: Rename Tab --> 으로 이름을 지정하면 다른 이름으로 바뀌지 않습니다.
- 프로그램이 출력을 내는 중이면 **녹색 점**이 붙고, 입력을 기다리거나 작업이 끝나면 이름 색이 바뀝니다 ([이름과 표시](../using/panes-tabs-splits.md#이름과-표시)).
- `+` 는 새 탭. 우클릭하면 프리셋으로 만듭니다. 그 옆의 분할 · 검색 아이콘은 이 페인을 나누거나 현재 서피스 안을 검색합니다.
- 탭이 넘치면 좌우 화살표가 나타납니다. 드래그로 순서를 바꿉니다.
- 빈 곳을 우클릭하면 **새 터미널** <!-- en: New Terminal --> · **새 마크다운...** <!-- en: New Markdown... --> · **새 HTML...** <!-- en: New HTML... --> · **새 이미지** <!-- en: New Image --> 로 새 탭을 만들 수 있습니다. **새 HTML...** 은 파일 선택 창에서 HTML · SVG 파일을 고르면 그 페인에 탭을 엽니다. 같은 메뉴에서 **페인 프리셋으로 저장** <!-- en: Save as pane preset --> 과 **프리셋으로 탭 생성...** <!-- en: Create tab from preset... --> · **프리셋으로 페인 생성...** <!-- en: Create pane from preset... --> 도 고를 수 있습니다. 종류별 설명은 [파일 관리와 보기](../using/files.md).

페인의 마지막 남은 탭 하나는 탭 닫기로 닫히지 않습니다. 서피스 닫기는 다릅니다. 탭에 남은 마지막 서피스를 닫으면 그 탭이 닫히고, 그 탭이 페인의 마지막 탭이면 페인이, 그 페인이 워크스페이스의 마지막 페인이면 워크스페이스까지 함께 닫힙니다.

<summary>상태바</summary>

작업 영역 맨 아래 한 줄입니다. 왼쪽은 현재 포커스된 서피스의 정보, 오른쪽은 버튼입니다.

- **git 브랜치** — 셸의 현재 디렉터리가 git 저장소면 가지 아이콘과 브랜치 이름. 최대 1초 늦게 반영됩니다. 저장소가 아니면 이 항목이 **아예 없습니다**. 특정 커밋을 직접 보고 있으면(detached HEAD) 이름 대신 `@` 와 짧은 커밋 번호가 나옵니다.
- **서피스 ID** — `s3·p1` 처럼 서피스 번호와 그 서피스가 든 페인 번호입니다. 앞의 숫자가 `tasty` CLI 로 이 터미널을 지정할 때 쓰는 값입니다([tasty CLI](../agents/cli.md)).
- **셸** — 실행 중인 프로그램 이름.
- **격자 크기** — `열×행`.
- **팔레트 단축키** — 키 모양으로 표시됩니다. 클릭하면 명령 팔레트가 열리고, 표시되는 키는 설정을 따라갑니다. 단축키를 비워 두면 이 항목도 사라집니다.
- **테마 아이콘** — 클릭할 때마다 밝은 테마(latte)와 어두운 테마(mocha)를 오갑니다. 아이콘 모양이 지금 어느 쪽인지 알려 줍니다 — 밝은 테마면 해.

**값이 없는 항목은 자리를 비워 두지 않고 사라집니다.** 윈도우가 좁아지면 격자 크기 → 셸 → 서피스 ID → 팔레트 단축키 → 브랜치 이름 순으로 차례로 숨고, 테마 아이콘은 끝까지 남습니다.

## 처음 알아둘 단축키

기본 프리셋(**Tasty**)의 값입니다. 표기의 `Alt` 는 macOS 에서 `Cmd(⌘)`, `Ctrl` 은 `Control(⌃)` 입니다. 바꾸는 방법과 전체 표는 [단축키](../customize/keybindings.md).

| 하는 일 | Windows · Linux | macOS |
|---------|-----------------|-------|
| 새 워크스페이스 | `Alt+N` | `Cmd+N` |
| 새 탭 | `Alt+T` | `Cmd+T` |
| 페인 분할 (좌우 / 상하) | `Alt+E` / `Alt+Shift+E` | `Cmd+E` / `Cmd+Shift+E` |
| 서피스 분할 (좌우 / 상하) | `Alt+D` / `Alt+Shift+D` | `Cmd+D` / `Cmd+Shift+D` |
| 명령 팔레트 | `Ctrl+Shift+P` | `Ctrl+Shift+P` |
| 설정 | `Ctrl+,` | `Ctrl+,` |

macOS 에서 iTerm2 식 `⌘` 중심 조합을 원하면 **설정** > **단축키** <!-- en: Keybindings --> 에서 **Mac** 프리셋을 고릅니다.

## 윈도우를 닫으면

윈도우가 여러 개면 닫기 버튼을 누른 윈도우만 닫힙니다. 마지막 남은 윈도우의 닫기 버튼을 누르면 **종료** <!-- en: Quit --> 할지 **최소화** <!-- en: Minimize --> 할지 묻습니다. 최소화를 고르면 Tasty 는 시스템 트레이(메뉴 막대)로 들어가고, 트레이 아이콘 메뉴의 **윈도우 표시** <!-- en: Show Window --> 로 돌아옵니다. 매번 묻지 않게 하려면 **설정** > **일반** > **종료 동작** <!-- en: Close behavior --> 을 바꿉니다.

종료를 확정하면 모든 윈도우의 웹 페이지와 마크다운 문서가 가려지고, 종료 대기가 있으면 진행 화면이 표시됩니다. 종료 확인을 취소하거나 백그라운드로 최소화했다가 돌아오면 문서를 계속 사용할 수 있습니다.

다시 실행할 때 배치와 터미널 기록을 [복원](../using/workspaces.md#재시작-후-복원)할 수 있습니다. 실행 중이던 프로그램의 복원과는 다르며, 설정과 프로그램별 세션 재개 지원에 따라 달라집니다.
