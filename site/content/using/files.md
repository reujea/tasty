# 파일 관리와 보기

탐색기에서 파일을 찾고 관리하며, 터미널 옆에서 마크다운·이미지·HTML을 볼 수 있습니다. Git 보기에서는 변경 사항을 확인합니다. 뷰어와 Git 보기는 해당 플러그인이 켜져 있어야 합니다.

## 여는 방법

| 어디서 | 어떻게 |
|--------|--------|
| 사이드바 **도구** <!-- en: Tools --> > **파일 열기…** <!-- en: Open File… --> | Tasty 자체 파일 선택 창. 지금 보고 있는 터미널·탐색기의 폴더에서 열리고, 원격 워크스페이스에서는 원격 파일을 보여주며, 고른 원격 파일은 그 원격 워크스페이스에 열립니다 |
| 파일을 윈도우 위로 드래그 | **여기에 드롭하여 열기** <!-- en: Drop to open --> 가 뜨면 놓습니다. 탐색기 칸 위에 놓으면 열지 않고 그 폴더로 복사합니다 ([끌어서 옮기기](#끌어서-옮기기)) |
| 탐색기 서피스 | 파일 더블클릭 |
| 터미널 | `Ctrl+클릭`, 또는 경로를 선택하고 우클릭 > **파일 열기** <!-- en: Open File --> ([터미널 다루기](terminal.md#링크와-경로-열기)) |
| 탭 스트립 빈 곳 우클릭 | **새 마크다운...** <!-- en: New Markdown... --> · **새 탐색기** <!-- en: New Explorer --> · **새 HTML...** <!-- en: New HTML... --> · **새 이미지** <!-- en: New Image --> |
| `Alt+'` | 현재 서피스를 다른 종류로 바꿉니다 ([종류 바꾸기](panes-tabs-splits.md#종류-바꾸기)) |
| CLI | `tasty new tab --pane 1 --type markdown --file README.md` 등 |

파일 확장자에 따라 어떤 서피스로 열지가 정해집니다 — `.md` 는 마크다운, 이미지 파일은 이미지, `.html` 과 `.svg` 는 HTML, 폴더는 탐색기. 어느 것으로 열지 정해지지 않으면 **다음으로 열기…** <!-- en: Open file with… --> 창이 떠서 고르게 하고, 고른 것은 **최근 선택** <!-- en: Recent --> 에 남습니다. 확장자 매핑과 핸들러는 **설정** > **핸들러** <!-- en: Handler --> 탭에서 바꿉니다.

핸들러 탭의 파일 형식·연결 설정은 **저장**을 누르면 바로 적용되고 파일에는 백그라운드에서 저장됩니다. 저장하지 못하면 경고와 알림에 원인이 나오며, 변경은 Tasty를 끌 때까지만 유지됩니다. 외부에서 편집했거나 손상된 원본은 덮어쓰지 않으므로, 파일을 확인하고 Tasty를 다시 시작한 뒤 다시 변경하세요. 시작할 때 이 설정을 읽지 못하면 로그에 파일명과 문제 종류가 남으며, 파일 내용은 기록하지 않습니다.

**다음으로 열기…** 창에는 파일 경로, 인식한 형식, 선택할 수 있는 핸들러가 표시됩니다. 핸들러마다 아이콘, 이름, 출처(**기본 제공** <!-- en: built-in --> · **직접 등록** <!-- en: you --> · **plugin**)가 보입니다.

**최근 선택**에는 전에 쓴 핸들러와 사용 시점이 표시됩니다. 방금 · 몇 분 전 · 몇 시간 전 · 어제 · 며칠 전으로 표시하다가, 일주일이 넘으면 `2026-09-13`처럼 날짜로 바뀝니다. 창을 열어 둔 채 자정을 넘겨도 표시가 갱신됩니다.

한 번 누르면 핸들러를 선택하고, 두 번 누르면 파일을 엽니다. 이 선택은 **이번 한 번만** 적용되며 파일 형식의 기본 핸들러로 등록되지 않습니다. 같은 파일을 다시 열 때 선택 창이 나올 수 있습니다. 기본 핸들러는 **설정** > **핸들러**에서 정하세요. 창은 `Esc`나 **취소** <!-- en: Cancel --> 로 닫습니다.

위의 방법으로 직접 연 파일은 새 탭으로 열리면서 **그 탭으로 바뀝니다.** AI 에이전트가 대신 열어 줄 때는 탭만 늘고 보고 있던 탭은 그대로 남습니다 — 작업하던 화면이 갑자기 바뀌지 않게 하기 위해서입니다.

열기를 요청한 서피스가 지정되어 있으면, 기다리는 동안 다른 윈도우로 이동해도 원래 서피스의 페인에 새 탭으로 열립니다. 다른 페인을 보고 있을 때 탐색기에서 파일을 열어도 탐색기가 있는 페인에 열립니다. 원래 서피스를 닫으면 다른 윈도우에 대신 열지 않습니다.

파일로 연 서피스는 다른 서피스와 똑같이 분할 · 이동 · 닫기 · 재시작 복원의 대상입니다. 탭 이름은 파일명이 됩니다.

파일 선택 창은 맨 위 한 줄(제목과 ✕가 있는 줄)을 끌어 옮깁니다. ✕, **취소** <!-- en: Cancel -->, `Esc` 중 하나로 닫으면 아무 파일도 열지 않습니다.

파일 선택 창의 목록 위에는 이름·크기·수정일 열 이름이 있고, 고른 행은 왼쪽 끝에 색 막대가 붙습니다. 긴 파일명은 `…`로 줄여 크기·수정일과 겹치지 않게 표시합니다. 줄여 표시해도 선택하거나 여는 파일은 바뀌지 않습니다.

파일 종류를 정해 두고 열었다면(예: 단축키 가져오기는 `.toml` 만) 이름 칸 오른쪽에 `*.toml` 처럼 보여 줄 확장자를 적은 칸이 있습니다. 확장자가 많으면 끝이 `…` 로 줄고, 마우스를 올리면 전체 목록이 보입니다. 이 칸은 안내일 뿐 눌러서 바꿀 수는 없습니다. 종류를 정하지 않고 열었다면 이 칸이 없습니다.

목록에서 한 번 누르면 파일이든 폴더든 그 줄이 선택되고, 두 번 누르면 폴더는 그 안으로 들어가고 파일은 열립니다. 폴더를 선택한 채 **열기** <!-- en: Open --> 를 누르면 그 폴더로 들어갑니다 — 키보드로 내려가는 길입니다. 저장할 위치를 고를 때는 폴더가 저장 대상이 될 수 없으므로, 폴더를 선택하면 이름 칸은 그대로 두고 아래에 그 사실을 알리는 회색 줄이 한 줄 뜹니다. 저장할 때 파일을 두 번 눌렀을 때는 이름만 채워지고 저장되지는 않습니다 — 덮어쓰기 경고를 읽을 기회를 남기기 위해서입니다.

파일 선택이 진행 중이면 새 선택 요청은 안내와 함께 거절됩니다. 기존 파일 선택 창에서 선택을 마치거나 취소한 뒤 다시 여세요.

## 탐색기

Tasty 안에 들어 있는 파일 관리자입니다. 터미널에서 `Alt+'` > **탐색기** 로 바꾸면 그 터미널의 현재 디렉터리를 루트로 엽니다. `tasty new tab --pane 1 --type explorer --path ~/proj` 로도 엽니다. `--path` 대신 `--cwd ~/proj` 를 주어도 그 폴더를 루트로 엽니다.

### 화면

- **왼쪽** — **파일** <!-- en: Files --> 트리(루트 고정)와 그 아래 **즐겨찾기** <!-- en: Favorites -->.
- **위쪽** — **뒤로** <!-- en: Back --> · **앞으로** <!-- en: Forward --> · **위로** <!-- en: Up --> · **새로고침** <!-- en: Refresh -->, 주소창, **새 폴더** <!-- en: New folder --> · **새 파일** <!-- en: New file --> 버튼과 **찾기** <!-- en: Find --> · **미리보기 패널** <!-- en: Preview panel --> · 숨김 파일(눈 모양) 토글, 보기 전환(**그리드** <!-- en: Grid --> · **목록** <!-- en: List --> · **상세** <!-- en: Detail -->). 탐색기 칸이 440px 보다 좁으면 명령 버튼이 **더 보기** <!-- en: More --> (`…`) 하나로 접히고, 누르면 같은 명령이 메뉴로 나옵니다. 메뉴의 찾기·미리보기 줄은 누르면 할 일을 씁니다(**찾기** ↔ **찾기 닫기** <!-- en: Close find -->, **미리보기 표시** <!-- en: Show preview --> ↔ **미리보기 숨기기** <!-- en: Hide preview -->, **숨김 파일 보기** <!-- en: Show hidden files --> ↔ **숨김 파일 숨기기** <!-- en: Hide hidden files -->). 숨김 파일 토글은 숨김 파일을 보이는 동안 눌린 모양이고, 마우스를 올리면 할 일과 단축키가 함께 보입니다(예: **숨김 파일 보기 (Ctrl+Shift+.)**).
- **오른쪽** — 현재 폴더의 항목. 그리드 보기에서는 로컬 이미지 파일(1 MiB 이하)이 아이콘 대신 작은 썸네일로 보입니다. 맨 위 `..` 로 상위 폴더에 갑니다. 상세 보기에서는 **이름** · **크기** · **수정일** · **형식** 열 제목을 클릭해 정렬합니다. 형식 열에는 "Markdown", "PDF 문서", "압축 파일", "PNG 이미지" 처럼 종류가 낱말로 나오고(표에 없는 형식은 "RS 파일"), 링크는 "Markdown 링크"처럼 가리키는 대상의 종류를 씁니다. 속성 팝업과 미리보기 머리도 같은 낱말을 쓰고, 형식으로 정렬하면 같은 종류끼리 붙어 .gz 와 .zip 같은 압축 파일이 나란히 놓입니다.
- 서피스 안에 **새 탭** <!-- en: New tab --> 을 여러 개 두고 폴더를 따로따로 볼 수 있습니다. 페인의 탭과는 별개입니다.

내부 탭을 오갔다 돌아오면 선택한 항목, 목록과 왼쪽 파일 트리의 스크롤 위치, 찾기 바의 검색어·하위 폴더 검색 결과가 그대로 남습니다. 같은 폴더를 연 두 탭도 각각 기억합니다. 다른 탭을 보는 동안 끝난 읽기와 검색은 시작한 탭에만 반영됩니다. 탭을 닫으면 이 상태를 버리며, 앱을 다시 열 때는 폴더·보기·정렬만 복원하고 선택과 찾기는 새로 시작합니다.

원격 탐색기도 같은 연결에서 서버의 폴더가 바뀌지 않았다면 작업 영역 갱신 뒤 내부 탭과 탐색 위치를 유지합니다. 서버가 폴더를 바꾸거나 연결을 새로 맺으면 서버가 알린 폴더의 새 탭으로 시작합니다.

탐색기가 든 배치를 프리셋으로 저장했다가 적용하면, 탐색기 안의 탭마다 보던 폴더와 보기·정렬이 그대로 열리고, 페인 탭 제목은 활성 탭이 연 폴더(루트) 이름입니다. 프리셋 편집에서 작업 디렉터리를 정해 두었으면 저장한 탭 대신 그 폴더 하나로 엽니다. 저장한 폴더가 지금은 없으면 그 탭에 읽기 오류 안내가 나옵니다.

분할선을 끌어 탐색기 칸을 줄이면 툴바·상태줄과 목록 두어 줄이 남는 높이(180px)에서 멈춥니다. 탐색기 칸을 나누거나 탐색기를 새로 나눠 만들 때도 탐색기 칸이 180px 을 지키도록 분할선이 한쪽으로 옮겨집니다. 다른 종류의 칸은 남는 높이를 받지만, 탭 줄과 한 줄이 들어가는 높이(56px)보다 얇게 나뉘지는 않습니다. 탐색기 칸끼리 180px 을 지킬 공간이 없거나 다른 칸이 56px 을 지킬 공간이 없으면 분할하지 않고, 분할 메뉴·단축키에서는 "이 패널을 나눌 공간이 부족합니다" 알림이 잠깐 뜨며 `tasty split` 은 그 이유를 오류로 알려 줍니다. 칸이 낮아 왼쪽 사이드바가 240px 보다 낮아지면 즐겨찾기는 숨고 파일 트리만 보입니다. 윈도우 크기를 줄이면 이 높이 아래로도 내려갈 수 있습니다. 내용 영역이 120px 보다 낮으면 빈 폴더·권한 거부·읽기 오류 안내가 아이콘 · 제목 · 버튼 한 줄로 바뀌고, 자세한 이유는 제목에 마우스를 올리면 보입니다.

폴더를 읽지 못하면(경로가 사라졌거나 폴더가 아니거나 원격 읽기가 실패한 경우) 목록 자리에 **이 폴더를 읽을 수 없습니다** <!-- en: Can't read this folder --> 와 운영체제가 알려 준 이유가 나옵니다. **다시 시도** <!-- en: Retry --> 는 같은 폴더를 다시 읽고, **상위 폴더로** <!-- en: Go up --> 는 한 단계 위 폴더로 갑니다. 위 폴더도 함께 사라졌으면 남아 있는 가장 가까운 위 폴더로 갑니다. 권한이 없을 때는 따로 **접근 거부** <!-- en: Permission denied --> 가 나옵니다.

탐색기에서 붙여넣기 · 이름 변경 · 휴지통으로 보내기를 하면, 바뀐 폴더를 보고 있는 다른 탐색기도 (다른 윈도우여도) 목록과 왼쪽 트리를 다시 읽습니다. 지금 보던 폴더가 지워졌거나 이름이 바뀌었으면 그 자리에서 읽기 오류 안내가 나오고, 다른 폴더로 저절로 옮겨 가지는 않습니다. 다른 프로그램이 폴더에 항목을 만들거나 지우거나 이름을 바꾸면, 지금 쓰고 있는 Tasty 윈도우에서 포커스가 있는 탭의 탐색기가 2 초 안에 알아채 목록과 펼쳐 둔 트리를 다시 읽습니다. 이때 선택과 스크롤 위치는 그대로입니다. 다른 탭에 있던 탐색기나 다른 앱을 쓰는 동안의 탐색기는 그 탭이나 Tasty 윈도우로 돌아오는 순간 확인합니다. 파일 내용이나 크기, 권한만 바뀐 경우와 원격(attach) 탐색기는 자동으로 반영되지 않으니 **새로고침** (`F5`) 을 누르세요. 열린 폴더 안 파일의 크기·수정 시각 변경까지 자동으로 맞추려면 **설정** <!-- en: Settings --> > **일반** <!-- en: General --> > **탐색기: 파일 정보 자동 갱신** <!-- en: Explorer: refresh file details --> 을 켭니다. 켜면 크기·날짜 열과 미리보기 · 썸네일이 몇 초 안에 새 값으로 바뀌지만, 확인할 때마다 그 폴더의 항목을 모두 읽으므로 느린 드라이브나 항목이 아주 많은 폴더에서는 꺼 두는 편이 낫습니다. 기본은 꺼짐이고, 펼쳐 둔 트리 폴더 안 파일은 켜도 확인하지 않습니다. 트리를 아주 많이 펼쳐 두면 한 번에 모두 확인하지 않고 몇 차례에 나눠 돌아가며 확인하므로, 깊은 폴더의 변경은 조금 늦게 보일 수 있습니다. 새로고침은 펼쳐 둔 트리도 함께 다시 읽습니다. 로컬 탐색기가 폴더 목록을 보이고 있을 때는 목록을 비우지 않아 선택과 스크롤 위치가 그대로입니다. 원격(attach) 탐색기, 오류 안내의 **다시 시도**, 읽는 중에 누른 새로고침은 목록을 비우고 처음부터 다시 읽습니다. 다시 읽었을 때 선택해 둔 항목이 사라졌으면 그 항목은 선택에서도 빠집니다.

주소창을 클릭하면 경로를 직접 입력할 수 있고, 최근 방문한 폴더가 자동완성으로 뜹니다. 후보를 클릭하거나 방향키로 고른 뒤 `Enter`를 누르면 그 폴더로 이동합니다. `Enter` 또는 **이동** <!-- en: Go --> 으로 갑니다. 왼쪽 트리는 루트에 고정되지만 오른쪽 목록은 어디로든 갈 수 있습니다. 파일 경로를 입력하면 파일을 열지 않고 그 파일이 든 폴더로 가서 그 파일을 골라 둡니다. 원격 탐색기도 같습니다.

자모나 악센트가 분리되어 저장된 이름은 화면에서 합쳐 보여 줍니다. 이렇게 표시하던 주소를 편집하면 원래 경로 전체가 선택됩니다. 같은 모양의 파일이 둘 있어도 복사와 이동에는 각각의 실제 이름을 그대로 씁니다.

- 상대 경로는 지금 보고 있는 폴더 기준입니다. `..` 은 한 단계 위입니다.
- `~` 와 `~/폴더` 는 홈 폴더 아래입니다.
- Windows 에서는 `C:` 처럼 드라이브만 적으면 그 드라이브의 맨 위로 가고, `\\서버\공유` 같은 네트워크 경로도 쓸 수 있습니다.
- 없는 경로를 입력하면 이동하지 않고 이유를 알림으로 보여 줍니다. 대상이 사라진 링크는 파일처럼 그 링크가 든 폴더로 가서 링크를 골라 둡니다.
- 원격 워크스페이스의 탐색기에서는 입력한 경로를 원격 컴퓨터에서 찾습니다. 로컬에 없는 폴더도 원격에 있으면 열리고, 원격에서 읽지 못하면 목록 자리에 이유가 나옵니다. `~` 는 원격 컴퓨터의 홈 폴더이고, `.` 과 `..` 도 원격 경로 기준으로 풉니다. 연결한 직후 원격 홈을 아직 알아내지 못했으면 `~` 대신 원격 경로를 전부 적으라고 알려 줍니다. 원격 경로가 파일인지 확인하는 동안 주소창은 입력한 경로를 그대로 보이고, 확인이 길어지면 주소창 끝에 도는 표시가 나옵니다. 이때 `Esc` 를 누르면 확인을 그만두고 주소창이 지금 폴더로 돌아갑니다.

Linux X11에서는 한글 등을 조합하는 동안 목록 이동·열기·선택 해제·이름 변경·휴지통 키를 누르면 조합을 먼저 처리합니다. 같은 누름으로 파일을 옮기거나 열지 않습니다. 조합이 끝난 뒤 다시 누른 키는 평소처럼 동작합니다. 찾기 입력칸에서도 조합을 끝내는 `Esc`는 검색어를 지우지 않으며, 다음 `Esc`부터 평소대로 동작합니다. 탐색기 항목의 이름 변경 팝업에서는 조합을 끝내는 `Enter`가 글자만 확정하고 팝업은 열어 둡니다. 이름을 바꾸려면 `Enter`를 한 번 더 누르거나 **저장** <!-- en: Save --> 버튼을 누르세요. 찾기의 다른 키와 경로 입력칸에는 해당 입력칸의 키 처리가 적용됩니다.

Linux 네이티브 Wayland에서는 한글 조합을 끝내는 키가 목록 동작이나 찾기의 검색어 지우기로 이어지는 문제가 남아 있습니다. 이름 변경은 입력칸에서 `Enter` 또는 **저장** <!-- en: Save --> 버튼으로 확정하고, `Esc`로 취소합니다. 앱이 처음 열린 뒤에도 다른 윈도우로 전환했다 돌아올 필요 없이 바로 확정할 수 있습니다.

### 새 폴더 · 새 파일

툴바의 **새 폴더** · **새 파일**, 빈 곳 우클릭 메뉴, 폴더 우클릭 메뉴(그 폴더 안에 만듭니다)에서 시작합니다. 목록 맨 위에 이름 입력 줄이 열립니다. 폴더 우클릭 메뉴에서 시작하면 그 폴더 바로 아래(그리드는 폴더 바로 다음 칸)에 열리고, 줄이 조금 들여 써지며 입력 칸 뒤에 **{폴더} 안에** <!-- en: in {folder} --> 가 붙고 그 폴더가 강조됩니다. 보던 폴더는 바뀌지 않습니다. 입력 줄에는 "새 폴더" 는 이름 전체가, "제목 없음.txt" 는 확장자 앞까지 선택되어 있습니다. 같은 이름이 있으면 "새 폴더 2" 처럼 번호가 붙은 이름으로 시작합니다.

- `Enter` 로 만들고, `Esc` 로 취소합니다. 취소하면 디스크에는 아무것도 생기지 않습니다.
- 입력 줄 밖을 누르면 이름이 올바를 때는 만들고, 비었거나 잘못됐으면 취소합니다.
- 이름이 비었거나(공백만 있는 이름 포함) 쓸 수 없는 글자(`/`, Windows 에서는 `\ : * ? " < > |` 도)가 들어 있거나 이름이 공백으로 시작하거나 끝나거나 Windows 가 예약한 이름(`CON`, `NUL` 등)이거나 Windows 에서 이름 끝이 점이면 입력 칸 아래에 이유가 바로 나옵니다. 이미 있는 이름은 `Enter` 를 누를 때 알려 주며(macOS·Windows 에서는 대소문자만 다른 이름도 이미 있는 이름입니다), 입력 줄은 연 채로 글자를 그대로 둡니다. 덮어쓰지 않습니다.
- 만든 항목은 정렬된 자리로 가서 선택됩니다. 그 사이 다른 폴더로 옮겨 갔거나 다른 항목을 골랐다면 선택은 바뀌지 않습니다.
- 쓸 수 없는 폴더에서는 두 버튼이 흐려지고, 마우스를 올리면 **이 폴더에 쓸 수 없습니다** <!-- en: Can't write to this folder --> 가 보입니다. 폴더 우클릭 메뉴로 쓸 수 없는 폴더 안에 만들려 하면 입력 줄이 열리지 않고 같은 안내가 나옵니다(Windows 에서는 만들 때 오류로 알립니다). 원격 워크스페이스의 탐색기에서도 쓸 수 있습니다. 원격 컴퓨터의 Tasty 가 이전 버전이면 이 버튼과 메뉴 항목이 없습니다.

탐색기에 포커스가 있을 때 `F7` 로 새 폴더, `Shift+F4` 로 새 파일을 만듭니다. macOS 는 기본 설정에서 F 키가 미디어 키라 `Fn` 을 함께 누릅니다. 키는 설정 > 단축키 > **탐색기** <!-- en: Explorer --> 에서 바꿉니다.

### 찾기 · 하위 폴더 검색

툴바의 **찾기** 토글(칸이 좁으면 **더 보기** 메뉴)이나 탐색기에 포커스가 있을 때의 `Ctrl+F` 로 툴바 아래에 찾기 줄을 엽니다. `Ctrl+F` 는 터미널 검색과 같은 단축키이고, 탐색기에서는 이 찾기 줄을 엽니다.

- 입력하는 즉시 지금 폴더에서 이름에 그 글자가 들어 있는 항목만 남습니다. 대소문자는 구분하지 않고, 맞는 부분은 강조색으로 보입니다. 오른쪽에 "2 / 6" 처럼 보이는 수와 전체 수가 나옵니다. 맞는 이름이 없으면 목록 자리에 "“…”와(과) 맞는 이름이 없습니다" 가 보입니다. 위 폴더로 가는 `..` 줄은 거르는 동안에도 남습니다.
- 걸러져 안 보이게 된 항목은 선택에서 빠집니다. 전체 선택도 보이는 항목만 고릅니다.
- **하위 폴더** <!-- en: Subfolders --> 를 켜면 지금 폴더 아래 전체에서 찾습니다. 찾는 동안 결과가 들어오는 대로 채워지고 **중지** <!-- en: Stop --> 로 멈출 수 있습니다(찾은 것은 남습니다). 상세 보기에서는 종류 대신 **폴더** <!-- en: Folder --> 열에 지금 폴더 기준 위치가 보이고, 목록·그리드 보기에서는 항목에 마우스를 올리면 보입니다. 결과 하나를 고르면 아래 상태줄에도 위치가 나옵니다. 읽을 수 없는 폴더는 건너뛰고 "폴더 1개 건너뜀" 처럼 알려 주며, 마우스를 올리면 그 폴더들이 보입니다. 결과가 5,000 개에 닿으면 검색을 멈추고 "5,000개 이상 찾음 · 중지됨" 을 보입니다. 찾은 결과는 남으며, 검색어를 더 입력하면 범위를 좁힐 수 있습니다. 폴더 링크 안으로는 들어가지 않습니다. 결과 항목의 이름을 바꾸거나 옮기거나 지우면, 어느 탐색기에서 했든 검색을 처음부터 다시 해 결과를 맞춥니다.
- 찾기 칸에서 `Esc` 를 한 번 누르면 글자를 지우고, 한 번 더 누르면 찾기 줄을 닫습니다. ×, 다른 폴더로 이동(뒤로·위로·주소창·폴더 열기)으로도 닫힙니다.
- 찾기 칸에 글자를 입력하는 동안에는 글자를 쳐서 찾기와 탐색기 단축키가 동작하지 않습니다.
- 확장자로 찾으려면 같은 칸에 `ext:rs`를 입력하세요. `ext:rs ext:md`는 rs 또는 md 파일을 찾고, `note ext:rs`는 이름에 note가 들어간 rs 파일을 찾습니다. 폴더는 제외하며 마지막 확장자만 봅니다. 대소문자는 구분하지 않고 `EXT:.RS`도 같습니다. 확장자는 문자·숫자·밑줄·하이픈으로 적습니다. 비어 있는 `ext:`나 `ext:*`, `ext:rs,md`는 일반 이름 글자로 찾으며 와일드카드·인용부호 문법은 없습니다. 확장자 조건과 함께 쓴 나머지 이름은 단어 사이를 공백 하나로 이은 부분 문자열로 찾습니다. 이름 조건만 강조됩니다.
- 검색 중 툴바나 빈 곳 메뉴에서 새 폴더·새 파일을 만들거나 일반 붙여넣기를 하면 검색을 시작한 폴더에 들어갑니다. 검색 조건에 맞으면 결과에 다시 나타납니다. 폴더를 지정한 메뉴나 **붙여넣기 (안으로)**는 지정한 폴더를 씁니다.
- 원격 워크스페이스의 탐색기는 지금 폴더 거르기만 하고 하위 폴더 검색은 없습니다.

### 미리보기 패널

툴바의 **미리보기 패널** 버튼을 누르면 목록 오른쪽에 패널이 열리고, 선택한 파일 하나를 보여 줍니다. 텍스트 파일은 앞부분(64 KB)을 고정폭 글꼴로, 이미지는 패널에 맞춰(원래 크기보다 키우지 않고) 보여 줍니다. 그 밖의 형식이나 폴더는 **이 파일 형식은 미리 볼 수 없습니다** <!-- en: No preview for this file type -->, 1 MiB 보다 큰 파일과 한 변이 16384 픽셀을 넘는 등 펼치기에 너무 큰 이미지는 **너무 커서 미리 볼 수 없습니다** <!-- en: Too large to preview --> 가 나옵니다. 이미지가 픽셀 상한을 넘으면 그 이미지의 실제 크기도 함께 보입니다. 파일을 여러 개 고르면 몇 개를 골랐는지 보이고, 하나만 고르라고 안내합니다. 패널 왼쪽 경계를 끌어 너비를 200~460px 사이로 바꿀 수 있습니다. 켜 둔 상태와 너비는 탐색기마다 기억되어 Tasty 를 다시 열어도 그대로이고, 프리셋으로 저장해도 따라갑니다. 탐색기 칸이 좁아 목록과 함께 둘 수 없으면 버튼은 켜진 채 패널만 잠시 숨습니다. 패널 머리 아래에 남은 높이가 120px 미만이면 파일명·종류·크기만 남고 본문과 머리 아래 구분선은 숨습니다. 원격 워크스페이스의 탐색기에서는 미리 볼 수 없습니다. 키보드로 움직인 현재 항목의 테두리는 미리보기 패널을 침범하지 않고 파일 목록 안에 표시됩니다.

### 숨김 파일

이름이 점(`.`)으로 시작하는 파일과 폴더, 그리고 Windows 에서 숨김 속성을 준 항목과 macOS 에서 숨김 표시(`chflags hidden`)를 한 항목은 처음에는 목록에 보이지 않고, 아래 상태줄에 **숨김 {n}개** <!-- en: {n} hidden --> 처럼 몇 개를 숨겼는지 나옵니다. `Ctrl+Shift+.`(macOS 는 `Cmd+Shift+.`)을 누르거나 **더 보기** 메뉴의 **숨김 파일 보기** 를 고르면 함께 보이고, 숨김 항목은 이름과 아이콘이 흐린 글자색으로 나옵니다. 같은 방법으로 다시 숨깁니다. 켜 둔 상태는 탐색기마다 기억되어 Tasty 를 다시 열어도 그대로이고, 프리셋으로 저장해도 따라갑니다. 왼쪽 폴더 트리도 같은 설정을 따릅니다. 하위 폴더 검색도 이 설정을 따릅니다. 숨김을 끄면 숨김 폴더 안으로 들어가지 않고, 설정을 바꾸면 같은 검색을 처음부터 다시 합니다. 원격 워크스페이스의 탐색기는 원격 컴퓨터의 숨김 속성·숨김 표시도 따릅니다. 원격 컴퓨터의 Tasty 가 이전 버전이면 이름 앞의 점만 봅니다.

### 속성

우클릭 메뉴 맨 아래 **속성** <!-- en: Properties --> 을 고르면 탐색기 칸 안에 팝업이 뜹니다. 파일과 폴더는 형식 · 크기 · 수정일 · 만든 날짜 · 경로 · 권한을 보여 줍니다. **경로** <!-- en: Path --> 는 항목 자신의 절대 경로이며 옆의 복사 버튼으로 복사할 수 있습니다. 폴더는 하위 항목 수와 크기를 뒤에서 세는 동안 진행 표시가 돌고, 읽지 못한 폴더가 있으면 크기 아래에 **일부 폴더를 읽지 못함** <!-- en: Some folders couldn't be read --> 을 표시합니다. 팝업을 닫으면 세기를 멈춥니다. 시각은 이 컴퓨터의 시간대로 보이며 **설정** > **일반** 의 **속성 창 시각 형식** 에서 분까지 · 초까지 · 초 + UTC 오프셋 중에 고릅니다.

항목 하나를 보고 있으면 아래 **열기** <!-- en: Open --> 버튼이 목록에서 Enter 를 누른 것과 같이 그 항목을 엽니다. 파일은 핸들러 설정을 따르고 폴더는 그 탐색기에서 들어가며, 팝업은 열린 채 남습니다. 끊긴 링크면 버튼이 흐려집니다.

내 컴퓨터의 파일이나 폴더 하나는 **권한** <!-- en: Permissions --> 옆 **편집** <!-- en: Edit --> 으로 권한을 바꿀 수 있습니다. macOS · Linux 에서는 소유자 · 그룹 · 기타의 읽기 · 쓰기 · 실행을 체크하고, Windows 에서는 **읽기 전용** <!-- en: Read-only --> 특성만 바꿉니다. **적용** <!-- en: Apply --> 을 눌러야 바뀌며, 그 항목에만 적용하고 폴더 안 항목은 그대로 둡니다. setuid · setgid · sticky 같은 특수 비트도 그대로입니다. 바꾸지 못하면 상자에 이유가 나오고 실제 권한을 다시 읽어 보여 줍니다. 탐색기 칸이 좁으면 상자가 잘리지 않도록 역할 이름을 체크박스 위 줄로 올리고, 더 좁으면 읽기 · 쓰기 · 실행을 이름 붙은 체크박스로 한 줄씩 늘어놓습니다. 소유자가 아니면(관리자 권한으로 실행한 경우 제외) 편집 버튼 대신 소유자만 바꿀 수 있다는 안내가 나옵니다. 링크, 여러 항목, 원격 항목의 권한은 바꿀 수 없습니다.

링크는 링크 대상과 대상의 종류 · 크기 · 수정 시각, 링크 자신의 경로를 보여 줍니다. 링크 대상도 복사할 수 있습니다. 대상이 없는 링크는 **끊긴 링크** <!-- en: Broken link --> 로 표시하고 대상 아래에 **대상을 찾을 수 없음** <!-- en: Target not found --> 을 보입니다. 링크 아래에는 링크를 지우거나 이름을 바꿔도 대상은 그대로라는 안내가 나옵니다. 권한 오류 등으로 읽지 못하면 이유와 함께 **다시 시도** <!-- en: Retry --> 버튼이 나옵니다.

여러 항목을 고르면 개수 · 종류 · 전체 크기 · 공통 위치를, 빈 곳을 우클릭하면 지금 폴더를 보여 줍니다. 고른 항목 중 일부를 읽지 못하면 읽은 항목만 세어 보여 주고 종류 아래에 **일부 항목을 읽지 못함** <!-- en: Some items couldn't be read --> 을 표시합니다. 모두 읽지 못하면 위의 다시 시도 화면이 나옵니다. 폴더와 그 안의 항목을 함께 골라도 안쪽 항목은 한 번만 세고, 하드링크로 연결된 같은 파일의 크기도 한 번만 더합니다. 원격 탐색기에서는 목록에 있는 형식 · 크기 · 수정일 · 경로만 보이며, 원격 목록에는 폴더 크기가 없어 폴더가 섞인 전체 크기는 — 로 표시합니다.

우클릭 메뉴에서 단축키가 지정된 모든 항목은 첫 번째 단축키를 오른쪽에 표시합니다. **실행 취소**·**다시 실행**도 같은 규칙을 따르며, 설정에서 단축키를 바꾸거나 모두 지우면 메뉴 표시도 따라 바뀝니다.

### 단축키 (탐색기에 포커스가 있을 때)

| 하는 일 | 단축키 |
|---------|--------|
| 새로고침 | `F5` |
| 상위 폴더로 | `Alt+↑` (macOS `Cmd+↑`) |
| 뒤로 / 앞으로 | `Alt+←` / `Alt+→` (macOS `Cmd+←` / `Cmd+→`) |
| 주소창으로 이동 (경로 전체 선택) | `Alt+L` (macOS `Cmd+L`) |

| 숨김 파일 보기·숨기기 | `Ctrl+Shift+.` · `Alt+Shift+.` (macOS `Cmd+Shift+.`) |

| 항목 옮기기 | 방향키 · `Home` · `End` · `PageUp` · `PageDown` (좌우는 격자 보기에서만) |
| 선택 넓히기 | 위 키에 `Shift` |

클릭으로 선택, `Ctrl+클릭` 으로 추가, `Shift+클릭` 으로 범위 선택. 키로 항목을 옮기면 그 항목에 테두리가 생기고, 목록을 클릭하면 다음 키를 누를 때까지 숨습니다. 목록의 빈 곳에서 끌면 사각형에 걸친 항목을 고르고, `Ctrl` 이나 `Shift` 를 누른 채 시작하면 지금 선택에 더합니다. 끄는 동안 목록 위·아래 끝 가까이 가면 그 쪽으로 스크롤되며 계속 고릅니다. 끝에 가까울수록 빨라지고, 목록 밖으로 나가도 가장 빠른 속도(초당 20줄)로 계속 스크롤합니다. `Shift+클릭` 은 마지막으로 클릭한 항목부터 누른 항목까지를 고르고, `Ctrl+Shift+클릭` 은 지금 선택을 둔 채 그 범위를 더합니다. macOS 에서는 `Ctrl` 대신 `Cmd` 를 씁니다.

### 글자를 쳐서 찾기

목록에 포커스가 있을 때 파일 이름의 첫 글자를 입력하면 그 글자로 시작하는 항목이 선택되고 그 자리로 스크롤됩니다. 그리드·목록·상세 어느 보기에서나 같습니다. 같은 글자를 이어서 누르면 후보를 하나씩 넘어가고, 마지막 다음에는 처음으로 돌아갑니다. 다른 글자를 이어서 입력하면 `co`, `con` 처럼 앞글자 검색이 됩니다. 대소문자는 구분하지 않으며, 1 초쯤 쉬었다가 입력하면 새 검색으로 시작합니다. 해당하는 이름이 없으면 선택은 그대로 남습니다.

주소창을 편집 중이거나 팝업이 떠 있을 때는 입력한 글자가 그쪽으로 갑니다. 탐색기를 여러 개 띄워 두었다면 지금 포커스가 있는 하나만 움직입니다.

수식 키 없이 글자 하나에 단축키를 직접 지정해 두었다면 그 글자는 단축키로만 동작하고 이 기능에는 쓰이지 않습니다. 기본 설정에는 그런 단축키가 없습니다.

### 우클릭 메뉴

이름을 바꿀 때 같은 이름의 항목이 있으면 덮어쓰지 않고 실패를 알립니다. 복사할 때 심볼릭 링크는 링크로 보존하고, 파일은 원래 권한과 수정 시각을, 폴더는 원래 권한(읽기 전용 포함)을 그대로 가집니다. 소유자 · 확장 속성 · ACL 은 옮기지 않습니다. 또 실제로 같은 폴더이거나 그 하위인 경로에는 폴더를 붙여넣을 수 없습니다. 파일 작업이 실패하면 알림에 오류가 표시됩니다.

폴더를 가리키는 링크는 폴더처럼 열리고 주소창에는 링크의 경로가 남습니다. 링크의 이름 변경·휴지통 이동은 링크만 다루고 가리키는 폴더는 그대로 둡니다. 가리키는 대상이 사라진 링크를 열면 대상이 없다는 알림이 나옵니다. 목록에서 링크는 이름 뒤에 작은 링크 아이콘이 붙고, 대상이 사라진 링크는 아이콘 자리에 경고 색 링크 아이콘이 보이며 마우스를 올리면 찾지 못한 대상 경로가 나옵니다. 원격 탐색기도 같게 보이고 같은 알림이 나오지만, 마우스를 올려도 대상 경로는 나오지 않습니다. 원격 Tasty 가 링크 상태를 보내지 않는 버전이면 링크를 구분하지 않고 일반 항목처럼 보입니다.

Linux 네이티브 Wayland에서는 우클릭 메뉴와 툴바의 **더 보기** <!-- en: More --> 메뉴를 지원하지 않습니다. 표시된 툴바 버튼과 탐색기 단축키를 사용하세요. **속성**처럼 기본 단축키가 없는 기능은 **설정** > **단축키** > **탐색기**에서 키를 지정할 수 있습니다.

- **열기** <!-- en: Open --> — 하위 폴더 검색 결과 하나를 우클릭하면 맨 앞에 나옵니다. 더블클릭처럼 폴더는 그 폴더로 들어가고 파일은 엽니다. 원격 탐색기에는 나오지 않습니다.
- **들어 있는 폴더에서 보기** <!-- en: Show in enclosing folder --> — 하위 폴더 검색 결과(**열기** 다음)나 링크 하나를 우클릭하면 맨 앞에 나옵니다. 그 항목이 실제로 들어 있는 폴더(링크는 가리키는 대상이 든 폴더)를 지금 보던 경로 그대로 열고 항목을 골라 보이는 곳으로 스크롤합니다. 대상이 사라진 링크와 원격 탐색기에는 나오지 않습니다.
- **새 폴더** <!-- en: New folder --> · **새 파일** <!-- en: New file --> — 빈 곳 메뉴의 맨 앞, 폴더 메뉴의 파일 조작 묶음에 있습니다. 위 "새 폴더 · 새 파일" 을 보세요.
- **경로 복사** <!-- en: Copy Path --> — 여러 개를 고르면 메뉴 이름이 **경로 모두 복사** <!-- en: Copy Paths --> 로 바뀌고, 경로를 줄바꿈으로 이어 붙입니다.
- **실행 취소** <!-- en: Undo --> · **다시 실행** <!-- en: Redo --> — 빈 곳 메뉴에 있고, "실행 취소: 3개 이동"·"실행 취소: 이름 변경" 처럼 대상 작업을 이름에 적습니다. 되돌리거나 다시 실행할 작업이 없어도 **실행 취소**·**다시 실행** 두 행은 **속성** 앞에 흐리게 남습니다. 탐색기마다 최근 작업 10개(복사·이동·이름 변경·새 폴더·새 파일)를 기억합니다. 일부만 된 복사·이동은 된 항목만 기억합니다. 실행 취소한 작업은 다시 실행할 수 있고, 새로 작업하면 다시 실행할 것은 사라집니다. 다시 실행은 같은 작업을 다시 하며, 복사·이동은 이름이 겹치면 다시 묻고 이름 변경·새 항목은 같은 이름이 있으면 덮어쓰지 않고 실패를 알립니다. 이름 변경을 실행 취소하면 원래 이름으로 돌아가고(원래 이름에 다른 항목이 생겼거나 그 뒤 항목을 고쳤으면 그대로 둡니다), 새 폴더·새 파일을 실행 취소하면 휴지통으로 보냅니다(만든 뒤 내용을 넣거나 고쳤으면 남겨 둡니다). 가장 최근 작업을 더는 되돌릴 수 없으면(예: 복사본을 지움, 옮긴 파일을 옮긴 뒤 고침) 행이 흐려지고 마우스를 올리면 이유가 보입니다(Windows 에서는 같은 이유가 행 이름에 나옵니다). 실행 취소한 뒤 원래 자리의 항목이 없어지거나 바뀌면 다시 실행도 같은 방식으로 흐려지므로, 되돌린 적 없는 파일을 다시 실행이 옮기는 일은 없습니다. 그 탐색기의 파일 작업이 아직 기다리거나 진행 중이면 두 행이 흐려지고 단축키는 안내만 띄우므로, 방금 시작한 작업을 건너뛰고 그 앞 작업이 되돌려지는 일은 없습니다. 휴지통 이동은 이 기록에 들어가지 않습니다(휴지통에서 복원합니다).
- **복사** <!-- en: Copy --> · **잘라내기** <!-- en: Cut --> · **붙여넣기** <!-- en: Paste --> · **붙여넣기 (안으로)** <!-- en: Paste (into) --> — 같은 이름이 있으면 어떻게 할지 묻습니다 ([진행과 결과](#진행과-결과)). 복사·잘라내기한 목록은 모든 Tasty 윈도우가 함께 쓰므로 다른 윈도우에서도 붙여넣을 수 있습니다. 이 목록은 OS 클립보드에도 올라가서 다른 파일 관리자에 붙여넣을 수 있고, 파일 관리자에서 복사·잘라내기한 파일도 탐색기에 붙여넣을 수 있습니다. 둘이 다르면 나중에 복사한 쪽이 붙여넣어지고, 그 뒤 다른 앱에서 글자를 복사했으면 탐색기에는 붙여넣을 것이 없습니다. 잘라낸 파일은 한 번 옮기고 나면 클립보드에서 지워집니다. 원격 탐색기에서 복사한 파일은 OS 클립보드에 올리지 않고, 클립보드에 이 컴퓨터의 파일이 아닌 항목(다른 컴퓨터의 경로나 웹 주소 등)이 있으면 붙여넣지 않습니다. 다른 앱이 클립보드를 가진 채 응답하지 않을 때도 그 앱이 나중에 복사한 것으로 보고 붙여넣지 않으며, 알림으로 알려 줍니다. macOS Finder 에서 복사한 파일은 늘 복사로 붙여넣어집니다. Linux 는 X11 클립보드를 쓰며, Wayland 에서는 XWayland 를 거칩니다. 시스템 클립보드를 갱신하지 못하면 파일 목록을 이 Tasty 인스턴스 안에만 저장했다고 알려 줍니다. 내부 목록을 붙여넣을 때도 시스템 클립보드를 확인하지 못했다면 안내합니다. 사용할 내부 목록이 없을 때 붙여넣기를 실행하면 접근 불가를 알립니다. 메뉴를 여는 것만으로는 알림이 나타나지 않습니다. 네이티브 Wayland 클립보드는 지원하지 않습니다.
- **휴지통으로 이동** <!-- en: Move to Trash --> — 확인 없이 OS 휴지통으로 보냅니다. 되돌리려면 휴지통에서. 그 드라이브에 휴지통이 없으면 아무것도 지우지 않고 알려 줍니다.
- **이름 변경** <!-- en: Rename -->. 새 이름에도 새 폴더·새 파일과 같은 규칙(빈 이름, 쓸 수 없는 글자, 앞뒤 공백, 예약 이름)이 적용되고, 맞지 않으면 입력 칸 아래에 이유가 나오며 저장되지 않습니다.
- **시스템에서 열기** <!-- en: Open in system --> — 고른 파일은 OS 기본 앱으로, 폴더는 OS 파일 관리자로 엽니다. 여러 항목을 고르면 모두 엽니다.
- **Finder에서 보기** <!-- en: Show in Finder --> (macOS) · **파일 탐색기에서 보기** <!-- en: Show in File Explorer --> (Windows) · **파일 관리자에서 보기** <!-- en: Show in File Manager --> (Linux) — 한 항목을 골랐을 때 그 항목이 든 폴더를 열고 항목을 골라 둡니다. Linux 에서 파일 관리자가 항목 고르기를 지원하지 않으면 폴더만 엽니다.
- **새 탭으로 열기** <!-- en: Open in New Tab --> — 그 폴더를 루트로 하는 탐색기 탭을 페인에 하나 더 엽니다.
- **이 폴더로 루트 설정** <!-- en: Set as Root --> — 왼쪽 트리의 루트를 옮깁니다.
- **즐겨찾기에 추가** <!-- en: Add to Favorites --> — 폴더 하나나 빈 곳을 우클릭하면 나옵니다. 이름을 붙여 왼쪽 아래 목록에 둡니다. 즐겨찾기는 모든 탐색기가 공유하며 `~/.tasty/explorer-favorites.toml` 에 저장됩니다. 다른 윈도우에서 추가하거나 지운 즐겨찾기도 바로 반영됩니다. 파일 저장은 뒤에서 진행되므로 저장 중에도 계속 작업할 수 있습니다. 저장하지 못하면 경고 알림이 뜨고 목록은 이번 실행에 남습니다. 외부에서 즐겨찾기 파일을 바꾼 경우에는 덮어쓰지 않으니 파일을 확인한 뒤 Tasty를 다시 시작하세요. 왼쪽 아래 즐겨찾기를 우클릭하면 **새 탭으로 열기** · **이 폴더로 루트 설정** · **즐겨찾기에서 제거** <!-- en: Remove from Favorites --> 가 나옵니다(원격 탐색기에서는 새 탭으로 열기가 빠집니다). 제거해도 폴더 자체는 그대로입니다.
- **속성** <!-- en: Properties --> — 위 [속성](#속성) 팝업을 엽니다. 원격 탐색기에서도 나옵니다.

마지막으로 고른 보기 방식은 기억되어 새 탐색기에도 적용됩니다. 탐색기 폰트는 **설정** > **외관** <!-- en: Appearance --> 의 **탐색기** <!-- en: Explorer --> 항목에서 따로 지정합니다. 원격 워크스페이스의 탐색기에서도 새 폴더 · 새 파일 · 이름 변경 · 휴지통으로 이동 · 복사 · 잘라내기 · 붙여넣기 · 끌어서 옮기기를 할 수 있습니다. 실제 작업은 원격 컴퓨터의 Tasty 가 하고, 진행 표시 · 이름 충돌 질문 · 결과 카드는 로컬과 같게 나옵니다. 휴지통은 원격 컴퓨터의 휴지통입니다. 원격 작업은 **실행 취소** 목록에 들어가지 않으니 결과 카드의 **되돌리기** 를 쓰세요. 원격 작업은 연결마다 하나씩 실행하므로 진행 줄과 대기 목록 맨 앞에 원격 컴퓨터 이름이 나옵니다. 칸이 좁으면 이름·바이트 표시를 남은 폭에 맞춰 줄여 대기 개수·취소 버튼과 겹치지 않게 합니다. 이름 글자가 보이지 않아도 호스트 글리프에 올려 두면 전체 이름을 보여 주고, 줄인 바이트 표시에 올려 두면 전체 값을 보여 줍니다. 대기 목록도 칸 안에 맞춰 열립니다. 매우 좁은 칸에서는 대기 목록의 작업 아이콘을 숨겨 취소·제거 버튼을 먼저 보여 줍니다. 버튼 하나가 온전히 들어가지 않으면 버튼도 숨기므로 칸을 넓혀 사용하세요. 원격 컴퓨터의 Tasty 가 이전 버전이면 파일을 바꾸는 항목과 버튼이 흐리게 꺼지고, 툴팁(단축키로 부르면 알림)이 그 컴퓨터의 Tasty 를 업데이트하라고 알려 줍니다. 작업 중에 연결이 끊기면 원격에서는 작업이 멈추지만 어디까지 했는지는 알 수 없다는 안내가 나오니, 다시 연결한 뒤 폴더를 확인하세요. 그 연결에서 기다리던 작업은 실행하지 않고 몇 개를 실행하지 않았는지 알려 줍니다. 시스템에서 열기 · 파일 관리자에서 보기 · 새 탭으로 열기는 원격 탐색기에 나오지 않습니다. **즐겨찾기에 추가** 는 메뉴에 보이지만 누르면 아직 지원하지 않는다는 알림만 뜨고 추가되지 않습니다.

로컬과 원격 사이, 또는 서로 다른 원격 컴퓨터 사이에서는 파일을 붙여넣거나 끌어 놓을 수 없습니다. 붙여넣기 메뉴가 나오지 않고, 단축키로 붙여넣으면 안내만 나옵니다. 경로가 같은 다른 컴퓨터의 파일을 대신 복사하지 않습니다. 마크다운 파일을 더블클릭하면 원격 컴퓨터에 그 파일의 탭이 열리고, 기본 핸들러를 원격에서 쓸 수 없으면 원격에서 쓸 수 있는 핸들러만 골라 보여 주고, 그런 핸들러가 없는 형식이면 안내만 나옵니다.

### 끌어서 옮기기

항목을 끌어 폴더 줄·폴더 칸, 왼쪽 트리의 폴더, 즐겨찾기에 놓으면 그 폴더로 옮깁니다. 파일 위나 빈 곳에 놓으면 그 탐색기가 보고 있는 폴더로 갑니다. 옆에 띄운 다른 탐색기로 끌어도 됩니다. 항목을 끌면서 목록이나 왼쪽 트리의 위아래 가장자리로 가면 자동으로 스크롤합니다. 가장자리에 가까울수록 빨라지고, 영역 밖에서는 초당 20줄 속도를 유지합니다. 여러 탐색기를 위아래로 나눴을 때는 마우스가 있는 영역만 스크롤하고, 영역 밖에서는 가장 가까운 탐색기만 움직입니다.

- 같은 디스크면 **이동**, 다른 디스크면 **복사**합니다. `Ctrl` (macOS `Option`) 을 누른 채 놓으면 반대로 합니다. 이 키는 **설정** > **단축키** > **일반** 맨 아래의 **탐색기 드래그 전환 키** <!-- en: Explorer drag flip modifier --> 에서 바꿉니다(`config.toml` 의 `[keybindings]` `explorer_drag_flip_modifier` 와 같은 값입니다).
- 끄는 동안 포인터 옆 표시가 **(폴더)(으)로 이동** <!-- en: Move to --> · **(폴더)(으)로 복사** <!-- en: Copy to --> 처럼 무엇을 할지 미리 알려 줍니다. 놓을 수 없는 곳이면 **놓을 수 없음** <!-- en: Can't drop --> 과 이유(자기 안으로, 이미 그 폴더에 있음, 다른 컴퓨터, 이 원격은 파일을 바꿀 수 없음, 쓰기 권한 없음)가 나옵니다. 심볼릭 링크로 들어간 폴더는 링크가 가리키는 폴더로 판단합니다.
- 원격 탐색기 안에서 끌면, 원격 컴퓨터가 같은 디스크라고 알려 준 폴더 사이에서만 **이동** 하고 그 밖에는 **복사** 합니다.
- 닫힌 트리 폴더 위에 800ms 머물면 마우스를 더 움직이지 않아도 펼쳐집니다. 기다리는 동안에는 놓을 폴더의 테두리가 유지됩니다. `Esc` 를 누르면 끌기를 취소합니다.
- 운영체제의 파일 관리자에서 탐색기 칸으로 끌어 온 파일은 그 폴더로 **복사**합니다(이동하지 않습니다). 원격 탐색기에는 놓을 수 없습니다(다른 컴퓨터의 파일이기 때문입니다). Linux에서 파일을 끌어오는 동작은 X11/XWayland에서 지원합니다. Linux(X11) 에서는 끄는 동안 칸 표시 대신 윈도우 전체 안내가 보이지만, 탐색기 칸 위에 놓으면 똑같이 복사됩니다.

Windows·macOS·Linux에서는 로컬 탐색기의 항목을 윈도우 밖으로 끌어 다른 앱에 **복사**할 수 있습니다. Linux는 X11과 네이티브 Wayland를 지원하며, 파일 아이콘과 포인터 표시는 운영체제가 제공합니다. 원본은 그대로 남고 외부 복사는 Tasty의 실행 취소 목록에 들어가지 않습니다. 원래 윈도우로 돌아와 놓아도 내부 이동을 함께 실행하지 않습니다. 원격 항목은 내보낼 수 없습니다. X11에서는 탐색기의 **선택 해제** 키(기본 `Esc`)로 끌기를 취소합니다. Windows·macOS·Wayland에서는 운영체제의 드래그 취소 키를 따릅니다.

Windows·macOS 구현은 컴파일로 확인했으며 실 기기 동작은 아직 측정하지 않았습니다. 같은 Tasty 프로세스의 다른 윈도우로는 보낼 수 없습니다. 별도로 실행한 Tasty가 일반 외부 앱처럼 받을 수는 있지만, Tasty 윈도우 사이의 파일 드래그는 지원 기능이 아닙니다. 시작 오류나 통신 오류가 나면 안내가 나오며, 드래그를 시작한 것만으로 복사가 완료됐다고 표시하지 않습니다.

### 진행과 결과

붙여넣기·끌어 놓기·휴지통 보내기는 한 번에 하나씩 차례로 처리합니다. 복사·이동은 먼저 대상 파일을 셉니다. 이때는 **복사할 항목 세는 중** 또는 **이동할 항목 세는 중**과 찾은 수를 갱신해 보여 주며 진행 막대는 없습니다. 집계가 끝나면 폴더 안의 파일까지 포함한 진행 개수와 현재 파일명을 표시합니다. 막대는 바이트 기준이고, 모두 빈 파일이거나 전체 크기를 알 수 없으면 파일 수를 기준으로 합니다. 결과에 나오는 개수는 처음 요청한 항목 수입니다. 다만 폴더와 그 안의 항목을 함께 골랐다면(예: 하위 폴더 검색 결과에서) 안쪽 항목은 폴더와 함께 처리되므로 따로 세지 않습니다. 링크 너머의 항목은 링크와 함께 골라도 따로 처리합니다.  작업을 시작한 탐색기 아래 상태줄에 진행 막대, 지금 다루는 파일, 크기가 나오고, **×** 로 멈춥니다. 멈추면 끝난 항목은 그대로 두고 남은 항목은 하지 않습니다. 기다리는 작업이 있으면 **+1 대기** <!-- en: +1 queued --> 표시가 붙고, 누르면 목록이 열려 기다리는 작업을 뺄 수 있습니다. 기다리는 작업이 너무 많거나 한 번에 고른 항목이 너무 많으면 작업을 받지 않고 그 탐색기에 경고 카드로 알립니다. 대기열이 찬 경우에는 카드의 **대기열 보기** <!-- en: Show queue --> 로 목록을 열 수 있습니다.

같은 이름이 이미 있으면 그 탐색기에 포커스가 있을 때 묻는 팝업이 뜹니다. 다른 곳을 보고 있었다면 상태줄의 **보기** <!-- en: Show --> 를 누르세요.

- **둘 다 유지** <!-- en: Keep both --> (`Enter`) — 기본값입니다. 새 항목에 `(copy)` 를 붙여 둡니다. 기존 항목은 바뀌지 않습니다.
- **건너뛰기** <!-- en: Skip --> · **바꾸기** <!-- en: Replace --> (파일만) · **나머지 취소** <!-- en: Cancel the rest --> (`Esc`).
- 같은 이름의 폴더는 합치지 않습니다. 폴더에는 건너뛰기와 둘 다 유지만 고를 수 있습니다.
- 충돌이 더 남았으면 **남은 충돌 n개에도 적용** <!-- en: Do this for the other conflicts --> 을 켜 한 번에 답합니다.

끝나면 탐색기 오른쪽 아래에 결과 카드가 뜹니다. 모두 끝난 카드는 잠시 뒤 사라지고, 실패하거나 건너뛴 항목이 있는 카드는 닫을 때까지 남아 그 경로를 보여 줍니다. **×** 로 멈춘 작업의 카드도 하지 않은 항목이 남았으면 닫을 때까지 남습니다. 복사하는 동안 쓰던 숨은 임시 폴더(`.tasty-copy-` 로 시작)를 지우지 못하면 카드가 경고 카드로 바뀌어 그 경로와 "임시 폴더를 지우지 못했습니다" 이유를 함께 보여 주고 닫을 때까지 남으니, 원인을 푼 뒤 그 폴더를 직접 지우세요.

- **다시 시도** <!-- en: Retry --> — 실패하거나 건너뛴 항목과, 멈춰서 하지 않은 항목만 다시 합니다. 이미 끝난 항목은 다시 하지 않습니다. 원본이 남은 이동 항목은 원본 지우기만 다시 합니다.
- **경로 복사** <!-- en: Copy paths --> — 카드의 경로를 클립보드에 담습니다.
- **되돌리기** <!-- en: Undo --> — 모두 끝난 복사·이동에서 카드가 보이는 동안 나옵니다. 옮긴 항목은 제자리로 돌리고(그 자리에 다른 항목이 생겼으면 그대로 둡니다), 복사본은 휴지통으로 보냅니다. 복사 뒤 고친 복사본은 남겨 둡니다. 바꾸기로 덮어쓴 파일은 되돌리지 못합니다.

다른 디스크로 옮길 때 원본을 다 지우지 못하면(예: 쓰기 권한이 없는 하위 폴더) 원본이 전부 또는 일부 남았다는 경고 카드가 닫을 때까지 남습니다. 이때 복사본이 온전한 자료이므로 되돌리기는 나오지 않습니다. 막던 원인을 푼 뒤 **다시 시도** 를 누르면 남은 원본만 지웁니다. 그사이 복사본이 없어졌거나 다른 것으로 바뀌었으면, 또는 원본 파일을 고쳤으면 원본을 지우지 않고 그 이유를 보여 줍니다. 복사본 경로가 링크 등으로 원본과 같은 파일을 가리키면 지우지 않습니다. 폴더는 복사본에 내용까지 똑같이 있는 항목만 지우고(큰 파일은 비교하는 동안 진행이 보이고 취소할 수 있습니다. 취소하면 아직 남은 원본만 경고 카드에 다시 남아 나중에 다시 시도할 수 있습니다), 옮긴 뒤 원본 폴더에 넣거나 고친 항목은 남긴 뒤 그 개수를 보여 줍니다. 비교하는 동안 상태줄에는 확인 중, 지우는 동안에는 원본 지우는 중이 나오고, 다 지우면 지운 원본 수를 알리는 카드가 잠시 뜹니다. 다시 시도 한 번이 원본 지우기와 다시 옮기기를 함께 하더라도 결과 카드는 하나입니다.

## 마크다운

`.md` 파일을 렌더해 보여줍니다. 파일이 바뀌면 1 초 안에 자동으로 다시 그립니다.

- 표 · 체크박스 · 각주 · 코드 강조 · `mermaid` 다이어그램 · `$…$` 수식 · `> [!NOTE]` 콜아웃(Obsidian 식 `[!tip]-` 접기 포함) · 맨 위 frontmatter 숨김.
- 제목이 있으면 본문 위에 접을 수 있는 **목차** <!-- en: Table of contents --> 가 붙습니다. 항목을 누르면 보고 있던 문서 그대로 그 제목 자리로 내려갑니다 — 같은 항목을 다시 눌러도 다시 이동합니다.
- 코드 블록에 마우스를 올리면 **코드 복사** <!-- en: Copy code --> 버튼.
- 문서에 포커스가 있을 때 [단축키](../customize/keybindings.md) 설정의 **검색** 키(기본 `Ctrl+F` · `Alt+F`, macOS `Ctrl+F` · `Cmd+F`) — **문서 내 검색** <!-- en: Find in document -->. 검색 키를 바꾸면 열려 있는 문서에도 바로 적용됩니다.
- 전체 선택 · 복사 키는 포커스가 있는 곳에만 적용됩니다. 본문에서 전체 선택하면 문서 내용만 고르고 주소 칸 · 검색 칸의 글자는 들어가지 않으며, 주소 칸이나 검색 칸에서는 그 칸의 입력만 고릅니다.
- 맨 위 주소창에 다른 파일 경로를 입력하고 `Enter` 나 **이동** <!-- en: Go --> 을 눌러 이동합니다. 최근 연 파일이 자동완성으로 뜹니다. 같은 Tasty 인스턴스의 다른 윈도우에서 연 파일도 최신순으로 최대 10개까지 함께 보입니다. 서피스가 좁으면 이동 버튼이 숨지만 `Enter` 로는 그대로 이동합니다.
- 주소창 왼쪽의 폴더 버튼(**파일 열기…** <!-- en: Open a file… -->)을 누르면 지금 문서가 있는 폴더에서 파일 선택 창이 열립니다. 고른 파일이 같은 서피스에 열리며 새 탭은 생기지 않습니다. 취소하면 문서는 그대로입니다. 파일 선택 창이 이미 떠 있으면 새로 열리지 않으니 먼저 그 선택을 마치거나 취소하세요. macOS 에서 키보드로 폴더 버튼을 누르면 파일 선택 화면이 문서 뒤에 가려질 수 있으니 마우스로 누르세요. 마우스로 눌렀을 때 바로 보이는지도 아직 실제 macOS 에서 확인하지 못했습니다. 원격 워크스페이스의 마크다운 주소창은 [원격 작업](../remote/attach.md)에서 설명합니다.
- 문서 안의 링크 — 다른 마크다운 · 파일은 같은 페인의 새 탭으로 열리고 Linux 에서는 그 탭으로 바로 넘어가며(macOS 에서는 마우스로 누른 링크만 넘어가도록 바뀌었지만 아직 실제 macOS 에서 확인하지 못했습니다. 키보드로 연 링크는 새 탭이 뒤에 붙기만 합니다), `http(s)://` 는 브라우저로 갑니다. 상대 경로는 그 문서가 있는 폴더 기준입니다. 열 수 있는 핸들러가 없는 파일이면 **다음으로 열기…** 창이 떠서 고르게 합니다(원격 워크스페이스에서는 원격에 열 수 있는 핸들러만 보이고, 하나도 없으면 알림이 뜹니다). `#제목` 처럼 같은 문서 안을 가리키는 링크와 각주 번호 · 되돌아가기 화살표는 그 자리로 이동만 합니다.
- **새로고침** 키(기본 `F5`)를 누르면 보고 있는 문서 하나만 파일을 다시 읽어 그립니다. 주소 칸이나 검색 칸에 입력하던 중에도 됩니다. 다만 문서를 새로 그리므로 주소 칸에 입력하던 내용, 열려 있던 검색 칸과 검색어, 선택은 지워지고 스크롤 위치만 되도록 그대로 돌아옵니다. 원격 워크스페이스의 문서는 원격의 원문을 다시 받아 오며, 연결이 끊겨 있으면 끊김 표시가 그대로 남습니다. 큰 파일은 아래와 같은 확인을 거칩니다.
- 1 MiB 를 넘는 파일은 **큰 파일을 열까요?** <!-- en: Open large file? --> 로 한 번 묻습니다. 이 확인 팝업은 그 마크다운 서피스 가운데에 뜹니다. 서피스가 팝업보다 좁으면 윈도우 가운데에 뜹니다. 작게 열었던 파일이 나중에 1 MiB 를 넘게 커져도 다시 읽기 전에 같은 확인을 띄우며, 답할 때까지 이전 내용이 그대로 보입니다. 취소하면 본문 자리에 **1 MiB를 넘는 파일이라 아직 읽지 않았습니다** <!-- en: This file is larger than 1 MiB and has not been loaded --> 가 보입니다. 그 아래 **파일 열기…** <!-- en: Open file… --> 버튼을 누르면 같은 확인을 다시 띄웁니다. 취소한 파일은 바뀌어도 자동으로 읽지 않으며, `tasty markdown reload --surface <ID>` 로도 다시 물을 수 있습니다. **열기** 를 고른 파일은 그 뒤로 묻지 않습니다.

**새 마크다운...** 이나 `Alt+'` > **마크다운** 은 **마크다운 파일 열기** <!-- en: Open Markdown File --> 창을 띄웁니다. 경로를 입력하거나 **찾아보기…** <!-- en: Browse… --> 로 고릅니다. 찾아보기는 지금 보고 있는 터미널의 현재 폴더에서 시작하고, 입력한 상대 경로도 그 폴더 기준으로 엽니다. 이 팝업은 그 서피스 영역 가운데에 뜨고, 다른 워크스페이스나 탭으로 옮기면 잠시 숨었다가 돌아오면 입력하던 그대로 다시 보입니다. 찾아보기로 연 파일 선택 창도 함께 숨고 돌아오며, 고르던 파일과 탐색 중인 폴더를 유지합니다. 숨은 동안에는 다른 화면의 클릭과 키보드 입력을 막지 않습니다.

```sh
tasty markdown recent
tasty markdown reload --surface 5
```

## 이미지

PNG · JPEG 등을 보고, 간단히 그립니다. **새 이미지** 는 빈 캔버스로 시작합니다. 이미지를 연 채로 만들어도 원래 파일과는 별개라, **저장** 하면 저장할 경로를 묻습니다. 새 경로로 저장하면 탭 이름이 그 파일 이름으로 바뀌고, 다시 시작해도 그 파일이 열립니다. 파일이 밖에서 바뀌면 1 초 안에 자동으로 다시 읽습니다 — 다만 **편집 중일 때는 미뤘다가** 편집을 끝낼 때 반영합니다(그리는 중에 밑그림이 바뀌지 않도록).

- 툴바 — **이전 이미지** <!-- en: Previous image --> / **다음 이미지** <!-- en: Next image --> (같은 폴더 안, 넘어가면 탭 이름도 그 파일로 바뀝니다. 편집 중에는 넘어가지 않으니 먼저 저장하거나 취소합니다 — `tasty image next`·`prev` 도 이때는 오류로 끝납니다), **새로고침** <!-- en: Refresh -->, **편집** <!-- en: Edit -->, **새 이미지** <!-- en: New image -->, 확대 **맞춤** <!-- en: Fit --> / `+` / `-`.
- **편집** 을 누르면 **굵기** <!-- en: Brush --> · **색상** <!-- en: Color --> 을 고르고 위에 그립니다. `Ctrl+Z` / `Ctrl+Shift+Z` 로 되돌리고 다시 합니다. **저장** <!-- en: Save --> 은 PNG 로 씁니다. JPEG 처럼 PNG 가 아닌 파일을 고쳐 저장하면 원본은 두고 같은 폴더에 같은 이름의 `.png` 를 만들어 그 파일로 넘어갑니다. 그 `.png` 가 이미 있으면 덮어쓰지 않고 저장할 경로를 묻습니다. 이때 입력칸 위에 이미 있다는 안내가 뜨고, 입력칸에는 `이름-1.png` 처럼 아직 없는 이름이 이름 부분이 선택된 채로 들어 있습니다.
- **다른 이름으로 저장**의 폴더 버튼은 Tasty 파일 선택 창을 엽니다. PNG 파일을 고르거나 이름을 입력하고 확정하면 저장 경로가 채워집니다. 기존 파일 이름이면 덮어쓰기 경고를 보여 줍니다. 실제 파일은 이미지의 **다른 이름으로 저장**에서 **저장**을 눌렀을 때 쓰며, 찾아보기를 취소하면 입력한 경로는 그대로입니다.
- 파일을 읽지 못하면 캔버스에 이유를 보여 줍니다 — **이미지를 찾을 수 없습니다** <!-- en: Image not found --> (경로 표시), **권한이 없습니다** <!-- en: Permission denied -->, **이미지를 열 수 없습니다** <!-- en: Can't open this image --> (손상됐거나 지원하지 않는 형식, 디코더 메시지 표시), **이미지가 너무 커서 열 수 없습니다** <!-- en: Image is too large to open --> (한 변이 16384px를 넘거나 디코딩에 512MiB보다 많은 메모리가 필요한 그림은 열지 않고, 그림의 실제 크기를 보여 줌). 너무 큰 그림을 뺀 나머지 경우에는 **다시 시도** <!-- en: Retry --> 를 누르면 다시 읽습니다. 파일이 돌아오거나 바뀌면 자동으로도 다시 읽습니다.
- 이미지에서 붙여넣기 단축키(기본 `Ctrl+V`)를 누르면 클립보드의 이미지를 떠 있는 선택 영역으로 붙여넣습니다. 클립보드에 이미지가 없으면 아무 일도 하지 않습니다. `tasty image paste --surface <ID>` 도 같습니다.
- `tasty image list` 는 **윈도우가 여러 개여도** 열려 있는 이미지를 전부 보여줍니다.
- `tasty image reload --surface <ID>` 는 기다리지 않고 지금 다시 읽습니다.

```sh
tasty image list
tasty image open --surface 5 shot.png
tasty image export --surface 5 out.png
```

## HTML

현재 폴더 상속을 켠 상태에서 HTML 파일 탭으로부터 새 탭이나 분할을 만들면 그 파일의 폴더를 기준으로 합니다. 웹 주소 탭은 기존 작업 폴더를 유지합니다.

헤드리스 서버에서도 `tasty html open`으로 HTML 탭의 요청 주소를 바꿀 수 있습니다. 헤드리스 서버는 페이지를 그리지 않으며, 원격 연결에서 HTML 본문 표시는 아직 지원하지 않습니다.

로컬 HTML 파일이나 URL 을 OS 의 웹 뷰로 띄웁니다. 탭 스트립 빈 곳 우클릭 > **새 HTML...** 을 누르면 파일 선택 창이 그 페인의 현재 폴더에서 열리고, 폴더와 `.html` · `.htm` · `.svg` 파일만 보입니다. 파일을 고르면 그 페인에 HTML 탭이 열리고, 취소하면 탭을 만들지 않습니다. 원격 워크스페이스에서는 파일 선택 창이 열리지 않고 아직 열 수 없다는 알림이 뜹니다.

- 로드 중이면 **불러오는 중…** <!-- en: Loading… -->, 실패하면 **불러오지 못했습니다** <!-- en: Failed to load --> 와 URL 이 보입니다.
- 메뉴나 팝업이 열려 있는 동안 Linux 에서는 HTML · 마크다운 페이지가 그대로 보입니다. 데스크톱에서 화면 합성(컴포지터)이 켜져 있으면 팝업이 둥근 모서리와 그림자, 뒤를 어둡게 하는 막까지 평소 모양 그대로 페이지 위에 겹쳐 보입니다. 합성이 꺼져 있거나 윈도우 관리자가 팝업 위치를 맞추지 못하면 팝업 상자 자리만 각진 상자로 가려집니다. 전체화면이나 윈도우 일부가 화면 밖에 있을 때 이런 상황이 생길 수 있습니다. Windows 와 macOS 에서도 페이지는 그대로 보이고 팝업 상자는 같은 각진 모양입니다. 이때 페이지를 누르거나 휠을 굴리면 팝업 바깥을 누른 것으로 처리되어 페이지에는 전달되지 않고, 키 입력도 페이지로 가지 않습니다. X 서버가 모양 확장(SHAPE · XFixes)을 지원하지 않는 Linux 에서는 팝업이 열려 있는 동안 페이지가 잠시 숨고 빈 패널만 보입니다. 알림 카드가 뜨면 카드와 겹치는 페이지만 카드가 사라질 때까지 숨고, 다른 페이지는 그대로 보입니다. 지금 글자를 입력하고 있는 페이지는 숨기지 않으므로 그 위의 알림 카드는 가려집니다.
- **설정** > **외관** 의 **HTML** 항목 — **기본 확대** <!-- en: Default zoom --> · **색 구성표** <!-- en: Color scheme --> (**테마 따름** <!-- en: Follow theme --> / 라이트 / 다크) · **원격 콘텐츠 허용** <!-- en: Allow remote content --> · **스크립트 샌드박스** <!-- en: Sandbox scripts -->. 원격 콘텐츠와 스크립트는 기본적으로 막혀 있습니다. 로컬에서 만든 미리보기를 보는 용도라 외부 사이트를 열 때는 **원격 콘텐츠 허용** 을 켜고 **스크립트 샌드박스** 를 꺼야 합니다.

### 주소 표시줄

HTML 화면 위쪽에는 주소 표시줄이 있습니다. 왼쪽부터 **뒤로** <!-- en: Back --> · **앞으로** <!-- en: Forward --> · **새로고침** <!-- en: Reload --> 버튼과 주소 칸입니다. 로컬 파일은 파일 경로로(홈 폴더는 `~`), 웹 문서는 URL 로 보입니다.

- 주소 칸에 파일 경로나 `file://` · `http://` · `https://` 주소를 입력하고 `Enter` 를 누르면 엽니다. 이동 버튼은 따로 없습니다.
- 상대 경로는 지금 문서를 기준으로 풉니다. 로컬 파일이면 그 파일이 든 폴더, 웹 문서면 그 주소 기준입니다. 빈 HTML 탭에서는 그 탭의 작업 폴더 기준이고, 기준이 없으면 열지 않고 알려 줍니다.
- 없는 파일을 입력하면 열지 않고 주소 칸 아래에 **파일을 찾을 수 없습니다** <!-- en: File not found --> 가 뜹니다. 보던 페이지와 입력한 글자는 그대로이며, 다음 글자를 입력하거나 `Esc` 를 누르면 안내가 사라집니다.
- 편집 중 `Esc` 는 입력을 취소하고 지금 문서 주소로 돌아갑니다. 주소 칸에 입력하는 동안에는 키가 페이지·터미널·Tasty 단축키로 가지 않습니다.
- 주소 칸에서 `Tab` · `Shift+Tab` 을 누르면 누를 수 있는 **뒤로** · **앞으로** · **새로고침** 버튼과 주소 칸 사이를 차례로 돌며, 버튼에 테두리가 보입니다. `Enter` 나 `Space` 로 그 버튼을 누르고, `Esc` 로 빠져나옵니다. 버튼으로 옮겨 가면 입력하던 글자는 원래 주소로 돌아가고, 주소 칸으로 돌아오면 주소 전체가 선택됩니다. 누른 버튼이 흐려지거나 불러오는 표시로 바뀌면 버튼의 포커스가 풀립니다.
- `Alt+L` (macOS `Cmd+L`) 로 지금 포커스가 있는 HTML 화면의 주소 칸으로 가며 주소 전체가 선택됩니다. 페이지 안에서 입력하던 중에도 동작합니다. 키는 **설정** > **단축키** > **서피스** 의 **주소창으로 이동** <!-- en: Focus the address bar --> 에서 바꾸며 탐색기의 주소창과 같은 키입니다.
- 불러오는 동안 새로고침 자리에 도는 표시가 나오고, 불러오지 못하면 주소 칸에는 열려던 주소가 남습니다.
- 히스토리 처음이면 뒤로, 끝이면 앞으로 버튼이 흐려집니다. HTML 화면이 440px 보다 좁으면 앞으로 버튼이 숨습니다.
- 빈 HTML 탭에는 주소 칸 안내와 단축키가 함께 보입니다. 주소 표시줄로 연 문서는 다시 시작하면 처음 만든 때의 주소(빈 탭이면 빈 탭)로 돌아갑니다. 에이전트가 `tasty html open` 으로 연 주소도 같습니다.
- 원격 워크스페이스의 HTML 탭에는 주소 표시줄이 없습니다.

### 원격 콘텐츠가 막힌 문서

**원격 콘텐츠 허용** 이 꺼져 있을 때 네트워크의 스타일시트 · 이미지 · 글꼴 등을 쓰는 로컬 문서를 보면 주소 표시줄 아래에 **이 문서의 원격 콘텐츠가 차단되었습니다** <!-- en: Remote content in this document is blocked --> 안내가 뜹니다. 원격 콘텐츠는 불러오지 않으므로 페이지가 스타일 없이 보일 수 있습니다. 스크립트 안내처럼 페이지를 가리지 않고 그만큼 아래로 내립니다.

- **원격 콘텐츠 허용** <!-- en: Allow remote content --> — 이 문서만 원격 콘텐츠를 불러오도록 한 번 다시 불러옵니다. 다른 문서로 이동하거나 파일 내용이 바뀌거나 Tasty 를 다시 시작하면 다시 막힙니다. 스크립트 허용과는 따로입니다. 문서를 불러오는 동안에는 누를 수 없습니다.
- 안내를 **×** 로 닫거나 원격 콘텐츠를 허용하면 주소 칸 오른쪽 끝에 지구본 아이콘이 남습니다. 막힌 문서는 사선이 그어진 지구본이고, 누르면 안내가 다시 뜹니다(누르기만으로 허용하지는 않습니다). 허용한 문서는 지구본이며 포인터를 올리면 허용했다는 안내만 보입니다.
- 원격 콘텐츠와 스크립트가 모두 막힌 문서는 두 안내가 원격 콘텐츠 → 스크립트 순서로 따로 쌓입니다.
- 에이전트가 연 문서는 사람이 그 탭을 볼 때 안내가 뜹니다. 에이전트는 `tasty surface html-remote-allow` 로 조회한 문서의 원격 콘텐츠를 허용할 수 있습니다.
- **원격 콘텐츠 허용** 설정을 켜 두면 모든 문서에서 원격 콘텐츠를 불러오고 안내와 아이콘이 없습니다. 원격 워크스페이스의 HTML 탭에는 이 안내가 없습니다.

### 스크립트가 막힌 문서

**스크립트 샌드박스** 가 켜져 있을 때 스크립트가 있는 문서를 보면 페이지 위에 **이 문서의 스크립트가 차단되었습니다** <!-- en: Scripts in this document are blocked --> 안내가 뜹니다. 안내는 페이지를 가리지 않고 페이지를 그만큼 아래로 내립니다. 안내 문구는 잘리지 않고 끝까지 보이며, 화면이 좁아 줄이 늘면 안내가 길어지고 페이지도 그만큼 더 내려갑니다. HTML 화면이 좁으면 버튼이 설명 아래 줄로 내려갑니다.

- **이 문서에서 허용** <!-- en: Allow for this document --> — 이 문서만 스크립트를 켜고 한 번 다시 불러옵니다. 다른 문서로 이동하거나 Tasty 를 다시 시작하면 다시 막힙니다. 허용한 문서의 탭에는 스크립트 파일 아이콘이 붙습니다.
- 화면이 새 문서를 불러오는 동안에는 **이 문서에서 허용** 을 누를 수 없습니다. 버튼에 포인터를 올리면 **문서를 다 불러오면 사용할 수 있습니다** <!-- en: Available when the document finishes loading --> 가 뜹니다. 링크·뒤로 가기·다시 불러오기로 직접 연 문서에 스크립트가 있으면 버튼이 다시 켜지고, 없으면 안내가 사라집니다. 에이전트가 연 문서라면 그 탭을 다시 볼 때 안내가 뜹니다. 아주 큰 파일은 화면이 열린 뒤에도 Tasty 가 파일 전체를 확인하는 동안 버튼이 잠시 꺼져 있을 수 있습니다. 이 확인은 다른 터미널과 화면을 멈추지 않습니다. 스크립트를 허용한 문서를 다시 불러올 때는 확인이 끝난 뒤에 새 문서가 나타납니다.
- 안내 오른쪽 위 **×** — 허용하지 않고 안내만 닫습니다. 탭 제목 뒤에 자물쇠 아이콘이 남고, 자물쇠를 누르면 안내가 다시 뜹니다. 자물쇠를 눌러도 탭은 바뀌지 않습니다.
- 에이전트가 연 문서나 세션 복원으로 다시 열린 문서는 사람이 그 탭을 볼 때 안내가 뜹니다. 에이전트도 상태를 조회한 뒤 `tasty surface html-script-allow` 로 그 문서의 스크립트를 허용할 수 있습니다. 조회한 뒤 문서가 바뀌었거나 아직 불러오는 중이면 허용하지 않습니다. 허용해도 보고 있던 탭과 포커스는 그대로입니다.
- 문서를 불러오지 못해 **불러오지 못했습니다** <!-- en: Failed to load --> 가 보이는 동안에는 안내와 탭의 자물쇠·스크립트 아이콘이 사라집니다. 다시 불러온 문서가 열리면 그 문서를 기준으로 다시 정해집니다.

```sh
tasty html open --surface 5 ./dist/index.html
tasty new tab --pane 1 --type html --url http://localhost:3000
tasty surface html-script --surface 5   # 스크립트 감지 결과·허용 여부·안내 상태 조회
tasty surface html-script-allow --surface 5 --url <url> --fingerprint <hex>   # 조회한 문서의 스크립트 허용
tasty surface html-remote-allow --surface 5 --url <url> --fingerprint <hex>   # 조회한 문서의 원격 콘텐츠 허용
```

## Git 보기

사이드바 **도구** > **Git** 을 누르면 현재 터미널 디렉터리의 저장소를 읽기 전용으로 보여주는 창이 뜹니다.

- **변경 사항** <!-- en: Changes --> (status) · **커밋** <!-- en: Commits --> (log) · 파일 클릭 시 **Diff**.
- 왼쪽 **워크트리** <!-- en: Worktrees --> 목록에서 다른 worktree 를 골라 그 기준으로 봅니다. 실제 checkout 은 바뀌지 않습니다.
- **새로고침** <!-- en: Refresh --> 으로 외부 변경을 반영합니다. 커밋 · 스테이징 같은 쓰기는 없습니다.
- **Git 뷰어 열기** <!-- en: Open Git Viewer --> 단축키는 **설정** > **단축키** > **플러그인** <!-- en: Plugins --> 에서 지정합니다(기본값 없음).

현재 디렉터리가 Git 저장소라면 이 창과 별개로 상태바에서 브랜치 이름을 볼 수 있습니다([첫 화면 둘러보기](../getting-started/first-look.md#상태바)).

## 빈 서피스

파일을 닫았거나 아직 종류를 정하지 않은 자리는 **빈 화면** <!-- en: Empty --> 으로 남고 가운데에 종류 선택 버튼이 있습니다. 누르면 [종류 바꾸기](panes-tabs-splits.md#종류-바꾸기) 팝업과 같습니다.

탐색기는 Tasty 에 내장되어 있고, 마크다운 · 이미지 · HTML · Git 보기는 번들 플러그인입니다. 플러그인을 끄면 해당 종류로 열 수 없습니다 — [플러그인](../plugins/index.md).
