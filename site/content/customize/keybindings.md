# 단축키

익숙한 단축키로 Tasty를 사용해 보세요. 프리셋을 고르거나 자주 쓰는 동작에 원하는 키를 지정할 수 있습니다. 단축키 설정은 **설정** <!-- en: Settings --> > **단축키** <!-- en: Keybindings --> 에서 찾을 수 있습니다.

## 표기 규칙

Tasty 는 단축키를 **키의 물리적 위치** 기준으로 저장합니다. 그래서 같은 설정이 세 OS 에서 다르게 눌립니다.

| 설정에 적히는 이름 | Windows · Linux | macOS |
|-------------------|-----------------|-------|
| `ctrl` | Ctrl | Control (⌃) |
| `alt` | Alt | **Command (⌘)** |
| `shift` | Shift | Shift (⇧) |
| `option` | Win (Windows) · Super (Linux) | Option (⌥) |

macOS 의 ⌘ 는 Windows · Linux 의 Alt 와 같은 자리에 있어서, 설정값 `alt+t` 는 Windows 에서 `Alt+T`, macOS 에서 `Cmd+T` 로 눌립니다. 마찬가지로 Windows 의 Win 키와 Linux 의 Super 키는 macOS 의 Option 과 같은 자리라서, `Win+K` · `Super+K` · `⌥+K` 를 녹화하면 모두 `option+k` 로 저장되고 세 OS 어디서나 그 자리의 키로 동작합니다. Windows · Linux 의 설정 화면은 이 키를 `Win` · `Super` 로 표시합니다. 아래 표는 이 규칙으로 두 열을 적었습니다.

`Win+L` · `Win+D` 처럼 Windows 가 예약한 조합과, GNOME · KDE 가 쓰는 Super 조합(Super 단독, Super+문자 다수)은 운영체제가 먼저 가져가서 Tasty 에 오지 않습니다. 이런 조합은 녹화되지 않고, 설정 파일에 적어도 동작하지 않습니다.

설정 파일에는 `ctrl` · `alt` · `option` · `shift` 네 이름만 씁니다. `cmd` · `super` · `win` · `meta` 같은 키 이름은 인식하지 않습니다.

**비라틴 키보드에서도 위치로 맞춥니다.** 러시아어 · 그리스어처럼 라틴 문자가 아닌 배열을 써도 단축키는 키캡의 라틴 위치로 인식됩니다 — 러시아어 배열에서 `H` 자리(러시아어로는 `Р` 가 나오는 키)를 수식키와 함께 누르면 `Ctrl+Shift+H` 단축키가 그대로 동작합니다. 배열을 바꿔도 단축키를 다시 잡을 필요가 없습니다. 마크다운 · 웹 미리보기 화면 위에서도 같습니다.

macOS 에서 설정 화면의 표기를 `⌘` `⌥` `⇧` 심볼로 바꾸려면 **설정** > **일반** <!-- en: General --> > **표시** <!-- en: Display --> 의 **Cmd 키 표시** <!-- en: Cmd key display --> · **Option 키 표시** <!-- en: Option key display --> · **Shift 키 표시** <!-- en: Shift key display --> 를 바꿉니다. 저장되는 값은 그대로입니다.

## 기본 단축키 (Tasty 프리셋)

처음 설치하면 **Tasty** 프리셋이 적용돼 있습니다. 한 동작에 여러 조합이 있으면 전부 동작합니다.

**새로고침** 은 지금 보고 있는 서피스에 새로고침을 요청합니다. 마크다운은 파일(원격이면 원격의 원문)을 다시 읽고, 탐색기는 폴더를 다시 읽으며, 터미널에서는 아무 일도 하지 않습니다. 탐색기의 새로고침 키와 같은 키여도 한 번만 다시 읽습니다. 마크다운 · HTML 화면 위에서는 수식키 없는 키 가운데 `F5` 같은 기능키만 이 동작으로 쓰이고, `R` 같은 글자 키를 지정하면 그 화면 안에서는 글자 입력으로 남습니다. 새로고침 키를 복사 · 붙여넣기 같은 편집 키에도 함께 지정했다면, 웹 페이지와 그 안의 입력란, HTML 주소 칸에서는 편집만 하고 새로고침하지 않습니다. HTML 주소 칸에 입력하는 동안에는 주소 칸으로 옮기는 키와 겹쳐도 그 키가 먼저입니다. 새로고침에 `F5` 가 지정돼 있는 동안 터미널 안 프로그램(mc · htop 등)에는 `F5` 가 전달되지 않습니다. 터미널 프로그램에서 `F5` 를 쓰려면 **설정** > **단축키** > **서피스** <!-- en: Surface --> 에서 새로고침 키를 비우거나 다른 키로 바꾸세요.

`Ctrl+C` 는 선택한 텍스트가 있으면 복사하고, 없으면 평소처럼 실행 중인 프로그램을 중단합니다.

마크다운 · HTML 화면의 본문과 그 안의 입력란, HTML 주소 표시줄에서도 복사 · 잘라내기 · 붙여넣기 · 전체 선택 키가 지금 포커스가 있는 곳에만 동작합니다. 입력란에서 전체 선택은 그 입력란의 글자만, 본문에서는 문서 전체를 고릅니다. 읽기 전용 칸과 본문은 잘라내기 · 붙여넣기로 바뀌지 않습니다. Windows · Linux 에서 `Ctrl+C` · `Ctrl+V` 처럼 웹 화면과 입력란이 원래 아는 편집 키는 여기서 지워도 계속 동작하며, 여기서 더한 키(예: `Alt+C`)는 같은 편집을 한 번 실행합니다. 선택한 것이 없을 때 복사 · 잘라내기를 눌러도 클립보드는 그대로입니다. 웹 페이지의 실행 취소 · 다시 실행은 탐색기와 따로 바꿀 수 있으며, Mac 에서 이 키를 지우면 웹 페이지의 `Cmd+Z` 도 동작하지 않습니다. 같은 키를 플러그인 명령에도 지정했다면 웹 페이지에서는 편집이 먼저입니다. 단어 이동은 웹 화면과 입력란의 기본 키를 씁니다. Linux 에서 페이지가 응답하지 않는 동안 편집 요청이 너무 많이 쌓이면 그 화면에서 편집 키가 더는 동작하지 않을 수 있습니다. 이때도 글자 입력은 그대로 되며, 그 화면을 닫았다가 다시 열면 편집 키가 돌아옵니다.

Windows 에서 마크다운 · HTML 화면이 키보드 포커스를 가진 동안에는 `Ctrl` 이나 `Alt` 없이 누르는 글자 · 숫자 · 기호 키(`Shift` 와 함께 눌러도 마찬가지)에 지정한 단축키를 받지 못하고, 그 키는 화면에 그대로 입력됩니다. 웹 화면에서도 쓸 단축키는 `Ctrl` · `Alt` 와 함께 누르는 조합이나 `F5` 처럼 글자가 아닌 키로 지정하세요.

**링크 복사** 는 기본 키가 없습니다. 키를 지정하면 터미널 링크 위에 마우스를 올린 채 그 키를 눌러 링크 텍스트를 바로 복사합니다. 명령 팔레트에는 나오지 않습니다.

### 기본값이 비어 있는 동작

다음은 실수 방지를 위해, 또는 OS 단축키와 겹쳐서 기본 조합이 없습니다. 필요하면 직접 지정합니다.

- **종료** <!-- en: Quit --> · **즉시 종료** <!-- en: Immediate quit --> · **백그라운드로 최소화** <!-- en: Minimize to background --> (Mac 프리셋은 `Cmd+Q` · `Cmd+M`, Linux 프리셋은 `Ctrl+Q` 가 들어 있습니다)
- **다음 탭** · **이전 탭** 의 자유 조합 (`Ctrl+Tab` 이 OS 와 겹쳐 비워 둠 — 번호 전환의 `Ctrl+L` · `Ctrl+H` 는 동작합니다)
- **마크다운 열기** · **탐색기 열기** · **마크다운으로 전환** · **탐색기로 전환**
- 탐색기의 **미리보기 패널** <!-- en: Preview panel --> 켜기·끄기 · **속성** <!-- en: Properties -->
- **워크스페이스 · 탭 · 페인 프리셋 적용**, **카테고리 전체 접기/펴기**
- **윈도우 최소화** · **윈도우 최대화/확대** · **윈도우 닫기** — macOS 메뉴 막대의 **윈도우** <!-- en: Window --> 메뉴 항목은 각 동작의 첫 번째 조합을 표시하고 그 조합으로 실행됩니다. 동작을 비워 두면 메뉴 항목에도 단축키가 없습니다.
- 사이드바 **도구** 메뉴의 항목들 — **포트 스캐너 열기** <!-- en: Open port scanner --> · **원격 도구 열기** <!-- en: Open remote tools --> · **프리셋 윈도우 열기** <!-- en: Open preset window --> · **튜토리얼 열기** <!-- en: Open tutorial --> · **파일 피커 열기** <!-- en: Open file picker -->

## 프리셋

**설정** > **단축키** > **프리셋** <!-- en: Preset --> 에 네 가지가 있습니다. 프리셋은 권장 세트일 뿐 OS 에 강제되지 않습니다 — Windows 에서 Mac 프리셋을 써도 됩니다.

| 프리셋 | 기준 | Tasty 프리셋과 다른 점 |
|--------|------|------------------------|
| **Tasty** (기본) | 자체 | 위 표. 복사 · 붙여넣기 · 줌은 세 OS 관례를 모두 묶어 둡니다 |
| **Mac** | iTerm2 · Terminal.app | `Cmd` 중심. 설정 `Cmd+,` · 알림 `Cmd+Shift+I` · DAG 목록 `Cmd+Shift+G` · 사이드바 `Cmd+Shift+B` / `Cmd+B` · 종료 `Cmd+Q` · 백그라운드 `Cmd+M` · 페인 닫기 `Cmd+Shift+W`. 여러 조합을 묶어 둔 동작은 `Cmd` 쪽 하나만 남습니다 — 복사 `Cmd+C` · 붙여넣기 `Cmd+V` · 잘라내기 `Cmd+X` · 전체 선택 `Cmd+A` · 검색 `Cmd+F` · 줌 `Cmd+=` · `Cmd+-` · `Cmd+0` · 명령 팔레트 `Cmd+Shift+P` · 코드 입력칸 적용 `Cmd+Enter`, 탐색기의 휴지통 `Cmd+Backspace` · 실행 취소 `Cmd+Z` · 다시 실행 `Cmd+Shift+Z` · 숨김 파일 `Cmd+Shift+.`. **활성 항목 닫기** 와 **워크스페이스 닫기** 는 비어 있습니다 |

적용 절차:

1. **설정** > **단축키** > **프리셋** 목록에서 프리셋 행을 클릭합니다. 지금 쓰는 프리셋에는 **사용 중** <!-- en: Active --> 표시가 붙어 있습니다.
2. 상세 화면의 **기능** <!-- en: Action --> / **현재** <!-- en: Current --> / 프리셋 열 3단 표에서 바뀌는 행을 확인합니다.
3. 오른쪽 위 **적용** <!-- en: Apply --> 을 누릅니다. 아직 파일에는 저장되지 않습니다.
4. 윈도우 아래 **저장** <!-- en: Save --> 을 누릅니다.

프리셋을 적용하면 직접 고쳐 둔 단축키는 모두 프리셋 값으로 돌아갑니다.

## 다른 컴퓨터로 옮기기 — 가져오기 / 내보내기

**설정** > **단축키** 왼쪽 목록 맨 아래(구분선 아래)의 **가져오기 / 내보내기** <!-- en: Import / Export --> 에서 단축키 구성 전체를 파일 한 장으로 옮깁니다. 일반 단축키 · 번호 전환 규칙 · 스크립트 단축키 · 플러그인 단축키가 모두 들어갑니다.

내보내기:

1. **내보내기…** <!-- en: Export… --> 를 누릅니다.
2. 저장할 폴더를 고르고 아래 **파일 이름** <!-- en: File name --> 칸에 이름을 정한 뒤 **저장** 을 누릅니다. 기본 이름은 `tasty-keybindings-<날짜>.toml` 입니다. 목록에서 기존 파일을 누르면 그 이름이 칸에 들어가고, 이미 있는 이름이면 경고가 뜨며 버튼이 **덮어쓰기** <!-- en: Overwrite --> 로 바뀝니다.
3. 저장되면 알림에 파일 경로가 뜹니다. 아직 저장하지 않은 편집도 함께 들어갑니다.

내보내는 동안 **내보내기…** 버튼은 이름과 폭을 유지한 채 비활성화되고, 버튼 옆에 진행 표시와 **내보내는 중…** 문구가 나타납니다. 같은 내보내기를 다시 누를 수 없지만 다른 설정은 계속 편집할 수 있습니다. 설정 윈도우를 닫거나 내보낼 단축키 구성을 바꾸면 예전 작업의 성공·실패 안내는 표시하지 않습니다. 이미 접수된 파일 쓰기는 계속됩니다.

저장하지 못하면(예: 읽기 전용 폴더) **내보내기** 행 안에 **내보내기 파일을 쓰지 못했습니다** <!-- en: The export wasn't written --> 가 뜹니다. **다시 시도** <!-- en: Try again --> 로 같은 자리에 다시 쓰거나 **다른 위치 고르기…** <!-- en: Choose another location… --> 로 다른 곳을 고릅니다. 이 안내가 떠 있는 동안 **내보내기…** 버튼은 눌리지 않습니다. 안내문 가운데 문장은 폴더가 읽기 전용일 때 · 쓸 권한이 없을 때 · 디스크가 가득 찼을 때를 각각 다르게 말해 줍니다. 그 셋 중 어느 것도 아니면 "쓰기가 끝나지 않았습니다" 로 적고, 운영체제가 낸 원문을 그 아래 작은 회색 줄로 덧붙입니다(길면 잘리고, 마우스를 올리면 전문이 보입니다).

결과를 확인할 수 없으면 **내보내기 결과 불명** 안내가 표시됩니다. 대상 파일을 확인한 뒤 직접 다시 시도하세요. 자동으로 다시 쓰지 않습니다. **다시 시도**는 현재 편집 중인 구성을 내보냅니다. 파일은 같은 폴더의 임시 파일을 통해 교체하며 지원되는 기존 접근 권한을 보존하지만, 모든 파일 속성이나 전원 장애 내구성을 보장하지는 않습니다.

가져오기:

1. **가져오기…** <!-- en: Import… --> 를 누르고 옮겨 온 파일을 엽니다. 바로 적용되지 않고 비교 화면이 뜹니다.
2. **일반 단축키** <!-- en: General bindings --> · **빠른 전환(그룹별)** <!-- en: Quick switch (by group) --> · **스크립트 단축키** <!-- en: Script bindings --> · **플러그인별 단축키 설정** <!-- en: Plugin overrides --> 네 묶음으로 현재 값과 가져올 값이 나란히 보입니다. 처음에는 바뀌는 행만 보이고, 오른쪽 위 **전체 N개 보기** <!-- en: Show all N --> 로 전부 볼 수 있습니다.
3. 가져오지 않을 행은 왼쪽 체크를 풉니다. 묶음 제목의 체크는 그 묶음 전체를 켜고 끕니다.
4. 오른쪽 위 **적용** <!-- en: Apply --> 을 누릅니다. 아직 파일에는 저장되지 않습니다.
5. 윈도우 아래 **저장** 을 누릅니다. **취소** 하면 가져온 내용도 전부 버려집니다.

알아 둘 점:

- 빠른 전환은 탭 · 워크스페이스 · 카테고리별로 가져옵니다. 각 묶음의 수식키와 번호별 키는 함께 적용됩니다.
- 이 컴퓨터에만 있는 플러그인 단축키는 파일에 없어도 지워지지 않습니다. 반대로 이 컴퓨터에 설치되지 않은 플러그인의 단축키는 가져오지 않고, 그 사실이 비교 화면에 한 줄로 표시됩니다.
- 파일을 읽으면서 건너뛴 부분이 있으면(더 새 버전의 tasty 가 쓴 파일, 이 버전이 모르는 동작 등) 비교 화면 위에 **경고와 함께 읽었습니다** <!-- en: Read with warnings --> 상자에 한 줄씩 모여 표시됩니다. 네 줄 이상이면 세 줄만 보이고 나머지는 **N개 더 보기** <!-- en: Show N more --> 로 펼칩니다.
- 가져온 단축키 중 Windows 의 `Win+L` · `Win+D` · `Win+E` · `Win+R` · `Win+I` · `Win+Tab` 처럼 OS 가 먼저 쓸 수 있는 조합이 있으면 같은 상자에 "Windows가 Win+L를 먼저 쓸 수 있어 Tasty에 전달되지 않을 수 있습니다." 같은 줄이 붙습니다. 경고일 뿐 가져오기는 그대로 됩니다. Linux 는 `Super` 하나만 누르는 단축키가 해당합니다.
- 단축키 파일이 아닌 것을 고르면 비교 화면 대신 **이 파일은 단축키로 읽을 수 없습니다** <!-- en: This file can't be read as keybindings --> 가 뜨고 아무것도 바뀌지 않습니다. **다른 파일 고르기** <!-- en: Choose another file --> 로 다시 고릅니다.

### 다른 OS 에서 만든 파일을 가져올 때

단축키 파일은 OS 와 관계없이 그대로 가져올 수 있습니다. Mac 에서 `Option` 으로 만든 단축키는 Windows 에서 `Win`, Linux 에서 `Super` 를 누르면 동작하고, 반대도 같습니다. **탐색기 드래그 전환 키** <!-- en: Explorer drag flip modifier --> (**설정** > **단축키** > **일반** 맨 아래)의 기본값은 Mac 이 `Option`, Windows · Linux 가 `Ctrl` 이라, Mac 에서 내보낸 파일을 가져오면 Windows · Linux 에서는 `Win` · `Super` 를 누른 채 끌어야 이동과 복사가 바뀝니다.

## 단축키 하나 바꾸기

1. **설정**(`Ctrl+,`) > **단축키** 를 엽니다. 왼쪽 서브탭은 동작의 대상별로 나뉩니다 — **일반** · **워크스페이스** · **페인** <!-- en: Pane --> · **탭** · **서피스** · **클립보드** · **줌** · **탐색기** · **스크립트 실행** <!-- en: Run Scripts --> · **프리셋** · **플러그인** · **가져오기 / 내보내기**.
2. 바꿀 동작의 키 버튼을 클릭하면 **키 조합을 누르세요...** <!-- en: Press key combination... --> 로 바뀝니다. 원하는 조합을 누릅니다.
3. 같은 동작에 조합을 하나 더 두려면 **단축키 추가** <!-- en: Add binding --> 를 누릅니다.
4. 녹화 중 `Esc` 를 누르면 그 슬롯이 비워집니다.
5. 이미 다른 동작이 쓰는 조합이면 **단축키 중복** <!-- en: Shortcut already in use --> 팝업이 뜹니다. **덮어쓰기** <!-- en: Overwrite --> 를 고르면 기존 동작의 조합이 지워지고 이 동작으로 옮겨집니다.
6. **저장** 을 누릅니다. **취소** <!-- en: Cancel --> 하면 전부 버려집니다.

녹화 규칙:

- 글자 · 숫자 · 스페이스 같은 타이핑 키는 수식키(Ctrl/Alt/Shift) 하나 이상과 함께 눌러야 등록됩니다. `W` 단독은 무시됩니다.
- `F1`~`F24` · `Tab` · `Enter` 같은 키는 수식키 없이도 등록됩니다.
- 수식키를 빠르게 두 번 누르는 더블탭(`Shift` 두 번 등)은 워크스페이스·탭·서피스 열기·닫기·분할·이동, 설정 · 알림 열기, 종료 같은 동작에만 녹화됩니다. 더블탭으로 실행되지 않는 칸(명령 팔레트, 스크립트, 플러그인 명령, 번호 전환 등)에서는 값이 바뀌지 않고 안내 문구가 뜹니다. 설정 파일에 이미 적힌 실행되지 않는 더블탭은 지우지 않고 화면 아래에 경고로 보여 줍니다. macOS 의 `alt+alt` 는 ⌘ 두 번이며, ⌥ 두 번은 더블탭으로 쓰지 않습니다.
- `Esc` 는 "슬롯 비우기" 로 예약돼 있어 단축키로 녹화할 수 없습니다. `Esc` 가 기본값인 **전체화면 무대 종료** · **코드 입력칸 취소** 를 되돌리려면 프리셋을 다시 적용합니다.
- 플러그인 단축키(**플러그인** 서브탭)가 본체 단축키와 겹치면 **플러그인 쪽이 먼저** 동작합니다.

## 플러그인 단축키 바꾸기

**플러그인** 서브탭에서 위의 **플러그인:** <!-- en: Plugin: --> 드롭다운으로 플러그인을 고르면 그 플러그인의 명령이 한 줄씩 나옵니다.

- 방식 드롭다운에서 **기본 상속** <!-- en: Inherit --> 을 고르면 Tasty 의 동작(예: `clipboard.paste`) 하나의 키를 따릅니다. 줄 아래에 지금 따르는 키가 보입니다.
- **독립 설정** <!-- en: Custom --> 은 다른 서브탭과 같은 방식으로 키를 녹화합니다. 키 버튼을 클릭하고 조합을 누르며, `+` 로 키를 더 둘 수 있습니다. 녹화 중 `Esc` 는 그 키를 지우고, 키를 모두 지우면 그 명령은 단축키가 없습니다. 녹화 중에 플러그인이나 방식을 바꾸거나 **초기화** 를 누르면 녹화가 취소됩니다. 키가 많거나 윈도우가 좁으면 키 버튼과 **초기화** 가 다음 줄로 이어지며, 키는 모두 보입니다.
- 설정 파일을 직접 고쳐 어떤 입력과도 맞을 수 없는 키(예: `ctrl+shft+h`)가 들어 있으면 그 키 버튼은 적힌 그대로 오류 테두리로 보이고, 줄 아래에 **인식할 수 없는 키:** <!-- en: Unrecognized key: --> 가 붙습니다. 그 키로는 실행되지 않습니다.
- `cmd+k`·`super+k`·`win+k`·`meta+k` 처럼 OS 키 이름을 적은 경우에는 대신 "Win·Super·Option 은 `option`, Cmd 는 `alt` 로 적으세요." 안내가 붙습니다. 설정 파일은 어느 OS 에서나 같은 뜻이 되도록 키 위치 이름만 받습니다.
- 설정 파일의 키가 Windows 의 `Win+L` 처럼 OS 가 먼저 쓸 수 있는 조합이면 줄 아래에 "Windows가 Win+L를 먼저 쓸 수 있어 Tasty에 전달되지 않을 수 있습니다." 경고가 붙습니다. 저장은 그대로 됩니다.
- **없음** <!-- en: None --> 은 단축키를 두지 않습니다.
- 저장하지 않은 변경이 있는 명령은 이름 뒤에 점이 보입니다. **초기화** <!-- en: Reset --> 는 개별 설정을 지우고 플러그인 기본값으로 돌아가며, 개별 설정이 없으면 누를 수 없습니다.
- 변경은 아래 **저장** 으로 닫을 때만 적용되고, 취소하거나 윈도우를 닫으면 버려집니다.

## 번호 전환 규칙 바꾸기

탭 · 워크스페이스 · 카테고리의 "n 번으로" · "다음/이전" 은 **수식키 하나 + 키 하나** 규칙으로 묶여 있습니다. **탭** 서브탭 아래쪽과 **워크스페이스** 서브탭 아래쪽에서 바꿉니다.

- **탭 전환 수식키** <!-- en: Tab switch modifier --> · **워크스페이스 전환 수식키** · **카테고리 전환 수식키** 드롭다운 — 기본 `Ctrl` · `Alt` · `Ctrl+Shift`. 바꾸면 해당 묶음의 번호별 키(탭 10 · 워크스페이스 9 · 카테고리 10)이 한꺼번에 바뀝니다.
- **1번 탭:** ~ **10번 탭:** 등 슬롯 버튼 — 수식키 없이 키 하나만 누릅니다(**키 하나만 누르세요 (수식키 없이)...** <!-- en: Press a key (no modifier)... -->). 예를 들어 1번 슬롯을 `Q` 로 바꾸면 `Ctrl+Q` 가 1번 탭이 되고, 수식키를 누르고 있을 때 탭에 뜨는 번호 표시도 `Q` 로 바뀝니다.
- **다음 탭:** · **이전 탭:** 등 — 마찬가지로 키 하나. 기본은 vi 식 `L`/`H`(탭), `J`/`K`(워크스페이스 · 카테고리).
- 드롭다운에서 **개별 지정** <!-- en: Custom --> 을 고르면 공통 수식키 대신 슬롯마다 다른 조합(`Ctrl+Alt+1` 같은)을 녹화합니다. 이때는 번호 표시가 뜨지 않습니다. 다시 규칙 방식으로 돌아가면 해당 묶음은 기본값으로 초기화됩니다.

<a id="팝업에-포커스가-가-있으면-단축키가-안-먹습니다"></a>

## 팝업에 입력하는 동안의 단축키

검색 바 · 파일 선택 · 명령 팔레트처럼 입력을 받는 팝업에 **포커스가 가 있는 동안에는 단축키가
동작하지 않습니다.** 검색어를 입력하는 중에 `Alt+W` 같은 키로 서피스가 닫히는 일을 막기 위한 동작입니다. 팝업이 떠 있기만 하고 포커스가 없으면 단축키는 평소대로 동작합니다.

터미널 조작으로 돌아가려면 다음 중 하나를 사용하세요.

- **`Esc`** — 포커스된 팝업을 놓습니다. 바깥을 클릭했을 때 닫히는 종류면 함께 닫히고,
  그렇지 않은 팝업은 열린 채로 포커스만 풀립니다. 열려 있어도 포커스가 없는 다른 팝업은
  그대로 남습니다.
- **팝업 바깥을 클릭** — `Esc` 와 같은 결과입니다.

설정 윈도우나 알림 패널이 떠 있을 때는 `Esc` 가 그쪽을 먼저 닫습니다.

## 단축키를 외우지 않아도 되는 두 가지

- **수식키 힌트** — `Ctrl` · `Alt` · `Shift` 등을 0.5초 이상 누르고 있으면(Shift 단독은 1.2초) 사이드바 아래에 그 조합으로 시작하는 단축키 목록이 뜹니다. 손을 떼면 사라집니다. Windows · Linux 에서 `Win` · `Super` 는 이 키를 쓰는 단축키가 하나라도 있을 때만 목록을 띄웁니다. **설정** > **일반** > **접근성** <!-- en: Accessibility --> > **수식키 힌트 표시** <!-- en: Show modifier key hints --> 로 끌 수 있고, 패널은 드래그로 옮기거나 크기를 바꿀 수 있습니다.
- **명령 팔레트** — `Ctrl+Shift+P` 또는 상태바 오른쪽의 팔레트 단축키 키캡. 동작 이름을 타이핑해 `Enter` 로 실행합니다. 단축키 탭의 동작과 활성 플러그인의 전역 명령이 검색됩니다. 다만 명령 팔레트 자신, **전체화면 무대 종료**, 마우스 아래 링크가 대상인 **링크 복사**, 코드 입력칸 키, 탐색기 항목 옮기기 · 선택 넓히기 · 열기 · 선택 해제 키는 나오지 않습니다(탐색기의 이름 변경 · 휴지통으로 이동은 나옵니다). 스크립트 단축키도 팔레트에는 나오지 않습니다. 검색어 칸은 포커스가 없어도 배경과 테두리로 구분되며, 입력 중에는 포커스 테두리가 표시됩니다.

## 설정 파일에서 직접 고치기

`~/.tasty/config.toml` 의 `[keybindings]` 절에 저장됩니다. 값은 OS 와 무관한 이름이라 파일을 다른 OS 로 옮겨도 그대로 쓸 수 있습니다.

```toml
[keybindings]
new_tab = ["alt+t"]
copy = ["ctrl+c", "alt+c", "ctrl+shift+c"]
quit = []                      # 비우면 단축키 없음
tab_switch_modifier = "ctrl"   # "ctrl+shift" 처럼 조합도 됨
tab_switch_slot_keys = ["1", "2", "3", "4", "5", "6", "7", "8", "9", "0"]
tab_switch_next_key = "l"
tab_switch_prev_key = "h"
```

`+` 키 자체는 `ctrl++` 또는 `ctrl+plus`, `-` 는 `ctrl+-` 또는 `ctrl+minus`, `=` 는 `ctrl+=` 또는 `ctrl+equals` 로 적습니다. 파일 편집 전반은 [설정](settings.md).
